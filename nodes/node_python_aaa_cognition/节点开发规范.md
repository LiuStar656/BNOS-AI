# BNOS 节点开发规范

> 本文档定义 BNOS 节点的开发标准，包括目录结构、配置文件、监听器、启动脚本等。
> 如需开发**新语言的节点生成器**，请参阅 [节点生成器开发准则](节点生成器开发准则.md)。
> 如需了解 `node_config.json` 输入端口与参数控件的详细配置，请参阅 [config_json 开发规范](config_json_开发规范.md)。

## 一、节点目录结构

每个节点在 `项目/nodes/` 下必须有如下结构：

```
nodes/
└── node_{lang}_{name}/
    ├── node_config.json      # 节点配置（必需，见下节）
    ├── start.bat            # Windows 启动脚本（必需）
    ├── start.sh             # Linux/macOS 启动脚本（必需）
    ├── listener.{ext}       # 监听器入口（可选，持续运行）
    ├── main.{ext}           # 处理逻辑入口（可选，核心业务代码）
    ├── output.json          # 节点输出文件（运行时生成）
    ├── requirements.txt     # 依赖声明（Python 等语言必需）
    ├── .pid                 # 进程 PID 文件（启动后自动生成）
    ├── .gitignore           # 忽略编译产物/日志
    └── logs/                # 运行日志目录（自动创建）
        └── listener.log
```

### Python 节点示例

```
nodes/
└── node_python_demo/
    ├── node_config.json
    ├── start.bat
    ├── start.sh
    ├── listener.py
    ├── main.py
    ├── packet.py            # 数据包结构定义（可选）
    ├── output.json
    ├── requirements.txt
    ├── venv/                # 独立虚拟环境（首次启动自动创建）
    ├── .gitignore
    └── logs/
        └── listener.log
```

### Rust 节点示例

```
nodes/
└── node_rust_demo/
    ├── node_config.json
    ├── start.bat
    ├── start.sh
    ├── Cargo.toml           # Rust 项目配置
    ├── output.json
    ├── src/
    │   ├── main.rs          # 主处理逻辑
    │   ├── listener.rs      # 监听器
    │   └── packet.rs        # 数据包结构（可选）
    ├── .gitignore
    └── logs/
        └── listener.log
```

## 二、node_config.json 基础规范

每个节点必须包含 `node_config.json`，字段如下：

```json
{
  "node_name": "node_python_1",
  "listen_upper_file": "../data/upper_data.json",
  "output_file": "./output.json",
  "output_type": "",
  "filter": {},
  "out_connections": {},
  "port_mappings": {},
  "parameters": [],
  "input_ports": [],
  "output_ports": []
}
```

### 核心字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `node_name` | string | **必须与节点目录名一致** |
| `listen_upper_file` | string | 监听的上游数据文件路径 |
| `output_file` | string | 本节点输出文件路径 |
| `filter` | object | 注意力过滤规则（空 `{}` 则处理所有任务） |
| `output_type` | string | 输出数据类型标识 |

### 注意力过滤机制

- `filter` 为空 `{}`：节点处理**所有**上游任务（广泛注意力）
- `filter` 有键值对：节点只处理**匹配所有条件**的任务（聚焦注意力）

```json
{
  "filter": { "type": "data_task", "priority": "high" }
}
```

> **详细配置**（`parameters` / `input_ports` / `output_ports` 11 种控件类型）见：[config_json 开发规范](config_json_开发规范.md)

## 三、监听器（listener）开发规范

监听器是节点的核心入口，**必须持续运行**，不能主动退出。

### 最低功能要求

1. 读取本节点 `node_config.json` 获取 `listen_upper_file` 路径
2. 监听上游节点的 `output.json`（或 `upper_data.json`）文件变化
3. 根据 `filter` 规则判断是否处理该任务（注意力过滤）
4. 检查 `_processed_<node_name>` 标记，避免重复处理
5. 调用 `main` 处理逻辑，传入任务数据
6. 将处理结果写入本节点 `output.json`
7. 在上游文件中添加 `_processed_<node_name>` 处理标记
8. 日志写入 `logs/listener.log`

### 自愈机制

- 输出文件路径不存在时自动创建目录
- 上游文件不存在时等待并重试
- 异常时不崩溃，记录日志后继续监听
- 检测运行环境是否完整，缺失则自动修复

### Python 监听器伪代码

```python
import json, time, os, subprocess, sys
from datetime import datetime

def log(msg, level="INFO"):
    timestamp = datetime.now().strftime("%Y-%m-%d %H:%M:%S")
    log_dir = os.path.join(os.path.dirname(__file__), "logs")
    os.makedirs(log_dir, exist_ok=True)
    with open(os.path.join(log_dir, "listener.log"), "a", encoding="utf-8") as f:
        f.write(f"[{timestamp}] [{level}] {msg}\n")

def load_config():
    config_path = os.path.join(os.path.dirname(__file__), "node_config.json")
    with open(config_path, "r", encoding="utf-8") as f:
        return json.load(f)

def _load_port_filters(config):
    """从 input_ports 中提取每个 source="node" 端口的 filter 规则。
    
    返回: dict[str, dict]  — {port_name: {key: value, ...}}
    """
    result = {}
    input_ports = config.get("input_ports", [])
    if not isinstance(input_ports, list):
        return result
    for port in input_ports:
        if not isinstance(port, dict):
            continue
        if port.get("source") != "node":
            continue
        pf = port.get("filter", {})
        if isinstance(pf, dict) and pf:
            result[port.get("name", "")] = pf
    return result

def listen():
    config = load_config()
    node_name = config["node_name"]
    upper_file = config["listen_upper_file"]
    output_file = config["output_file"]
    filter_rules = config.get("filter", {})
    processed_key = f"_processed_{node_name}"
    
    log(f"监听器启动，监听: {upper_file}")
    
    while True:
        try:
            if not os.path.exists(upper_file):
                time.sleep(1)
                continue
            
            with open(upper_file, "r", encoding="utf-8") as f:
                data = json.load(f)
            
            # 注意力过滤
            if filter_rules:
                if not all(data.get(k) == v for k, v in filter_rules.items()):
                    time.sleep(1)
                    continue
            
            # 端口级过滤（v2.1+）：每个 source="node" 的输入端口可有独立的 filter
            port_filters = _load_port_filters(config)
            if port_filters:
                try:
                    input_data = json.loads(data.get("data", json.dumps(data)))
                except Exception:
                    input_data = data
                data_passed = True
                for port_name, pf in port_filters.items():
                    port_val = input_data.get(port_name, {})
                    if isinstance(port_val, dict) and not all(port_val.get(k) == v for k, v in pf.items()):
                        data_passed = False
                        break
                if not data_passed:
                    time.sleep(1)
                    continue
            
            # 防重复处理
            if data.get(processed_key):
                time.sleep(1)
                continue
            
            log(f"检测到匹配任务，开始处理")
            
            # 调用 main.py 处理
            result = subprocess.run(
                [sys.executable, "main.py", json.dumps(data)],
                capture_output=True, text=True, timeout=300
            )
            
            if result.returncode == 0:
                output = json.loads(result.stdout)
                os.makedirs(os.path.dirname(output_file), exist_ok=True)
                with open(output_file, "w", encoding="utf-8") as f:
                    json.dump(output, f, ensure_ascii=False, indent=2)
                
                # 标记已处理
                data[processed_key] = True
                with open(upper_file, "w", encoding="utf-8") as f:
                    json.dump(data, f, ensure_ascii=False, indent=2)
                
                log("处理完成")
            else:
                log(f"处理失败: {result.stderr}", "ERROR")
        
        except Exception as e:
            log(f"异常: {e}", "ERROR")
        
        time.sleep(1)

if __name__ == "__main__":
    listen()
```

## 四、处理逻辑（main）开发规范

`main` 是节点的业务逻辑入口，负责**单次**处理任务并返回结果。

### 接口规范

- **输入**：接收 JSON 字符串（从命令行参数传入）或从 stdin 读取
- **输出**：输出 JSON 字符串到 stdout
- **核心要求**：业务逻辑封装在 `MyNode` 类的 `process()` 方法中，顶层 `process(data)` 函数作为桥接。`process(data)` 必须是纯函数，**不依赖进程环境**（复合节点兼容）

### 复合节点兼容约束 ★

> `main.py` 在复合节点模式下会被 `importlib.import_module()` 加载到编排进程内直接调用，而非通过 `subprocess` 启动子进程。因此必须遵守以下约束：

#### 1. 所有文件路径必须以 `__file__` 为基准（强制）

```python
# ✅ 正确
import os
NODE_DIR = os.path.dirname(os.path.abspath(__file__))
config_path = os.path.join(NODE_DIR, "node_config.json")
model_path = os.path.join(NODE_DIR, "models", "qwen.gguf")

# ❌ 禁止 —— 依赖 os.getcwd()，复合节点模式下 cwd 是项目根目录
config_path = "node_config.json"
model_path = "./models/qwen.gguf"
log_dir = os.path.join(os.getcwd(), "logs")
```

| 语言 | 正确写法 | 禁止写法 |
|------|----------|----------|
| Python | `os.path.dirname(os.path.abspath(__file__))` | `os.getcwd()` / `"./xxx"` / `"xxx.json"` |
| Rust | `env!("CARGO_MANIFEST_DIR")` → 编译期，或 `std::env::current_exe()` → 运行时 | `std::env::current_dir()` |

#### 2. `process()` 函数必须可直接 import 调用

```python
# ✅ 正确：process 是顶层函数，可直接导入
def process(data: dict) -> dict:
    ...

# ❌ 禁止：process 依赖 sys.argv
def process():
    data = json.loads(sys.argv[1])   # 复合节点不传命令行参数
```

#### 3. 模块导入时不得有副作用

```python
# ❌ 禁止：import 时执行阻塞 I/O 或依赖 cwd
with open("node_config.json") as f:    # 依赖 cwd，import 时报错
    CONFIG = json.load(f)

# ✅ 正确：惰性加载
_config = None
def get_config():
    global _config
    if _config is None:
        cfg_path = os.path.join(os.path.dirname(__file__), "node_config.json")
        with open(cfg_path) as f:
            _config = json.load(f)
    return _config
```

#### 4. 不得在模块级别持有可变全局状态

```python
# ❌ 禁止：跨节点共享状态
SESSION_CACHE = {}   # 多个节点的 main 共享同一进程，会互相污染

# ✅ 正确：每次 process() 自包含
def process(data: dict) -> dict:
    cache = {}   # 局部变量，每次调用独立
    ...
```

#### 5. EXE 打包兼容约束 ★

> 节点通过 BNOS 编译为独立 exe 后，listener 会以 `import _bnos_main` 方式加载 `main.py` 模块并直接调用 `process(data)`，而非 `subprocess` 启动子进程。`__name__ == "__main__"` 代码块在 exe 模式下**永远不会执行**。

##### 5.1 `process()` 是唯一的调用入口

listener 只调用 `process(data)`，不传命令行参数、不读 stdin/stdout。因此所有业务逻辑必须在 `process()` 内完成或由 `process()` 调用。

##### 5.2 模块导入必须零副作用（强制）

`import _bnos_main` 时不应触发任何文件 I/O、配置读取或路径解析。这些操作一律放入 `if __name__ == "__main__"` 块内。

```python
# ✅ 正确：模块级只定义函数和常量，无副作用
import json

def process(data: dict) -> dict:
    return data.get("data")

if __name__ == "__main__":
    # 配置读取、路径解析仅在此处执行（直接运行 main.py 时）
    import os
    NODE_DIR = os.path.dirname(os.path.abspath(__file__))
    with open(os.path.join(NODE_DIR, "node_config.json")) as f:
        cfg = json.load(f)
    ...

# ❌ 禁止：模块级读取 node_config.json
NODE_DIR = os.path.dirname(os.path.abspath(__file__))
with open(os.path.join(NODE_DIR, "node_config.json")) as f:
    cfg = json.load(f)   # exe 模式下 Nuitka 解压路径异常，必定报错
```

##### 5.3 不要依赖 NODE_DIR / os.getcwd() / __file__

exe 模式下这些路径均不可靠（指向临时解压目录或不确定的 cwd）。若 `process()` 需要访问节点目录下的文件（如模型、资源），应由 listener 传入路径参数，而非在 `main.py` 中自行解析。

> **总结**：保持 `main.py` 模块级代码干净——只有 import、常量定义和函数定义。业务逻辑封装在 `MyNode` 类中，配置/路径/I/O 全部放在 `if __name__ == "__main__"` 里。这样无论直接运行、复合节点 import、还是 exe 编译，都能正常工作。

### Python 模板（推荐）

节点业务逻辑封装在 `MyNode` 类中，其他代码为框架基础设施，开发者不要修改。

```python
"""
节点名称 - 简短描述
"""
import sys
import json
import os


# ════════════════════════════════════════════════════════════════
#  ★ 开发者在此类中编写所有业务逻辑 — 其他代码不要修改 ★
# ════════════════════════════════════════════════════════════════

class MyNode:
    """
    节点的业务逻辑处理器。

    process() 是框架入口，由桥接函数 process(data) 自动调用。
    开发者只需在此类中填充业务逻辑，不要修改框架代码。
    """

    def __init__(self):
        """初始化业务状态（可选覆盖）"""
        pass

    def process(self, data: dict) -> dict:
        """
        框架入口。

        参数:
            data: 上游传入的 JSON dict

        返回:
            dict 或 list[dict]:
            - dict  : 单端口输出，用 "_port" 指定端口，默认 "default"
            - list  : 并行多端口输出，每项必须是 dict 且自带 "_port"

        端口约定：
          - "_port": "status"  → 走 status 端口（init 检测用）
          - "_port": "default" → 走 default 端口（业务数据，可省略）
        """
        # ═══ 在此实现你的业务逻辑 ═══
        result = data.get("data", {})
        # ══════════════════════════════
        return result


# ════════════════════════════════════════════════════════════════
#  框架桥接（开发者不要修改）
# ════════════════════════════════════════════════════════════════

NODE_DIR = os.path.dirname(os.path.abspath(__file__))
_node = MyNode()


def process(data: dict) -> dict:
    """框架入口，由 listener.py 或 __main__ 调用。"""
    return _node.process(data)


# ════════════════════════════════════════════════════════════════
#  __main__ 入口（仅直接运行 python main.py 时执行）
# ════════════════════════════════════════════════════════════════
if __name__ == "__main__":
    # 读取输入（支持 argv 和 stdin 两种方式）
    input_data = {}
    if len(sys.argv) >= 2:
        try:
            input_data = json.loads(sys.argv[1])
        except Exception:
            pass
    if not input_data:
        try:
            s = sys.stdin.read().strip()
            if s:
                input_data = json.loads(s)
        except Exception:
            pass
    if not input_data:
        print(json.dumps({"code": -1, "error": "no input"}, ensure_ascii=False))
        sys.exit(1)

    # 加载配置
    config_path = os.path.join(NODE_DIR, "node_config.json")
    with open(config_path, "r", encoding="utf-8") as f:
        cfg = json.load(f)

    # 执行业务 + 输出
    result = process(input_data)

    if isinstance(result, list):
        # 并行多端口输出：data 为数组，每项自带 _port
        print(json.dumps({"code": 0, "data": result}, ensure_ascii=False))
    else:
        # 单端口输出：pop _port 作为 type
        port = result.pop("_port", cfg.get("output_type", "default"))
        print(json.dumps({"code": 0, "type": port, "data": result}, ensure_ascii=False))
```


### Rust 示例

```rust
use serde_json::Value;

fn process(data: &Value) -> Option<Value> {
    let input = data.get("data")?;
    
    // ═══ 在此实现你的业务逻辑 ═══
    let result = input.clone();
    // ══════════════════════════
    
    Some(serde_json::json!({
        "code": 0,
        "data": result
    }))
}

fn main() {
    let args: Vec<String> = std::env::args().collect();
    let data: Value = if args.len() > 1 {
        serde_json::from_str(&args[1]).unwrap()
    } else {
        serde_json::from_reader(std::io::stdin()).unwrap()
    };
    
    if let Some(result) = process(&data) {
        println!("{}", serde_json::to_string(&result).unwrap());
    }
}
```

### 输出格式

**单端口输出（dict）：**
```json
{
  "code": 0,
  "type": "端口名（如 default / status）",
  "data": { "key": "value" }
}
```

**并行多端口输出（list）：**
```json
{
  "code": 0,
  "data": [
    { "_port": "default", "data_type": "reply", "content": "..." },
    { "_port": "default", "data_type": "knowledge", "content": "..." }
  ]
}
```

- `code`: `0` 表示成功，非 `0` 表示失败
- `type`: 单端口输出时，从结果 dict 的 `_port` 字段取值，默认 `"default"`
- `data`:
  - 单端口时：处理结果 dict（`_port` 字段已被弹出）
  - 多端口时：数组，每项为一个输出，自带 `_port` 指明目标端口

## 五、启动脚本规范

### start.bat（Windows）

```bat
@echo off
setlocal enabledelayedexpansion
if not "%1"=="--no-pause" (
    cls
    chcp 65001 >nul
    echo ======================================
    echo        BNOS Node Starter
    echo ======================================
    echo.
)
cd /d "%~dp0"

REM === 环境自愈（按需实现） ===
REM 检测运行时依赖，缺失则自动修复

REM === 后台启动 ===
if not "%1"=="--no-pause" (
    echo 后台启动监听程序...
    start /b "" <启动命令>
) else (
    start /b "" <启动命令> >nul 2>&1
)

REM === 写入 PID ===
timeout /t 1 /nobreak >nul
REM 用 tasklist 获取进程 PID
for /f "tokens=2" %%i in ('tasklist /fi "imagename eq <进程名>" /nh 2^>nul') do echo %%i > .pid

if not "%1"=="--no-pause" (
    echo 监听程序已在后台运行
    pause
)
```

### start.sh（Linux/macOS）

```bash
#!/bin/bash
cd "$(dirname "$0")"
NO_PAUSE=false
[ "$1" = "--no-pause" ] && NO_PAUSE=true

# === 环境自愈（按需实现） ===

# === 后台启动 + PID ===
nohup <启动命令> > /dev/null 2>&1 &
echo $! > .pid
[ "$NO_PAUSE" = false ] && echo "监听程序已在后台运行 (PID: $(cat .pid))" && read -p "按回车键退出..."
```

### 启动脚本关键规范

| 规范 | 说明 |
|------|------|
| 支持 `--no-pause` | GUI 调用时必须静默运行，不 `pause`/`read` |
| 环境自愈 | 检测依赖缺失时自动修复（安装 venv、编译等） |
| 后台启动 | Windows 用 `start /b`，Linux/macOS 用 `nohup &` |
| PID 记录 | 启动后写入 `.pid` 文件，内容为进程 PID（一行一个数字） |
| `.pid` 格式 | 文件只写一行一个数字，如 `12345` |

## 六、节点间通信协议

### 任务数据格式

上游节点通过监听文件（`listen_upper_file` 指向的 JSON）传递任务：

```json
{
  "type": "data_task",
  "data": { "key": "value" },
  "_processed_node_python_1": true
}
```

### 输出数据格式

节点处理完成后写入 `output_file`：

```json
{
  "code": 0,
  "type": "data_result",
  "data": { "processed_key": "processed_value" }
}
```

### 防重复处理

每个节点处理完任务后，在上游文件中写入 `_processed_<node_name>` 标记：

```json
"_processed_node_python_1": true
```

监听器在每次处理前检查此标记，若已存在则跳过。

### 多节点链式处理

```
upper_data.json
    ↓ [node_python_1] 过滤 type=data_task → 处理 → output.json
    ↓ [node_python_2] 监听 node_1 的 output → 处理 → output.json
    ↓ [node_python_3] 监听 node_2 的 output → 处理 → output.json
```

## 七、开发检查清单

新建节点时请逐项确认：

- [ ] 目录结构完整（node_config.json / start.bat / start.sh）
- [ ] `node_config.json` 中 `node_name` 与目录名一致
- [ ] `listen_upper_file` 路径正确
- [ ] `filter` 规则配置合理（空 `{}` 或具体规则）
- [ ] 监听器持续运行，不主动退出
- [ ] 监听器有防重复处理标记
- [ ] 监听器异常不崩溃，记录日志后继续
- [ ] `main` 接收 JSON 输入，输出 JSON 到 stdout
- [ ] 输出格式符合 `{"code": 0, "type": "...", "data": ...}` 规范
- [ ] start.bat 支持 `--no-pause` 参数
- [ ] start.bat 后台启动 + 写入 `.pid`
- [ ] start.sh 后台启动 + `echo $! > .pid`
- [ ] `.pid` 文件内容为一行一个数字
- [ ] 日志写入 `logs/listener.log`
- [ ] `.gitignore` 排除 `venv/`、`target/`、`logs/`、`.pid`、`output.json`
- [ ] `node_config.json` 中 `entry` 字段指向有效脚本文件
- [ ] ★ 所有文件路径以 `__file__` 为基准（禁止 `os.getcwd()` / `./xxx` 相对路径）
- [ ] ★ 业务逻辑封装在 `MyNode` 类中，`process(data)` 为顶层桥接函数
- [ ] ★ 模块 `import` 时无阻塞 I/O、无 cwd 依赖副作用
- [ ] ★ 无模块级可变全局状态（每次 `process()` 自包含）
- [ ] ★ EXE 打包兼容：模块级代码无副作用，配置读取只在 `__main__` 块内
- [ ] ★ `process()` 不依赖 `NODE_DIR` / `os.getcwd()` / `__file__` 解析路径
