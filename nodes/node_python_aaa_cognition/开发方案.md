## 一、节点定位

提示词拼接站。**不是认知引擎。不做推理、不做决策**，只负责：

1. 收集上下文（内存数据 + DB 历史 + 多源输入）
2. 拼接成符合模板的 prompt
3. 发给 LLM，回收节标记文本
4. 解析节标记，按 `data_type` 路由到下游节点
5. 并行写 DB（所有持久化数据）

真正的"智能"在 LLM 推理节点，AAA 只是一个高效的数据搬运工 + 格式化工具。

## 二、来源

从 AAA 项目 `main.py` 重构，去除内嵌 LLM 调用和定时任务线程。LLM 推理能力独立为 `node_python_llm_infer` 节点，AAA 退化为纯粹的上下文组装 + 结果分发器。

## 三、职责

- 接收输入 -> 直连路径的数据直接在内存中用，DB 路径的从 DB 一次读取
- 并行写 DB（fire-and-forget，不阻塞推理链路）
- 构建 prompt -> 发送到 LLM 推理节点
- 接收节标记文本 -> 解析 + 路由输出
- 需要 FAISS 检索？-> 内部检索 -> 重建 prompt -> 再次发送 LLM
- 需要工具调用？-> 输出 `tool_call` 到 Grok 节点
- 无需工具？-> 注入情绪标签 -> 输出 `reply`/`knowledge` 到下游
- 接收 Grok 工具结果 -> 并行写 DB + 重建 prompt -> 再次发送 LLM

## 四、端口定义

### 多输入端口

| 端口名 | filter (data_type) | 说明 |
|--------|-------------------|------|
| `user_input` | `text` | 用户文本输入 |
| `llm_response` | `text` | LLM 返回的节标记文本 |
| `tool_result` | `json` | Grok 工具执行结果 |

| `vision_input` | `json` | 视觉描述数据（Phase 2+） |
| `env_input` | `json` | 环境/系统信息（Phase 2+） |
| `init_check` | `json` | GUI 初始化检测信号 |

### 输出端口

| 端口名 | 说明 |
|--------|------|
| `default` | 中枢输出（`data_type` 区分：`prompt`/`tool_call`/`reply`/`knowledge`） |
| `status` | 状态反馈给 GUI |

多端口用 `filter` 路由，**不在 main.py 中用 if-else 枚举数据类型做分发**（遵循 BNOS 节点开发规范）。

| 输出 data_type | 目标节点 | 目标端口 |

## 六、处理逻辑伪代码

遵循 BNOS 节点开发规范：`main.py` 从 stdin 读 JSON、stdout 写 JSON、不依赖任何 BNOS 模块、多端口用 `filter` 路由不用 if-else 分发。

### main.py 伪代码

```python
#!/usr/bin/env python3
"""
节点处理入口。
从 stdin 读取 JSON -> 处理 -> 写入 stdout。
不依赖任何 BNOS 模块。
"""
import sys
import json
import re
import threading
import sqlite3
from datetime import datetime


def main():
    try:
        input_data = json.loads(sys.stdin.read())
    except (json.JSONDecodeError, IOError):
        input_data = {}

    config = load_config()
    data_type = input_data.get("data_type", "")

    # === 业务逻辑：根据端口路由数据 ===
    # 多端口已由 listener 根据 filter 路由，此处按 data_type 处理对应业务
    result = process(input_data, config, data_type)

    # 输出到 stdout（listener 会写入 output.json）
    sys.stdout.write(json.dumps(result, ensure_ascii=False))
    sys.stdout.flush()


def process(input_data: dict, config: dict, data_type: str) -> dict:
    """核心处理逻辑"""
    db_path = config.get("db_path", "../shared/chatbot.db")

    if data_type == "text" and input_data.get("_port") == "user_input":
        # 用户文本输入 -> 收集上下文 -> 构建 prompt -> 发送 LLM
        context = gather_context(input_data, db_path, config)
        prompt = build_prompt(context, config)
        # 并行写 DB（fire-and-forget）
        fire_and_forget_write_db(input_data, db_path, role="user")
        return {"data_type": "prompt", "content": prompt}

    elif data_type == "text" and input_data.get("_port") == "llm_response":
        # LLM 返回的节标记文本 -> 解析 -> 路由输出
        parsed = parse_llm_output(input_data.get("content", ""))
        fire_and_forget_write_parsed(parsed, db_path)
        # 判断是否需要工具调用
        if parsed.get("工具调用") and tool_rounds_under_limit(config):
            return {"data_type": "tool_call", "tools": parsed["工具调用"]}
        else:
            reply = inject_mood_tag(parsed.get("自然回复", ""))
            return {"data_type": "reply", "content": reply,
                    "knowledge": parsed.get("知识条目", "")}

    elif data_type == "json" and input_data.get("_port") == "tool_result":
        # Grok 工具结果 -> 并行写 DB + 重建 prompt -> 再次发送 LLM
        fire_and_forget_write_db(input_data, db_path, role="tool")
        context = gather_context(input_data, db_path, config)
        prompt = build_prompt(context, config)
        return {"data_type": "prompt", "content": prompt}

    elif data_type == "json" and input_data.get("_port") == "init_check":
        # GUI 初始化检测 -> 返回 status
        return {"data_type": "json", "status": "ready",
                "_port": "status"}

    return {"data_type": "json", "status": "noop"}


def gather_context(input_data: dict, db_path: str, config: dict) -> dict:
    """收集上下文：内存数据 + DB 历史 + 多源输入"""
    context = {}
    # 直连路径：当前对话数据直接在内存中用
    context["user_text"] = input_data.get("content", "")
    # DB 路径：从 DB 一次读取全部聚合数据
    context.update(load_from_db(db_path, config))
    # 多源输入（asr/vision/env）已由对应端口写入 DB，此处统一读取
    context["faiss_top5"] = faiss_retrieve(context["user_text"], config)
    return context


def fire_and_forget_write_db(data: dict, db_path: str, role: str):
    """并行写 DB，不阻塞推理链路"""
    t = threading.Thread(target=write_db_sync, args=(data, db_path, role), daemon=True)
    t.start()


def write_db_sync(data: dict, db_path: str, role: str):
    """实际的 DB 写入（在子线程执行）"""
    conn = sqlite3.connect(db_path)
    try:
        # 写入逻辑...
        pass
    finally:
        conn.close()


def load_config() -> dict:
    """加载 node_config.json 中的参数"""
    import os
    config_path = os.path.join(os.path.dirname(__file__), "node_config.json")
    if os.path.exists(config_path):
        with open(config_path, "r", encoding="utf-8") as f:
            return json.load(f)
    return {}


if __name__ == "__main__":
    main()
```

## 八、节标记解析与情绪标签注入

### 节标记解析代码（核心）

```python
import re

def parse_llm_output(text: str) -> dict:
    pattern = re.compile(r'【(.+?)】\s*\n(.*?)(?=\n【|$)', re.DOTALL)
    result = {}
    for match in pattern.finditer(text):
        key = match.group(1).strip()
        value = match.group(2).strip()
        if not value:
            continue
        if key == "工具调用":
            tools = []
            for line in value.split("\n"):
                line = line.strip()
                if not line:
                    continue
                parts = line.split("|", 1)
                if len(parts) != 2:
                    continue
                tool_name = parts[0].strip()
                args = {}
                for kv in parts[1].split(","):
                    kv = kv.strip()
                    if "=" in kv:
                        k, v = kv.split("=", 1)
                        args[k.strip()] = v.strip()
                tools.append({"tool_name": tool_name, "args": args})
            result[key] = tools
        else:
            result[key] = value
    return result
```

### 情绪标签注入

```python
def _mood_to_tag(mood: str) -> str:
    mapping = {
        "开心": "开心", "高兴": "开心", "愉快": "开心", "兴奋": "开心",
        "难过": "难过", "伤心": "难过", "沮丧": "难过", "低落": "难过",
        "生气": "生气", "愤怒": "生气", "烦躁": "生气",
        "惊讶": "惊讶", "震惊": "惊讶", "好奇": "惊讶",
        "害羞": "害羞",
        "俏皮": "俏皮", "调皮": "俏皮",
    }
    for k, v in mapping.items():
        if k in mood:
            return v
    return ""


def inject_mood_tag(reply_text: str, mood: str = "") -> str:
    """在回复文本前注入 <情绪> 标签，供 Live2D 节点解析"""
    tag = _mood_to_tag(mood)
    if tag:
        return f"<{tag}>{reply_text}"
    return reply_text
```

## 九、DB 读写分离原则

### 直连路径 vs DB 中转路径

- **直连路径**（当前对话数据）：用户文本、LLM 回复、工具结果 -> 直接在内存中使用 + 并行写 DB
- **DB 中转路径**（多源聚合数据）：视觉、环境、ASR -> 先写 DB -> AAA 一次查询取出全部
- **通用规则**：产生数据就写 DB，无一例外

### DB 写入映射

| 数据 | 目标表 | 备注 |
|------|--------|------|
| 自然回复 | `user_messages` | `role=assistant` |
| 心情+想法 | `feelings` 表 | |
| 事件摘要 | `event_summary` 表 + FAISS 向量库 | |
| 自我认知 | `self_cognition` 表 | |
| 他人认知 | `other_cognition` 表 | |
| 用户信息 | `user_facts` | `category=background` |
| 自我信息 | `self_info` 表 | |
| 知识条目 | `user_facts` | `category=preference` |
| 工具结果 | `long_term_memory` | `source=grok, role=tool` |
| 用户输入 | `long_term_memory` | `source=text, role=user` |

## 十三、会话上下文感知

### 13.1 需求

AI 需要感知以下上下文信息，以做出更自然的回应：

1. **GUI 打开/关闭事件**：用户打开应用时 AI 知道"用户来了"，关闭时知道"用户走了"
2. **会话间隔时间**：用户每次发送消息时，AI 知道"距离上一次输入过去了多久"
3. **会话生命周期**：从打开到关闭为一个完整会话，AI 能感知当前处于哪个阶段

### 13.2 设计思路

参考 Lumi_Nox 项目的状态机 + 时间戳机制，在 AAA 节点内部实现轻量化会话管理，**不依赖独立的状态机或事件总线**（AAA 是单进程节点，不需要跨进程的事件分发）。

核心思路：通过在 DB 和 JSON 文件中记录时间戳和会话标记，实现 App 生命周期感知。

### 13.3 状态定义

| 状态 | 含义 | 触发条件 |
|------|------|----------|
| `IDLE` | 空闲（应用关闭） | 初始状态、应用关闭后 |
| `CHATTING` | 对话中（应用打开） | 用户首次发送消息后 |
| `ENDED` | 对话结束（应用关闭） | GUI 关闭后标记 |

### 13.4 时间间隔计算

| 字段 | 存储位置 | 说明 |
|------|----------|------|
| `last_input_time` | `chatbot.db` → `conversation_state` 表 | 每次用户输入后更新 |
| `last_reply_time` | `chatbot.db` → `conversation_state` 表 | 每次 AI 回复后更新 |
| `session_start_time` | `chatbot.db` → `conversation_state` 表 | 状态从 IDLE→CHATTING 时记录 |
| `last_session_end_time` | `chatbot.db` → `conversation_state` 表 | 状态从 CHATTING→ENDED 时记录 |

### 13.5 实现方案

#### DB 新增表

```sql
CREATE TABLE conversation_state (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_status TEXT DEFAULT 'IDLE',     -- IDLE / CHATTING / ENDED
    last_input_time TEXT,                   -- 上次用户输入时间 ISO 8601
    last_reply_time TEXT,                   -- 上次 AI 回复时间 ISO 8601
    session_start_time TEXT,                -- 当前会话开始时间
    last_session_end_time TEXT,             -- 上次会话结束时间
    input_count_this_session INTEGER DEFAULT 0,  -- 本轮会话输入次数
    created_at TEXT DEFAULT (datetime('now', 'localtime'))
);
```

> 该表为单行表（Singleton Row），`id` 始终为 1。写入前先 DELETE，再 INSERT。

#### AAA 行为变更

在 `_gather_context()` 中增加会话状态和时间间隔信息的收集：

```python
def _gather_context(self, user_text, dbp):
    # ... 原有代码 ...
    
    # 新增：会话上下文感知
    session_info = self._get_session_info(dbp)
    
    return {
        # ... 原有字段 ...
        # 新增字段：
        "session_status": session_info.get("status", "CHATTING"),
        "time_since_last_input": session_info.get("time_since_last_input", ""),
        "time_since_session_start": session_info.get("time_since_session_start", ""),
        "input_count_this_session": session_info.get("input_count", 0),
    }


def _get_session_info(self, dbp):
    """查询会话状态并计算时间间隔"""
    conn = sqlite3.connect(dbp)
    try:
        row = conn.execute("SELECT * FROM conversation_state WHERE id = 1").fetchone()
        if not row:
            return {"status": "IDLE", "time_since_last_input": "", 
                    "time_since_session_start": "", "input_count": 0}
        
        now = datetime.now()
        status = row[1]  # session_status
        
        # 计算距离上次输入的时间
        last_input_str = row[2]  # last_input_time
        if last_input_str:
            try:
                last_input = datetime.fromisoformat(last_input_str)
                delta = now - last_input
                time_since = _format_time_delta(delta)
            except:
                time_since = ""
        else:
            time_since = ""
        
        # 计算会话已持续时长
        session_start_str = row[4]  # session_start_time
        if session_start_str and status == "CHATTING":
            try:
                session_start = datetime.fromisoformat(session_start_str)
                session_delta = now - session_start
                session_duration = _format_time_delta(session_delta)
            except:
                session_duration = ""
        else:
            session_duration = ""
        
        return {
            "status": status,
            "time_since_last_input": time_since,
            "time_since_session_start": session_duration,
            "input_count": row[6] or 0,
        }
    finally:
        conn.close()


def _format_time_delta(delta):
    """将 timedelta 格式化为可读字符串"""
    total_seconds = int(delta.total_seconds())
    if total_seconds < 60:
        return f"{total_seconds}秒前"
    elif total_seconds < 3600:
        return f"{total_seconds // 60}分钟前"
    elif total_seconds < 86400:
        hours = total_seconds // 3600
        mins = (total_seconds % 3600) // 60
        return f"{hours}小时{mins}分钟前"
    else:
        days = total_seconds // 86400
        return f"{days}天前"
```

#### 关键触发点

| 触发时机 | 动作 |
|----------|------|
| `_on_text()` 收到用户输入 | 检查 `conversation_state` 表。如果 `session_status != 'CHATTING'`（首次输入或上次会话已结束），将状态从 IDLE 改为 CHATTING，记录 `session_start_time`；更新 `last_input_time` 和 `input_count`。 |
| `_on_parsed()` 处理 LLM 回复 | 更新 `last_reply_time` |
| 下次启动检测到上次 `session_status == 'CHATTING'` | 自动将状态改为 CHATTING（恢复上次会话），记录：上次会话结束时间 = 当前，然后设为新会话 |
| GUI/AAA 检测到应用关闭 | 将状态设为 ENDED，记录 `last_session_end_time` |

#### 轻量化检测（不依赖独立信号）

AAA 不依赖 GUI 发来的 "打开/关闭" 信号（因为涉及跨进程通信复杂度），而是通过以下方式推断：

1. **打开检测**：AAA 的 listener 检测到 `gui_input.json` 文件更新时，如发现 `conversation_state` 中 `session_status == 'IDLE'` 且距上次 `last_session_end_time` 超过 60 秒，则认为"用户打开了应用"
2. **关闭检测**：由于 AAA 无法实时知道 GUI 进程关闭，采用以下策略：
   - AAA listener 设置一个"静默超时"（如 5 分钟），如果超过 `last_input_time` 5 分钟无新输入，自动将状态转为 `ENDED`
   - 或由 GUI 在关闭时额外写入一个标记文件 `shared/session_end.signal`

> Phase 1 方案：使用**5 分钟无输入自动标记 ENDED** + 下次输入时自动恢复 CHATTING。不需要额外信号文件。
