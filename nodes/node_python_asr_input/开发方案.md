## 一、节点定位

AI 的**耳朵 + 耳朵主人识别**。常驻进程，自持麦克风，连续进行：

```
VAD 监听 → 有人说话 → 录音 → STT → 声纹识别 → 情感/事件 → 输出
```

输出到 `turn_taking` 节点（话者交替决策），由后者决定是否触发 AI 回复。

## 二、来源

- **STT 引擎**：参考 Mewco 的 SenseVoice（sherpa-onnx），多语言 + 原生情感输出，替代原计划的 Whisper
- **VAD**：参考 MyNeuro 的 Silero VAD（纯 CPU，毫秒级），替代 dBFS 阈值方案
- **声纹识别**：参考 Mewco 的 CAm++ Speaker Embedding 模型
- **录音**：参考 Mewco 的 PyAudio 连续采集

## 三、职责

- 自持麦克风，连续进行 VAD 检测（不依赖 GUI 触发）
- 检测到有人说话结束时，录音送 STT 转文字
- 提取声纹嵌入，动态匹配/注册说话人
- 输出带 `speaker_id`、情感、事件标记的结构化文本
- 不决定"AI 要不要回复"（交给 `turn_taking` 节点）

## 四、端口定义

### 输入端口

| 端口名 | filter (data_type) | 说明 |
|--------|-------------------|------|
| `config` | `config_update` | 运行时热更新配置（灵敏度、声纹开关等） |

### 输出端口

| 端口名 | data_type | 目标 |
|--------|-----------|------|
| `default` | `voice_segment` | `turn_taking` 节点 |

### 数据流

```
[麦克风] ─── 连续 PCM 流
  │
  ▼
VAD (Silero VAD, CPU, <1ms)
  ├─ 无人说话 → 丢弃音频
  └─ 有人说话 → 缓存音频帧
      │
      │ VAD 检测到结束
      ▼
  完整音频段
  ├─ 声纹 (CAm++) → 嵌入向量 → 匹配 speaker_id
  ├─ 判断 speaker_type
  │   ├─ is_known=True  → known
  │   └─ is_known=False → stranger（首次自动注册但标记陌生人）
  │
  ├─ STT (SenseVoice) → 文本 + 情感 + 事件（无论陌生人/熟人都转文字）
  │
  └─ 组装输出
      │
      ▼
  output.json: {speaker_id, speaker_type, text, emotion, events, confidence}
  │
  ▼
turn_taking 节点（消费 voice_segment）
  ├─ source == "known"    → 按话者交替规则决定是否回复
  ├─ source == "stranger" → 只存日志，永不触发回复
  └─ source == "gui"      → 用户打字，总是回复
```

## 五、整体架构

### 主循环（listener.py）

```python
class ASRListener:
    def __init__(self):
        self.vad = SileroVAD(threshold=0.5)          # Silero VAD 模型
        self.asr = SenseVoiceASR()                     # SenseVoice 识别器
        self.vp = VoicePrintDB()                       # 声纹库
        self.audio_buffer = AudioRingBuffer()           # 环形缓冲区

    def start(self):
        stream = pyaudio.open(rate=16000, channels=1, format=paInt16)
        while True:
            frame = stream.read(512)                    # 32ms 帧
            is_speech = self.vad.is_speech(frame)
            if is_speech:
                self.audio_buffer.write(frame)          # 缓存音频
            elif self.audio_buffer.has_speech():         # 刚说完
                audio_data = self.audio_buffer.drain()
                self._process_segment(audio_data)
            time.sleep(0)                                # 忙等，不 sleep

    def _process_segment(self, audio_data):
        # 1. 声纹提取 + 身份判断（先做，耗时 ~5ms）
        speaker_id, confidence, speaker_type = self.vp.identify(audio_data)

        # 2. STT 转文字（无论陌生人/熟人都转，用于日志记录）
        result = self.asr.transcribe(audio_data)

        # 3. 组装输出（turn_taking 根据 speaker_type 决定是否允许回复）
        self._write_output({
            "data_type": "voice_segment",
            "speaker_id": speaker_id,
            "speaker_type": speaker_type,   # "known" | "stranger" | "unknown"
            "text": result["text"],
            "emotion": result["emotion"],
            "events": result["events"],
            "confidence": confidence,
            "timestamp": time.time()
        })
```

### 为什么不走文件轮询

| 方案 | 问题 |

| GUI 录完 → 写 input.json → ASR 节点转写 | 延迟高（GUI 侧录完才发），无法做 VAD |

## 七、STT 语音转文字

### 选择 SenseVoice（替代 Whisper）

**原因**（参考 Mewco 的实际效果）：

| 维度 | Whisper | SenseVoice (sherpa-onnx) |
|------|---------|------------------------|
| 模型大小 (small/tiny) | 244MB / 39MB | ~40MB (int8 量化) |
| CPU 推理速度 | 慢（3-5x 实时） | 快（0.3-0.5x 实时） |
| 多语言 | ✅ | ✅ 中英日韩粤 |
| **原生情感输出** | ❌ | ✅ HAPPY/SAD/ANGRY/NEUTRAL |
| GPU 需要 | 建议 | 不需要，CPU 即可 |
| 集成难度 | pip install | sherpa-onnx pip 包 |
| 参考实现 | 官方 CLI | Mewco `asr.py` 直接复用 |

## 八、声纹识别（动态注册）

### 核心思想

**不预设说话人名单**。每次录音提取声纹嵌入 → 跟声纹库已有的嵌入逐一比对：

```
新音频 → CAm++ → 128维嵌入向量
  │
  ├─ 跟库中所有向量算余弦相似度
  │   ├─ 最高分 ≥ 阈值(0.6) → 匹配到已有 ID
  │   └─ 最高分 < 阈值     → 新 ID: Speaker_003
  │
  └─ 输出 speaker_id + confidence
```

### VoicePrintDB

```python
class VoicePrintDB:
    def __init__(self, db_path: str = "voiceprints.json"):
        self.db_path = db_path
        # {id: {embedding: [...], name: "", is_known: False, register_time: 0}}
        self.voices: dict[str, dict] = {}
        self._load()

    def identify(self, audio: np.ndarray, threshold=0.6) -> tuple[str, float, str]:
        """识别并返回 (speaker_id, confidence, speaker_type)
        speaker_type:
          "known"    → 匹配到已标记为熟人的 ID
          "stranger" → 匹配到已注册但标记为陌生人的 ID
          "unknown"  → 完全不匹配，动态注册新 ID（默认标记陌生人）
        """
        embedding = self._extract_embedding(audio)
        best_id = None
        best_score = 0.0
        for sid, v in self.voices.items():
            score = cosine_similarity(embedding, v["embedding"])
            if score > best_score:
                best_score = score
                best_id = sid
        if best_score >= threshold:
            # 匹配到已注册声纹
            if self.voices[best_id]["is_known"]:
                return best_id, best_score, "known"
            else:
                return best_id, best_score, "stranger"
        else:
            # 新说话人，动态注册（默认标记为非熟人）
            new_id = f"Speaker_{len(self.voices) + 1:03d}"
            self.voices[new_id] = {
                "embedding": embedding.tolist(),
                "name": new_id,
                "is_known": False,       # 默认陌生人
                "register_time": time.time()
            }
            self._save()
            return new_id, best_score, "unknown"

    def mark_as_known(self, speaker_id: str, name: str = ""):
        """将说话人标记为熟人"""
        if speaker_id in self.voices:
            self.voices[speaker_id]["is_known"] = True
            if name:
                self.voices[speaker_id]["name"] = name
            self._save()
```

## 十一、声纹 ID ↔ 身份绑定

### 概述

ASR 的声纹识别产生 `speaker_id`（如 `"Speaker_003"`），但真正的身份是在对话中由 LLM 认知的（如"张三"）。需要一个桥接层将两者绑定。

### 表结构（AAA 的 `chatbot.db` 中新增）

```sql
-- speaker_bindings: 声纹 ID ↔ 身份
CREATE TABLE IF NOT EXISTS speaker_bindings (
    voiceprint_id TEXT PRIMARY KEY,    -- ASR 的 speaker_id
    identity_key TEXT NOT NULL UNIQUE,  -- AAA 身份 key
    display_name TEXT NOT NULL,         -- 可读名字（默认用 identity_key）
    is_known INTEGER DEFAULT 0,        -- 0=陌生人, 1=熟人
    first_seen TEXT DEFAULT (datetime('now','localtime')),
    last_seen TEXT DEFAULT (datetime('now','localtime'))
);

-- user_profiles: 身份存档
CREATE TABLE IF NOT EXISTS user_profiles (
    identity_key TEXT PRIMARY KEY,
    display_name TEXT NOT NULL,
    created_at TEXT DEFAULT (datetime('now','localtime'))
);
```

### 绑定流程

```
ASR 输出 {speaker_id: "Speaker_003", speaker_type: "unknown", text: "我是张三"}
  ↓
AAA _on_text 收到 → 检查 speaker_id 在 speaker_bindings 中是否有对应 identity_key
  ├─ 有记录 → identity_key 透传到 prompt（"张三在说话"）
  └─ 无记录 → 自动注册：
       speaker_bindings: {voiceprint_id="Speaker_003", identity_key="user_003", is_known=0}
       user_profiles: {identity_key="user_003", display_name="Speaker_003"}
       prompt 中显示："新说话人 Speaker_003 说：我是张三"
  ↓
LLM 回复 → 解析节标记
  ↓
当 【用户信息】节包含 name=xxx 或 voiceprint_name=xxx 时：
  1. 根据当前对话关联的 speaker_id 查 speaker_bindings
  2. 更新 display_name：UPDATE speaker_bindings SET display_name='张三' WHERE voiceprint_id='Speaker_003'
  3. 更新 user_profiles：UPDATE user_profiles SET display_name='张三' WHERE identity_key='user_003'
```

### 熟人标记触发

- **自动**：同一 `voiceprint_id` 出现次数 ≥ N 次（默认 5）后，`is_known` 自动标记为 1
- **手动**：用户说"记住我"或"AI，这是我的朋友" → LLM 输出 `【用户信息】is_known=1` → AAA 更新标记
- **GUI 操作**：设置面板中手动标记说话人为熟人/陌生人

### 与 AAA 现有表的关系

```
speaker_bindings                AAA 现有表
  voiceprint_id  ─────────────→ long_term_memory(source='asr')
  identity_key   ───→ user_facts(category='background')
                     → user_facts(category='preference')
                     → other_cognition
                     → self_cognition
```

所有现有表**不需要改**——speaker_bindings 只占 1 个列（identity_key），查询时 JOIN 即可。

### turn_taking 中的使用

turn_taking 节点消费 voice_segment，根据 `speaker_type` 决定是否允许 AI 回复：

- `"known"` → 按话者交替规则（静音时长、话题相关度、随机因子）决定是否回复
- `"stranger"` → 只记录日志，永不触发 AI 回复
- `"unknown"` → 同 stranger（首次出现的说话人也默认不回）

同时维护 `speaker_bindings` 中 `is_known` 标记的自动升级（累积出现次数达到阈值后自动转为熟人）。

### 14.1 可直接增强 asr_input 的组件

#### 14.1.1 音频降混单声道（downmix_mono）

**jarvis 源码**：`native/src/audio.cpp`（56 行）

多声道音频降混为单声道，所有模型通用输入格式。

```python
# 可直接移植（来自 jarvis audio.cpp）
def downmix_mono(interleaved: np.ndarray, channels: int) -> np.ndarray:
    """多声道降混为单声道，clamp 到 [-1, 1]"""
    if channels == 1:
        return interleaved
    frames = len(interleaved) // channels
    reshaped = interleaved[:frames * channels].reshape(-1, channels)
    mono = reshaped.mean(axis=1)
    return np.clip(mono, -1.0, 1.0)
```

**用途**：PyAudio 采集的可能是立体声，SenseVoice/CAm++ 需要 16kHz 单声道。

#### 14.1.2 线性插值重采样（resample_linear）

**jarvis 源码**：`native/src/audio.cpp`

将系统混音格式（通常 48kHz）降采样到模型要求的 16kHz。

```python
# 可直接移植（来自 jarvis audio.cpp）
def resample_linear(input_data: np.ndarray, src_rate: int, dst_rate: int) -> np.ndarray:
    """线性插值重采样"""
    if src_rate == dst_rate:
        return input_data
    ratio = dst_rate / src_rate
    output_len = int(len(input_data) * ratio)
    indices = np.arange(output_len) / ratio
    left = np.floor(indices).astype(int)
    left = np.clip(left, 0, len(input_data) - 1)
    right = np.clip(left + 1, 0, len(input_data) - 1)
    fraction = indices - left
    return input_data[left] + (input_data[right] - input_data[left]) * fraction
```

**用途**：WASAPI 系统音频通常 48kHz，需降到 16kHz 送 STT。比 scipy.signal.resample 更轻量零依赖。

#### 14.1.3 精确窗口组装器（ExactWindowAssembler）

**jarvis 源码**：`native/src/audio.cpp` + `native/include/jarvis/audio.hpp`

累积音频样本，达到指定窗口大小时切出完整窗口，避免截断。

```python
# 可直接移植（来自 jarvis audio.cpp 的 ExactWindowAssembler）
class ExactWindowAssembler:
    """精确窗口组装器：保证每次输出的音频窗口完整"""
    def __init__(self, sample_rate: int, window_ms: int):
        self.window_samples = int(sample_rate * window_ms / 1000)
        self.buffer = []

    def push(self, samples: np.ndarray) -> list:
        """放入样本，返回 0 或多个完整窗口"""
        self.buffer.extend(samples)
        windows = []
        while len(self.buffer) >= self.window_samples:
            window = np.array(self.buffer[:self.window_samples])
            self.buffer = self.buffer[self.window_samples:]
            windows.append(window)
        return windows
```

**用途**：VAD 检测到语音结束后，确保音频段完整。防止截断导致 STT 识别质量下降。

#### 14.1.4 有声检测（RMS 能量阈值）

**jarvis 源码**：`native/src/worker.cpp` 的 `has_audible_signal()` 函数

计算音频 RMS 能量，判断是否有实质声音（区分静音和说话）。

```python
# 可直接移植（来自 jarvis worker.cpp 的 has_audible_signal）
def has_audible_signal(samples: np.ndarray, threshold: float = 0.000004) -> bool:
    """RMS 能量阈值判断是否有声"""
    if len(samples) == 0:
        return False
    rms = float(np.sqrt(np.mean(samples ** 2)))
    return rms > threshold
```

**用途**：VAD 之前快速过滤静音段，减少 VAD 模型调用。jarvis 阈值 `0.000004` 经过实战调优，可直接参考。

#### 14.1.5 双缓冲设计

**jarvis 源码**：`native/src/worker.cpp` 的 `start_monitoring()` 方法

jarvis 维护两个音频缓冲区：
- `rolling_audio`：32k 采样（2 秒 @16kHz），用于实时双工推送
- `pending_perception_audio`：最大 192k 采样（12 秒），用于感知请求

**BNOS 适配**：asr_input 的 `AudioRingBuffer` 可借鉴双缓冲设计：
- **短缓冲**（2 秒）：用于 VAD 判断和即时响应
- **长缓冲**（12 秒）：用于 STT 转写，保证长句不被截断

```python
# 借鉴 jarvis 的双缓冲设计
class DualAudioBuffer:
    def __init__(self, sample_rate=16000):
        self.sample_rate = sample_rate
        self.short_buffer = collections.deque(maxlen=sample_rate * 2)    # 2秒，VAD 用
        self.long_buffer = collections.deque(maxlen=sample_rate * 12)   # 12秒，STT 用

    def push(self, samples: np.ndarray):
        self.short_buffer.extend(samples)
        self.long_buffer.extend(samples)

    def get_recent(self, seconds: float) -> np.ndarray:
        """获取最近 N 秒音频"""
        count = int(self.sample_rate * seconds)
        return np.array(list(self.short_buffer)[-count:])
```

## 十五、新节点建议：node_python_audio_input

### 15.1 为什么需要独立节点

当前 asr_input 只采集**麦克风**（用户说话）。但 AI 还需要"听系统播放的声音"：

| 场景 | 麦克风（asr_input） | 系统音频（新节点） |
|------|:---:|:---:|
| 用户说话 | ✅ | - |
| 用户看视频 | - | ✅ 听到视频内容 |
| 用户听音乐 | - | ✅ 识别音乐类型 |
| 游戏音效 | - | ✅ 辅助场景判断 |
| 网课音频 | - | ✅ 课程转写 |

**独立判断标准**（参考节点开发规范 §2.1）：

| 标准 | 判断 |
|------|------|
| 不同技术栈 | ✅ PyAudio 麦克风 vs WASAPI/pycaw 回环 |
| 不同崩溃域 | ✅ 麦克风挂了系统音频还能工作 |
| 独立业务逻辑 | ✅ 系统音频有独立的有声检测、格式转换、输出协议 |
| 可独立开发测试 | ✅ 不依赖 asr_input 的 VAD/STT/声纹链路 |
