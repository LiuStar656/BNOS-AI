## 一、目标（用户 2026-08-11）

**结构应该从动力学自然涌现，不是代码灌进去的**——否则等同大模型训练（人工架构+数据）。

```
灌（错——已放弃）: consolidate 分配槽位 + 直写边 → 结构代码赋予
涌现（对——目标）: 神经元+词表+物理法则 → 教学（输入+奖惩）→ 结构自然长出
```

## 二、代码只留什么（物理法则——不是设计）

| 法则 | 作用 | 生物对应 |
|---|---|---|
| 膜电位/WTA/不应期 | 神经元动力学 | LIF 模型 |
| STDP | 突触可塑性（共现→建边） | Hebbian / STDP |
| DA 门控 | 奖励/惩罚（引导方向） | 多巴胺调制 |
| 资格迹（_elig_pairs） | 时间信用分配（延迟奖惩归因） | eligibility trace（Izhikevich 2007）|
| 侧抑制/竞争 | 选择（谁发放） | lateral inhibition |

**这些是"物理"不是"设计"——代码保留**。除此之外（槽位/绑定/轨道/互斥规则）都应从法则+经验涌现。

## 三、自然涌现的条件（逐条——实验验证状态）

### 条件 1：零边起点（不连线）——✅ 已验证

```
v52.2（神经元+词表+机制，边=0）→ 教学 → STDP 自然建边
用户："为什么要连线？"——不需要——STDP 从 0 边自己建（共现→Hebbian）
验证: 教学「叫爸爸」30 次 → 40 条边自然长出 → 叫→爸爸 256
```

### 条件 2：STDP 自然建边（共现→Hebbian）——✅ 已验证

```
共同出现的词（叫+爸爸）→ 相邻注入 → STDP 强化 → 边建立
用户："建边是正常的——短时间内同时出现自然会建边"
这是联想（System 1）的基础——不是污染
```

### 条件 3：竞争选择（WTA 收窄）——✅ 已验证

```
WTA 窗口收窄（wta_k=4——每拍 1 词）→ 只有 v 最高的发放
多候选边并存时（叫→爸爸/妈妈/爷爷）→ 竞争选出当前最强的
验证: 「叫妈妈」→ 妈妈（爸爸/爷爷被竞争压掉——不再全带出）
```

### 条件 4：论元强调（韵律）——✅ 已验证

```
注入论元用强调幅度（amp=4）→ 论元 v 最高 → 竞争胜出
生物对应: 成人教学强调目标词（儿向语 prosody）
验证: 强调后「叫妈妈」→ 妈妈（注入+驱动 → 排序第一）
```

### 条件 5：奖惩引导（奖励强化正确）——✅ 已验证

```
奖励（da>0）→ mod>0 → 强化"本次教学配对"（叫爸爸→叫爸爸边）
无奖励（da=0）→ 不强化（共现仍建边——自然——但不受引导）
验证: 奖励教学 10 次 → 叫→爸爸 13→30→107→238（逐次强化）
```

### 条件 6：惩罚引导（惩罚压制错误）——⚠️ 部分验证（有遗留问题）

```
惩罚（da<0）→ mod<0 → 压制"本次行为配对"
惩罚力度: punish_factor=3（比奖励陡——惩罚反应快）
验证: 错误边 238→236（被压——但效果弱/只压一次——遗留问题见 §五）
```

### 条件 7：奖惩是"方向"不是"开关"——✅ 已验证（用户确认）

```
建边 = 自然（共现——无条件）
奖励 = 引导强化（"这个对——记住"）
惩罚 = 引导修正（"这个错——不建立"）
用户："建边是正常的"——奖惩引导的是"边的强弱/去留"，不是"是否建边"
```

### 条件 8：System 1/2 自然分化——✅ 已验证（用户确认）

```
联想（System 1）: 叫→爸爸 自然激活（"看到叫出现爸爸"——思考）
回答（System 2）: 叫爸爸→爸爸（论元确认后——教学塑造）
两者并存——不冲突——引擎自然涌现
「叫」单独→爸爸 = 自然联想（正确——不是 bug——不该惩罚）
```

## 四、自然涌现的完整流程（教学协议）

```
① 准备: v52.2（神经元+词表+机制——零边）
② 教学: 说「叫 爸爸」+ 奖励（正确场景）+ 论元强调
③ 涌现: STDP 建边（共现）→ 竞争选择（WTA收窄）→ 论元胜出
④ 引导: 奖励强化正确配对 / 惩罚压制错误配对
⑤ 验证: 输入「叫爸爸」→ 爸爸（回答）；「叫」→ 爸爸（联想）
```

**老师只做三件事**：说（输入）、给零食（奖励）、不给/罚（惩罚）——**不碰网络结构**。

## 五、遗留问题（诚实记录）

### 问题 1：惩罚效果弱/不稳定

```
错误边 238→236（惩罚只压 2 点——力度 3 倍仍弱）
且"惩罚教学"本身可能强化（注入共现→STDP——即使 da<0）
根因: 资格迹配对（_elig_pairs）打标——(叫,爷爷) 配对缺失
      （词内 叫→叫 配对多——目标配对没标上）
待查: 配对打标时序（_prev_inp 与注入拍的错位）
```

### 问题 2：未教论元泛化不完美

```
「叫 妹妹」（未教）→ 选历史论元（爷爷）而非妹妹
根因: 妹妹无 叫→妹妹 边（未共现过）——竞争时无候选
      泛化需要"开放槽"（未教词也能填）——纯 STDP 未长出
待查: 类型变异更充分？竞争机制（论元强调更强）？
```

### 问题 3：颗粒度（同一边不同场景）

```
叫→爸爸: 「叫爸爸」场景=对（奖励）；「叫」单独场景=联想（不罚？）
同一条边——场景不同——奖惩不同——需要"条件性"（context-dependent）
当前: 靠教学协议（老师决定何时奖励/惩罚）——引擎不做场景判断
      （避免代码规则——保持引擎纯法则）
```
