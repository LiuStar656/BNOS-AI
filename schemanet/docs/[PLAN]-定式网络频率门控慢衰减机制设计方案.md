## 一、背景与现状评估

### 1.1 记忆管理机制现状（三代演化）

| 机制 | 状态 | 选择性 | 突发性 | 可复活 |
|---|---|---|---|---|
| weight_decay 慢衰减 | **已废弃**（默认 0） | 无差别衰减所有连接 | 渐进 | 休眠期全忘 |
| slot_cap 满槽覆盖 | **待废除**（用户决策） | 只挤弱连接 | 写时突发 | 被挤即失 |
| learn_gate 学习门 | 在用 | — | — | 冻结 = 物理零改动 |

**关键事实**：
- [SparseSchemaNet（sparse_net.py）](file:///e:/杂项/BNOS_AI_project/schemanet/sparse_net.py#L40-L175) 只存储 `slot_cap` 属性，**从未实现覆盖逻辑**——语言实验（slot_cap=0）下实际**没有任何遗忘机制在生效**，W 无上限增长（当前 1809 万连接）
- 满槽覆盖实现只在稠密版 [schema_net.py `_enforce_slot_capacity`（L173-196）](file:///e:/杂项/BNOS_AI_project/schemanet/schema_net.py#L173-L196)
- weight_decay 当年被废弃的根因：**无差别衰减**——活跃定式也要靠学习强化抵消，学习间歇（休眠期）全部弱化，违背"久不复习不洗掉"的封存哲学

### 1.2 用户的决策与动机

1. **废除槽位上限**：取消"装不下就挤最弱"的写时覆盖——连接不再因容量被挤掉
2. **频率门控慢衰减**（v0.2 定案）：低频唤醒的槽位**不删除连接**，连接**逐步衰减为 0**——渐进、可复活；高频槽位不衰减
3. 生物对应：突触修剪的渐进性 + 稳态可塑性 + 睡眠记忆巩固 + **艾宾浩斯遗忘曲线**（衰减中有恢复窗口）

### 1.3 与上一版（频率淘汰·清空式）的对比

| | v0.1 频率淘汰（清空） | v0.2 频率门控衰减（定案） |
|---|---|---|
| 低频槽动作 | `clear()` 一键清空 | 连接逐周期 ×(1-λ) 渐进弱化 |
| 可复活 | 无（清空即失） | **有**（衰减中复习 → Hebbian 强化抵消 → 权重回升） |
| 误杀风险 | 高（把"即将被想起"的定式清掉） | 低（渐进给恢复窗口） |
| 稀疏回收 | 立即 | 衰减到 `eps` 后删除条目 |
| 记忆曲线 | 阶跃 | 平滑遗忘曲线 |

### 1.4 为什么需要新机制（废除后的真空）

废除 slot_cap 后若不做替代，W 只会单向增长（每学一句都新增连接，噪声连接也永久累积）。频率门控衰减是**唯一的回收通道**——且相比 weight_decay 多了"频率门控"这一关键选择：**活跃定式永不衰减，只忘低频**，恰好修复了 weight_decay 被废弃的根因。

1. **废除 slot_cap 满槽覆盖**：代码路径停用（保留参数默认 0 + 标记废弃），文档更新

## 三、方案设计

### 3.1 唤醒计数（与 v0.1 相同的干净口径）

```
数据结构：
  slot_freq  int32[n, slots]      # 唤醒计数
  window     步数窗口（如 2000）
  min_wake   窗口内最少唤醒次数（如 5）

计数时机（step() 内，唯一的正确口径）：
  new_spikes > 0 的神经元 i → slot_freq[i, k_star[i]] += 1
  （k_star 每步对所有神经元 argmax，但只有发放神经元的主导槽才算"唤醒"——
    静息步 v≈0 的 argmax 是噪声性选择，计入会污染计数）
```

> 不用全局频率分母（`freq / total_steps`）：语言实验 45 万步 × 阈值 0.01 = 需 4500 次唤醒才免衰减 → 任何槽位都达不到 → 全量弱化。滑动窗口计数语义稳定、不随实验规模漂移。

### 3.2 整理动作（sleep_consolidate，逐步衰减为 0）

```python
def sleep_consolidate(self, window=2000, min_wake=5, decay=0.3, eps=1e-4):
    """低频槽位连接逐步衰减。衰减中可被唤醒复活；归零条目删除释放。"""
    if not self.learn_gate:          # 冻结态拒绝执行（物理零改动语义）
        return 0
    cleared = 0
    for i in range(self.n):
        for k in range(self.slots):
            if self.slot_freq[i, k] >= min_wake:
                continue             # 活跃槽不衰减
            row = self.W_out[i][k]
            nv = {j: w * (1 - decay) for j, w in row.items()}
            for j, w in nv.items():
                if w <= eps:
                    del row[j]       # 归零 → 删除条目（稀疏回收）
                    cleared += 1
                else:
                    row[j] = w
            self.slot_freq[i, k] = 0
    return cleared
```

**设计要点**：
- **保留在槽位上**：连接条目在衰减过程中一直存在（可被读出/传播/复习强化）——用户"保留在槽位上"的语义
- **逐步衰减为 0**：每周期 ×(1-λ)，多周期后逼近 0；到 `eps` 阈值删除条目释放空间
- **可复活**：衰减中该槽被唤醒 → Hebbian/STDP 写入（eta=0.1、stdp_pre=0.5）与衰减率（decay=0.3/周期）竞争，复习充分则净回升——无需额外"复活"逻辑，动力学自带
- **清理后联动**：S 矩阵（`build_score_mat`）与 grad_readout 的 edge_mirror 基于 W，整理后需重建

### 3.3 触发时机（睡眠/整理语义）

| 时机 | 说明 | 推荐 |
|---|---|---|
| 显式 `sleep()` 调用 | 学习阶段结束后整理（生物对应睡眠记忆巩固） | **主推**（语义干净） |
| 周期性（每 window 步） | 学习过程中顺带整理 | 可选 |
| 手动触发 | 实验/调试用 | 保留 |

### 3.4 与现有机制的关系

| 机制 | 废除前 | 废除后 |
|---|---|---|
| slot_cap 满槽覆盖 | 写时挤最弱 | **停用**（参数保留默认 0 + 标记废弃，历史留档可重跑） |
| weight_decay | 已废弃（无差别） | 不复活；**频率门控衰减取代其位置**（选择性版本） |
| 频率门控衰减 | 无 | **唯一遗忘机制**（低频槽渐进弱化） |
| learn_gate 冻结 | 冻结不学习 | 不变；且**冻结时 sleep 拒绝执行** |
| 豁免/封存 | 容量内隐式保留 | **不需要独立豁免**——衰减中可复活即内置恢复窗口 |

> 记忆观转变：**"装得下就不动"（容量驱动被动保留）→ "用进废退、可复活"（使用驱动渐进遗忘）**。高频定式永不衰减；低频定式缓慢弱化、期间被想起即复活、长期不用最终归零回收。

## 五、风险评估

| 风险 | 等级 | 缓解 |
|---|---|---|
| **衰减参数标定不当**：decay 过大误伤、过小回收无力 | 高 | Phase 2 人工 A/B 定式标定（decay ∈ {0.1, 0.3, 0.5}）；语言接入保守起步（decay 偏小 + min_wake 偏大） |
| **复活竞争失衡**：衰减率长期压过强化率，低频定式"想复活但复不起来" | 中 | 已验证强化率（eta=0.1/拍、stdp_pre=0.5）量级 >> 周期衰减率（decay=0.3/周期）；Phase 2 显式验证复活路径 |
| **计数噪声**：静息 argmax 污染计数 | 低 | 口径已定"只数发放神经元"；Phase 2 断言静息期计数不增长 |
| **冻结语义破坏**：sleep 改 W 违反 learn_gate=False 零改动 | 低 | `sleep_consolidate` 内检查 learn_gate，冻结拒绝执行 |
| **验收口径变化**：语言验收"W 结构不变"不再成立 | 中 | 升级为"活跃保留 + 低频回收率报告"；train_w 稀疏梯度只更新非零子集，整理后需重建 S/镜像 |
| **静态实验受影响**：freeze 实验 slot_cap 依赖 | 中 | Phase 0 回归重跑，重新判读强度增量口径 |
| **低频定式最终归零不可复活**（超出恢复窗口） | 设计决策 | 用户已接受 use it or lose it；恢复窗口长度由 decay 与窗口大小共同决定，可调 |
