# 定式网络 Stage 3 v16 实验报告（句式颗粒度升级：配对句式 + 小句内容 + 句式状态机读取）

> 日期：2026-08-10 | 状态：[OK] | 版本：成长路线 §2.6 复杂句单元"句式复杂度升级"实现（快照 v15.0 → **v16.0**，全量验收 301s 通过）

## 一、背景与需求

用户两次决策（2026-08-10）：

1. **"s3 在句式上的颗粒度不够，句式的复杂度没有这么低"**——当前 s3 训练数据是 4 词骨架 `[关系词1, X, 关系词2, Y]`（11 条），真实关系句远更复杂（内容小句化、关系词位置多样、可嵌套、有修饰）；
2. **"用质量更好的来训练，主要是对话和短文的"**——数据源从商品评价语料（stage3_sents.json）改为**质量更高的对话类和短文类语料**。

前置探测（`20260810_122047_probe_s3adv`，v15.0 上实测）量化差距：

| 维度 | 现 s3（4 词骨架） | 真实语料（15000 句商品评价） |
|---|---|---|
| 长度 | 4 词 | 均值 **15.3 词**，8-16 词为主 |
| 关系词位置 | 句首+句中（固定配对） | 句首/句中/句尾多样，配对/单用并存 |
| 内容结构 | 单 X 单 Y | 内容小句化（S V O）、时间修饰、助词 |

v15.0 上升级句式（6-8 词小句化）读取仅 **10/29 = 34.5%**，三类断点：

- **① 配对直读过度触发**：`因为今天→所以`（跳过内容小句"下雨"）——v15 的 REL_NEXT 配对直读只适配 4 词骨架，关系词1 后还有内容时过度触发；
- **② 后半关系词无上下文**：`所以→吃饭`（期待结果主语"我"，所以→我 无边）；
- **③ 主语结尾断读**：`所以我→你`（真实语料边 我→你 201.6 碾压专门边）。

## 二、方案设计

### 2.1 数据（质量优先：对话 + 短文）`stage3_rel_v2.json`，108 条

| 来源 | 数量 | 说明 |
|---|---|---|
| 短文·真实 | 47 | **toutiao 新闻标题精筛**（382688 行 → 去标点 → jieba 分词 → 无 ASCII 专名 → 词表外词 ≤4 → 5-22 词），真实短文句式 |
| 对话·构造 | 38 | 日常口语关系句（"因为他累了所以他想睡觉"） |
| 短文·构造 | 23 | 叙述关系句（"因为今天下雨所以我带伞"） |

四维全覆盖：嵌套复合 / 内容小句化（因为[S V O]所以[S V O]）/ 关系词位置多样 / 句内修饰加长（今天 / 助词了 / 动宾 / 去地点）。

### 2.2 读取 = 句式状态机 `clause_next`（废除 v15 REL_NEXT 配对直读）

状态：`NONE → 读关系词1 → PRE → 读关系词2 → POST`，按状态选择读取路径：

```python
def clause_next(ng, pats, n2w, prefix, k=6, domain=None):
    state, rel1 = clause_state(prefix)
    last = prefix[-1]
    if state == "PRE" and rel1:
        # 内容小句读取：读内容词传出突触 top-1（排除人称——内容小句尾部再读人称
        # = 开新小句，超出"单一配对句"边界；且真实边 了→你 碾压专门边）
        top = direct_next_multi(ng, pats, n2w, [last], k=1,
                                domain=domain, exclude=PERS_SET)
        if top and top[0][0] in REL_BACK:
            # 内容读完（top-1 是关系词2）→ 配对约束直读（因为→所以）
            nxt = REL_FRONT[rel1]
            w = edge_between(ng, pats, rel1, nxt)
            return [(nxt, w if w > 0 else 1.0)]
        return top if top else []
    if state == "POST":
        if last in REL_BACK:
            # 关系词2 后先读结果主语（排除 V/O/关系词 + 域内过滤）
            return direct_next_multi(ng, pats, n2w, [last], k=k,
                                     exclude=VB_O | REL_ALL, domain=domain)
        # 结果主语后读结果谓语（排除人称，避开 我→你 201.6）
        return direct_next_multi(ng, pats, n2w, [last], k=k,
                                 exclude=PERS_SET | {"在"}, domain=domain)
    return direct_next_multi(ng, pats, n2w, [last], k=k, domain=domain)
```

三类断点逐一修复：① PRE 阶段只读内容词传出突触，**内容没读完不配对直读**；② POST 阶段关系词2 后**排除 V/O 读结果主语**；③ 结果主语后**排除人称读结果谓语**（避开 我→你 201.6）。

### 2.3 验收 = 分句接话（对话语义：教师说前半 → 网络逐词接后半）

6 句代表（覆盖三类关系 + 四维升级），按**角色类型**判定命中（尊重内容多样性——主语位任何人称、谓语位任何动作/宾语都算句式接对）：

| 前半（教师说） | 后半（网络接） | 角色链 |
|---|---|---|
| 因为今天下雨 | 所以我带伞 | REL2 / SUBJ / PRED |
| 虽然他生病了 | 但是他上课 | REL2 / SUBJ / PRED |
| 先吃饭 | 然后我写作业 | REL2 / SUBJ / PRED |
| 因为他累 | 所以他睡觉 | REL2 / SUBJ / PRED |
| 虽然下雨 | 但是我们去公园 | REL2 / SUBJ / PRED / PRED |
| 因为饿 | 所以我吃饭 | REL2 / SUBJ / PRED |

REL2 位用**配对约束**（因为→所以）严格判定；SUBJ/PRED 位用角色词集宽判定。

### 3.1 校准分析（教师批改，全量仅 1 处）

`虽然他生病了但是他→?` PRED 位期望"上课"，网络读出"生病"——**真实语料边 他→生病 碾压专门边 他→上课**（"他生病"在商品评价语料中高频）。校准固化 他→上课 ×6 反超。整个 v16 只此 1 处，与 v15 的"真实边碾压专门边"是同一矛盾的更小化复现（108 条高质量数据已经把碾压降到最低）。

### 3.2 修正前 17/19 的两处断点（均为 PRED 位，校准后全修复）

- `虽然他生病了但是他→上课`：读"生病"（他→生病 碾压）→ 校准 ×6；
- `因为他累所以他→睡觉`：读"生病"（他→生病 强势传出突触共享）→ 校准后共享"上课"也自动落入 PRED 合法集 ✅。

## 四、关键洞察

1. **句式复杂度上不去的根因不是句子少，而是"网络见过的句式太少"**——读不出来 = 读取机制（状态机）+ 数据质量（对话/短文真实句式）双缺；
2. **纯注入开源语料无效**：真实语料边碾压专门定式边（v15 已验证 在→你 206.0 vs 在→看 8.0）；正确路径 = **受控小句化专门化 + 真实短文精筛补充**（108 条高质量数据 > 15000 条低质商品评价）；
3. **状态机是读取约束，不是新语言知识**——它像人读长句时跟踪"我在原因段还是结果段"，读出的仍是已学边；
4. **分句接话 + 角色判定**是比"整句逐词精确生成"更合理的验收口径：对话语义下"所以→他"与"所以→我"同样自然，宽判定尊重内容多样性，同时 REL2 配对约束锁死句式骨架；
5. **真实边碾压的量化落点变了**：v15 是 在→你（206 vs 8），v16 是 他→生病 vs 他→上课（校准 6 次即反超）——数据质量提升后碾压幅度急剧缩小。
