## 一、背景

用户观察到"模型文件 16MB，加载到内存却占 500MB"，追问原因与优化空间。静态分析确认元凶是 `W_out[i][k] = {j: w}` 的 Python dict 存储（[sparse_net.py L124-125](sparse_net.py 内)），并参考 llama.cpp（MMap/单文件）、量化（精度匹配语义）、ONNX（结构-实现解耦）提出优化方向。本实验用真实快照实测三种存储结构的真实 RSS，量化优化空间。

**存储格式（文件，13B/边）**：`src_i(int32) + slot_k(int8) + dst_j(int32) + vals(float32)`，zip 压缩后 23MB。

**内存结构（运行时）**：
- dict 事实源 `W_out[i][k][j] = w`（每边 ~70-110B，含 int 键/float 值/哈希槽）
- numpy 镜像缓存 `_edge_row → (dst int64, w float64)`（16B/边，懒重建，传播热路径）

## 三、三方案对比（同一快照）

| 方案 | 边存储 | 实测 RSS | 相对现状 | 写入能力 |
|---|---|---|---|---|
| 现状（dict 事实源） | dict ~110B/边 | **~2.1 GB** | 1× | 全功能 |
| 数组事实源（int32+float32） | 8B/边 | **~69 MB**（边）+ 运行时 + 环境 ≈ 150-170MB | **省 ~92%** | 需写侧改造（二分定位） |
| mmap 只读（llama.cpp 式） | 磁盘按页换入 | **~107-177 MB** | 省 ~92-95% | 只读（教学需复制） |
| dtype 瘦身（镜像 int32/float32） | 16B/边→12B/边 | −137 MB | 仅省 7% | 全功能 |

## 四、结论

1. **dict 是绝对元凶**：1807 万边 × ~110B ≈ **1.9GB**，占加载内存的 90%+。文件 13B/边 vs dict 110B/边 ≈ **8.5 倍放大**。
2. **数组事实源优化空间实测 92%**：2.1GB → ~150-170MB。这是唯一的主要手段。
3. **dtype 瘦身是次要手段**：在 dict 存在时 int64→int32 仅省 137MB（7%）——先去掉 dict，再谈精度。
4. **mmap 红利**：只读场景（诊断/复现对话）实测 107-177MB，与"数组事实源"同量级，且**零结构改动**。
5. **认知修正**：此前观察的"500MB"是教学运行中间态（镜像未全量构建）；该快照完整加载实际需 **2.1GB**——内存问题比此前认知更严重，优化收益比此前估算更大。

## 五、方案 A 已实施（2026-08-10，实测落地）

**实施内容**：`W_out` 由 dict 重构为 **EdgeRow**（[sparse_net.py] 内）：每行 `dst(int32, 排序) + w(float64)` 数组事实源 + dict 兼容接口（get/setitem/items/clear/update/pop…）。外部脚本零改动；镜像 = 数组视图（dirty 机制废弃）；Hebbian/STDP 改批量合并（batch_update）、weight_decay/sleep 改整行 scale+prune；load/snapshot 改按行分组批量构建。同步适配：snapshot.py、grad_readout.py（restore_w/build_edge_mirror/sync_edges）、_speak/_grow_v11/_diag_v11 置脏调用。

**实测验证（同一快照 20260810_103033_我_rule）**：

| 验证项 | 结果 |
|---|---|
| 加载耗时 | **1.5s**（重构前 dict 逐条插入 ~分钟级） |
| 加载 RSS | **343MB**（重构前完整 2138MB，省 84%） |
| 结构对拍 | nnz=18,071,248、总重=8,509,135.9 与文件逐值一致；抽样 3101 组 / 390,267 边逐边一致 |
| 行为对拍 | _speak 教学全链路 78 轮通过（奖励/惩罚/示范/独立说出/自判应答/保存），边读数正常（吃→苹果 256.0、看→公园 192.0） |
| GradReadout | 梯度一步 60 边变化 → sync_edges 写回 → restore_w 回滚逐边一致；sync 空转零扰动 |

**内存账落地**：完整加载 2138MB → **343MB**（省 84%），且镜像不再重复占内存（原 +290MB）。剩余大头：EdgeRow 边数组 217MB（12B/边）+ 60 万行容器 77MB。后续可再压：int32+float32（w 改 float32 需行为对拍）、mmap 只读通道（~107MB）。
