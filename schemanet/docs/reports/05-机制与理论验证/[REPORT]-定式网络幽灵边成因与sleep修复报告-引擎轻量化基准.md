## 一、幽灵边成因

**幽灵边 = 边权 <1 的微痕边**（Hebbian/STDP 的"任何一次共同发放就建边"——+0.1~0.5 权重）——35k 词组合空间 × 长期训练/噪声发放 → 5643 万条共现痕迹——**只增不减**。

**v34.0 实测分布**：

```
总边 56,428,786：
  <1：54,209,652（96.1%）← 幽灵边
  1-10：2,181,172（3.9%）
  10+：37,962（0.1%）← 真正有用的边（教学/固化定式）
活跃词（有 ≥10 强边）：1,476/37,144 = 4%
```

## 二、sleep 机制为什么没清（三个设计问题）

| 问题 | 证据 |
|---|---|
| ① 从未被调用 | sleep_consolidate 是孤儿机制（训练流程 live12 等未接入——2026-08-11 发现） |
| ② 阈值 eps=1e-4 太低 | prune_below 只删 ≤0.0001——0.1~0.9 的幽灵边全在"安全区"——设计性漏掉 |
| ③ 弱化不清除 | 低频槽 ×0.7 弱化——弱化到 0.09 仍 >1e-4——永远保留 |

**sleep 设计意图是"清低频垃圾"——但阈值使 96% 的幽灵边被设计性地漏掉**（实测"删 10 弱边" vs 5600 万）。

## 三、sleep 修复验证（eps=1.0）

```
剪枝前：边 56,428,786（677 MB）| 泛化 10/10
剪枝后：边 928,497（11 MB）   | 删除 55,500,289 条幽灵边
等价性：泛化 10/10 → 10/10 ✅ 能力完全保持
```

**正确阈值 = 1.0**（清微痕保强边——64 权重教学边/固化主干不受影响）——对应大脑睡眠的**突触稳态假说**（synaptic homeostasis：睡眠整体弱化突触、保留强连接）。

## 四、性能基准（剪枝前后）

| 指标 | 剪枝前 | 剪枝后 | 变化 |
|---|---|---|---|
| 边数 | 56,428,786 | 931,952 | **-98%** |
| 边存储 | 677 MB | 11 MB | **-98%** |
| 加载 | 3587 ms | 467 ms | **快 7.7 倍**（实测均值 3 次） |
| free_read | 0.014 ms | 0.010 ms | 快 ~30% |
| direct_next | 3.956 ms | 3.999 ms | 不变（Python 逻辑瓶颈——非边数） |
| edge_between | 0.267 ms | 0.250 ms | 微快 -6% |

**分析**：网络是"逻辑密集"不是"计算密集"——direct_next 只扫目标词的 4 神经元行（Python 层 Counter/循环/n2w 查询开销主导）——剪枝不减推理计算。**剪枝的真实收益是长期的**：空间 -98%、加载快 7.7 倍、sleep 每次调用快 ~60 倍（扫 92 万 vs 5600 万边）、训练内核（行内 6 条 vs 400 条边）更快、增量学习维护在干净图上、汇聚边界行为更干净。

## 五、引擎轻量化完整方案

| 侧 | 手段 | 效果 |
|---|---|---|
| 参数侧 | sleep eps=1.0 剪幽灵边 | 677→11MB（-98%）——已验证能力等价 |
| 代码侧 | 引擎分层：推理引擎（numpy only——去 numba 内核 651 行/去 schema_net 参考实现 1689 行） | 4240 → ~1300 行（-70%）——numba 仅训练需要（step/STDP——5600 万边性能必需——训练引擎保留） |
| 接口侧 | Net.load(version) 一句话加载（domain/teach_out 快照缓存——已验证快 2.6 万倍）+ net.process(stimulus) 流式推理 | 7 步启动 → 2 句跑起来（大模型式） |
| 速度侧 | 推理路径 numba 化（direct_next 汇聚循环） | 边际收益（4ms 已轻——除非高频调用）——暂缓 |

**净效果**：推理引擎 = numpy only + ~1300 行 + 11MB 边 + 467ms 加载——**部署轻 3 个数量级 vs 大模型（几十 GB + 框架依赖）**。

## 六、结论

1. 幽灵边 = Hebbian 微量累积的共现痕迹（只增不减）——96% 是无行为价值的微痕
2. sleep 机制存在但三问题（未调用/阈值 1e-4 太低/弱化不清除）——**修复 = eps=1.0**——一次清 98% 且能力等价
3. 剪枝收益在"长期"（空间/加载/后续每步训练）——不在"推理计算"（逻辑瓶颈）
4. 引擎轻量化三侧方案齐备（参数 -98% / 代码 -70% / 接口 2 句）——推理引擎 numpy-only
