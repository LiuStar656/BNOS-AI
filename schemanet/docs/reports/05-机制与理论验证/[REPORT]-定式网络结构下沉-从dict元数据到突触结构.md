## 一、问题（用户 2026-08-11）："机制明白了，可是结构呢？怎么放到网络上"

定式框架（叫X / 跟我一起说X）的机制已验证（互斥/同义/论元回声）——但用户指出关键：**结构目前一半在网络、一半在代码**。

```
【突触层（真·网络结构——快照可存）】
  叫 → 槽0（64 强边）——入口边
  槽0 → 槽1（64）——主干边
  槽1 → 我（64）——读出边
  → 网络"物理上"有 叫→槽0→槽1→我 的轨道（synfire chain）

【代码层（dict 元数据——剥离代码就没了）】
  fixed={} / content={0:[槽0],1:[槽1]} / bound={叫:0, 我:1} / first=[叫,我]
  → "哪个位是槽、词绑哪个位" 的语义在 dict 里——不是突触
```

**结构没有完全放上网**——语义（绑定/固定位/内容位）靠 dict 记录，剥离代码就没了。

## 二、SNN 结构表达（文献基础）

| SNN 结构 | 表达什么 | 我们的对应 |
|---|---|---|
| **Synfire chain**（同步发放链，Abeles 1991）| 序列结构——A→B→C 顺序激活 | 槽0→槽1 主干边 = **轨道** ✓ |
| **Cell assembly**（细胞组装，Hebb 1949）| 概念 = 神经元组 | 词 = 4 神经元组 ✓ |
| **Attractor**（吸引子，Hopfield 1982）| 模式稳定态 | 槽位激活 = 轨道态 |
| **角色-填充绑定**（role-filler binding，Hummel & Holyoak 2003）| "谁在哪个槽" | **关键——绑定从 dict → 同步发放** |

### 角色-填充绑定的神经实现（Hummel & Holyoak——结构映射的 SNN 方案）

```
角色神经元（role）: 槽位（叫X 的 X 位置）——独立神经元
填充神经元（filler）: 具体词（爸爸/妈妈/爷爷）
绑定（binding）: role×filler 的**同步发放**（temporal binding）
  —— "爸爸在槽1" = 槽1 与爸爸**同步发放**（Hebbian 绑定——不是 dict！）
```

**结构放上网 = 绑定从 dict 变成突触/同步发放**。

## 三、现状盘点：哪些已是结构、哪些还在代码

| 结构 | 现状 | 性质 |
|---|---|---|
| 轨道（synfire chain）| 槽0→槽1 主干边 w=64 | ✅ **纯突触**（真结构）|
| 入口边（词→槽0）| 叫→槽0 w=64 | ✅ 纯突触 |

## 四、下沉方案（结构全放上网）

```
① 轨道 = 纯突触（已有）——synfire chain ✓
② 绑定 = 突触（已有槽→词边）——"爸爸在槽1" = 槽1→爸爸 边存在 ✓
③ 互斥 = 突触竞争（独立轨道——入口不共享）✓
④ 角色-填充 = 槽神经元 + 绑定边（已有）——去掉 dict 解释
⑤ 剩余 dict（fixed/content/bound）→ 只做"构建脚手架/快照恢复"
   ——运行时语义全在突触——dict 剥离后网络仍工作
⑥ 消歧规则（论元回声/硬过滤）→ 下沉为突触竞争/抑制
   ——论元回声: 注入词兴奋（v 高）→ WTA 自然胜出
   ——联想过滤: 主干边强（64）vs 联想边弱（≤16）→ 轨道候选占优
```

### 终极形态

```
剥离 skeletons dict（运行时）——网络只靠 W_out 边结构表达框架：
  "叫→槽0→槽1→我" 就是全部——dict 只是构建过程的脚手架
  快照保存 W_out（边）+ 词表——加载后纯突触运行
```
