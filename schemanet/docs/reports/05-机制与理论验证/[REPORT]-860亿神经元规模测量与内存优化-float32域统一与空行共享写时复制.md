## 三、优化实施（保证神经元数量不减少）

### 3.1 float64 → float32 域统一

```
所有神经元状态数组（v/spikes/fat/pre_trace/gain/_drive_any/elig）：
  np.zeros(n) → np.zeros(n, dtype=np.float32)     （68 → 36 B/神经元）
_sig_spikes：0/1 掩码 → uint8                      （省 7 B/神经元）
slot_freq：int32 保持
快照：_restore_net 的 gain 统一 astype(float32)——加载后全 f32 域
```

**精度安全性**：物理量（theta=1 阈值、权重 0-16、eta 增量 0.1）在 float32
尾数 23bit（相对精度 1e-7）下完全够用。历史教训（快照 f32 截断对拍
8895 差异边）是"内存 f64 + 快照 f32 混用"导致——**全 f32 统一域无此问题**
（同一快照加载两次行为逐位一致）。旧快照（f64）加载自动转 f32 兼容。

### 3.2 空行共享单例 + 写时复制（大头）

```
稀疏网络绝大多数行是空的（当前 0 边起点）——原实现每神经元一个 EdgeRow
对象（~50B）——改为模块级共享 _EMPTY_ROW 单例：

  W_out 初始化: [[_EMPTY_ROW for _ in range(slots)] for _ in range(n)]

安全机制（关键——防共享污染）:
  读取: 空行只读共享（传播/读出——零风险）
  写入: _row_w(i, k) 写保护——共享行 → 新 EdgeRow 并替换 W_out[i][k]
        引用（写时复制）——所有引擎写入点已打补丁:
        · release_da 资格迹兑现
        · 惩罚路径（_punish_cands LTD）
        · Hebbian/STDP/LTD 的 _apply_edge_updates groups 构建
        · sleep_chunking 组块写边
        · 词表换新模式
  实测验证: 写入行独立（is not _EMPTY_ROW）✓ 未写入行仍共享 ✓
            共享实例恒为空（len=0——无污染）✓
```

## 六、结论

```

  状态数组:  9.2 TB（内存）——单机不可行——8.6 亿缩比 = 92 GB（工作站可试）
```
