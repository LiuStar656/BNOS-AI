# [REPORT] 定式网络并发探针：同时激活 与 最后记忆同时写入（v35 单快照）

> 日期：2026-08-11 | 版本：v1 | 状态：已完成
> 前置：v35 快照（`runs/v35_0_20260811_044836`，n=149312，模式 37144，928,497 边）
> 脚本：`_probe_concurrent_v35.py` | 留档：`runs/_probe_concurrent_v35_20260811_081559/result.json`

## 背景

用户问题（2026-08-11）：
1. 定式网络能不能被**同时激活**？
2. 运行在**不同实例**里，最后的记忆能不能**同时写入**（同一个快照）？

实验全部基于 v35 **这一个快照**（副本进 `base/`，不动 runs/ 主链），
学习组沿用 `_probe_concurrent` 口径（槽位隔离）：A 组「我→吃→苹果」学槽 0、
B 组「他→看→家」学槽 1，各 5 轮。

## 方法（4 个实验）

| # | 实验 | 做法 | 判据 |
|---|---|---|---|
| A1 | 串行基准 | 单实例加载 v35，6 词探针（读边 top-5 + 回响激活集） | 作为 A2/A3 比对基准 |
| A2 | 多进程同时激活 | 3 进程**同时加载同一快照文件**、同时放行回响 | 3 实例输出与基准逐项一致 |
| A3 | 同实例多线程 | 1 个 ng 对象内 3 线程同时激活（各 5 轮） | 与基准一致轮数（共享状态边界） |
| B1 | 同文件并发写 | 2 进程各学一组 → 打包后同时 `savez` 到**同一个** net.npz | 文件能否加载；双方记忆是否都在 |
| B2 | 合并写入 | 2 实例各学一组 → diff（相对 v35 基准）取 max 合并进同一快照 | 双方记忆是否都在同一快照 |

## 结果

### A2 多进程同时激活 —— **互不干扰**

3 进程同时读同一快照文件、同时回响：`proc0/1/2` 输出与基准**逐项完全一致**
（读边 top-5 候选与回响激活神经元集合均相同）。每个实例 = 独立内存副本，
快照文件只读共享 → 同时激活天然安全。

### A3 同实例多线程共享对象 —— **串扰**

3 线程共用同一 ng 对象、各激活 5 轮：一致轮数 `[0, 0, 0]`（全乱）。
根因：`evoke` 路径共享可变状态 `ng.v / ng.spikes / ng.pre_trace`，
线程间互相踩踏（读边 `direct_next_multi` 无状态，不受影响）。
→ **"同时激活"的边界 = 每实例独立加载一份快照；同一对象内并发激活不安全。**

### B1 同文件并发写 —— **静默损坏**

2 进程各学一组后同时写同一 `net.npz`：
- 双方都返回 `write_ok`（**无任何异常**）；
- 最终文件 `BadZipFile: Bad CRC-32 for file 'slot_k.npy'`——`slot_k/dst_j/vals`
  三个条目损坏（两写线程在 zip 内交错覆盖）；
- 网络数据不可恢复，**不是"后写覆盖先写"，而是文件级损坏，双方记忆全丢**。

### B2 合并写入 —— **双方记忆共存（正确做法）**

| 关键边 | 基准 v35 | 合并后 | 神经元级边 |
|---|---|---|---|
| A 我→吃（槽0） | 72.8 | **131.0** | 16 条 |
| A 吃→苹果（槽0） | 33.6 | **90.4** | 16 条 |
| B 他→看（槽1） | 0.0 | **40.0** | 16 条 |
| B 看→家（槽1） | 0.0 | **40.0** | 16 条 |

唤起比例：注入我→吃=1.0、注入他→看=1.0、注入看→家=1.0；
注入吃→苹果=0.0（注意力竞争挤出——`_probe_concurrent` 已证"唤起失败 ≠ 学习失败"，
学习判据以边强度为准，90.4 ≫ 33.6 成立）。

**附加发现（diff 结构）**：双方 diff 各 18,068 条，其中 **17,600 条完全相同**
（值 = 0.1 = eta）。根因：`step()` 噪声发放（noise_p=0.06）+ 共发放 Hebbian 微边，
rng 固定种子 42 + 步数相同 → 噪声序列确定性相同 → 微边逐条相同（确定性底噪）。
双方**独有** 468 条 = 各自教学边（16+16）+ STDP 边——合并取 max 恰好只保留
"真实新增"，噪声微边重复写入无副作用。

## 结论

1. **同时激活：可以**。不同实例（进程）各自加载同一快照后同时回响，输出
   与单实例逐项一致、互不干扰（实例 = 独立内存副本，快照文件只读共享）。
   唯一禁区：**同一实例对象内**多线程并发激活（共享 v/spikes/pre_trace 串扰）。

2. **"最后记忆同时写入"不能直接写同一个文件**：两实例各自学完直接同时
   `savez` 同一路径 → 无异常但静默损坏（BadZipFile，网络不可恢复）。
   正确姿势 = 各实例先学，结束时以**公共基准**（v35）做 diff，取 max 合并进
   单快照——双方教学边共存，且合并只叠加不削减（v35 原有边保留）。

3. **理论印证**：并发实例的确定性（固定种子 rng → 噪声微边逐条相同）使
   diff 合并天然干净——同种子实例的 diff 高度重叠，合并是幂等的。

## 边界与后续

- A2 覆盖 3 进程 × 6 词 × 单轮探针；未覆盖：百级进程、混种异源实例（不同
  种子 rng 的 diff 合并）、写盘与读盘持续交错的长驻进程。
- B2 合并未对 v35 原有行为做全量回归（free_read 12 题等）；合并只加不减
  （max），理论上不破坏既有路径，建议后续沿用 `_eq_check_prune` 口径复核。
- 多实例协作的工程化：建议封装 `merge_snapshots(base, branches, target)`（把
  `_merge_branch.py` 与本次 diff 逻辑合并为一个共享模块），供 live-stream/
  场景类多实例训练统一调用。
