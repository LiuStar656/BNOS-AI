# REPORT：定式网络生成性能与吞吐实测报告（成本模型 + 状态机接话 + 直接读边）

> 日期：2026-08-10 | 状态：[OK] 实测完成 | 类型：性能/机制报告
> 基准：v16.0 快照（n=148848，词表 37117，W_out 1800 万边，EdgeRow 数组存储）
> 实测方法：Python 纯解释执行（CPython 3.x，无 JIT/无向量化优化），单进程
> 背景链：用户"训练速度为什么慢" → "k 一直不变吗？" → "wta_k 保持不变吗？" → "s5 推理能解决长文本吗？" → "长文本生成在哪？" → "一句话生成怎么生成的？" → "每秒多少 token？" → 本报告

## 一、成本模型：E 是主变量，n 是次变量

定式网络每步计算（sparse_net.step 动力学）分三块：

| 操作 | 成本 | 随什么涨 |
|---|---|---|
| 积分/噪声/WTA（全向量） | O(n·slots) | 随 **n** 线性（numpy 向量化，便宜） |
| 传播（W@spikes） | O(发放神经元传出突触和) ≈ O(wta_k × d) | 随 **平均突触密度 d = E/n** 线性 |
| Hebbian/STDP 更新 | O(发放对 + 前驱非零边) | 随 **E** 线性 |

**结论：总突触数 E 决定平均突触密度 d，d 直接乘进传播成本——训练和推理都随 E 线性变慢，n 的影响是次级的（向量操作线性 + 内存线性）。**

**"越喂越慢"机理**：散文全量把 E 从 1800 万推到 4900 万（×2.7）→ d 同步 ×2.7 → 后期每句传播读的行更长。实测：句数 ×2.5，耗时 ×2.9（超线性，即 d 增长的贡献）。

**规模预估**：

| | 现在（v17） | 未来（V≈5.6 万词，v14 边界） |
|---|---|---|
| n | 148,848 | ~90 万 |
| E | 4900 万 | ~1 亿（有效搭配饱和点） |
| d | ~330/神经元 | ~110/神经元（E 受饱和点约束，n 涨得快 → d 反降） |

词表扩大后 d 可能**下降**——规模扩大不一定线性恶化，取决于 E 是否受控（受 sleep_consolidate / edge_min 治理）。

## 二、k 参数分析：固定是"性能预算"设计

两个 k 当前**都是固定常量**：

| 参数 | 值 | 含义 | 变化代价 |
|---|---|---|---|
| K（词模式） | 4 神经元/词（n = V×K） | 词表达的冗余度 | ↑ n/内存线性涨、d 降；↓ 词组装易被噪声破坏 |
| wta_k（WTA 发放） | 16（上限，非固定值） | 每步并发词预算 ≈ 4 词（16/4） | ↑ 传播线性变慢、竞争减弱；↓ 可能截断真后继 |

**wta_k 是上限不是固定发放数**（schema_net.step：`top = candidates 若 ≤wta_k 全发，否则截断前 wta_k`）——**实际发放数 = min(过阈候选数, 16)**，动态变化，但预算参数恒定，无自适应机制。

**设计意图**：传播成本 ∝ wta_k × d，固定 wta_k 把每步计算锁定；并发不足（>4 词同时激活的需求）由**多步传播**补偿（run_experience 的 max_steps / _learn_sentence 逐词注入）——**时间换并行**。生物对应：注意焦点大小固定，焦点随时间扫描。

## 三、生成机制：分句接话 + 状态机 + 直接读边

当前"一句话生成" = 教师给前半句 → 网络用**句式状态机 + 直接读边**逐词接后半：

```
NONE → PRE（读到关系词1）→ POST（读到关系词2）
PRE:  读内容词传出突触 top-1（排除人称/"在"）；top-1 ∈ REL_BACK → 配对约束直读
POST: 读结果主语（排除 V/O）→ 读结果谓语（排除人称/"在"）
底层: direct_next_multi —— srcs 各词传出突触加权汇聚取 top-k，不走全局回响
判定: 角色合法集（REL2 配对约束 / SUBJ 人称 / PRED 动作宾语）
```

关键特征：是"接话"不是自由生成；验收为**目标词推进**（prefix 追加期望词）；状态机是**读取约束**不是新知识；校准（教师批改）兜底。

## 四、吞吐实测（v16.0）

**方法**：加载 v16.0，用 EVAL 的 6 个前半作前缀 ×20 重复，连续续写测吞吐。

| 路径 | 吞吐 | 每词 |
|---|---|---|
| **状态机接话**（clause_next） | **75.4 词/秒**（800 词 / 10.6s） | 13.3ms |
| **纯读边自由续写**（direct_next_multi） | **7.6 词/秒**（2400 词 / 316s） | 132ms |

**反直觉发现**：状态机比纯读边**快 10 倍**。原因：

- 状态机有约束（排除人称/V-O/"在" + 角色推进）→ 读的是低频词（传出突触少）
- 纯读边自由续**滑向高频词**（了/我/想），其传出突触行几千上万条 → `direct_next_multi` 每步全行 tolist + Counter 累加

**对比参照**：

| 引擎 | 速度 |
|---|---|
| 本地 CPU LLM | 5-20 token/s |
| GPU 量化 LLM | 50-200 token/s |
| 定式网络（纯 Python，状态机） | **75 词/秒 ≈ 110+ token/s** |

定式网络**纯 Python、无优化**已达本地 CPU LLM 一两个量级以上——但这不代表"机制快"，而是"每步只读一行边"的结构性优势（LLM 每步自注意力 O(L²)，定式网络每步 O(d)）。

## 五、瓶颈定位与优化空间

**慢点不在机制，在实现**——`direct_next_multi`（_grow_v16.py L118-139）的 Python 逐边遍历：

```
row.items()  → EdgeRow 数组每次 tolist 转换（Python list）
n2w.get(j)   → 每边一次 dict 查找（37 万词映射）
exclude/domain 集合成员检查每边一次
scores[w] += wt → Counter 逐边累加
most_common(k) → 全量排序
```

本质只是"取一行传出突触的 top-k"。**向量化方案**（分配制连续块已确认：allocate_pats 按游标连续分配 k 个神经元，`词 id = dst // K`）：

1. 收集 src 神经元的 (dst, w) 数组（零复制 edge_view）→ np.concatenate
2. `词 id = dst // K` → bincount 按词聚合求和（V 长度向量）
3. 过滤掩码（排除 src 词/exclude/domain，预构建词 id 布尔掩码）
4. `np.argpartition` 取 top-k（stable 排序保证同权重顺序与旧行为一致）

预计吞吐提升 **10-100 倍**（状态机 75 → 千词级/秒）。

**对拍铁律**：改实现必须证等价——新旧 `direct_next_multi` 对若干采样 prefix 输出 (词, 权重) 完全一致（权重 1e-9 容差，同权重按首现序），通过后才可替换。

**其他治理手段（机制已存在）**：edge_min 弱突触修剪（散文 3100 万新边大量 0.1/0.5 弱突触，修剪后传播读行变短 + 降噪）、sleep_consolidate 慢衰减（低频边回收，E 受控）、EdgeRow 数组存储（已落地 12B/边）。

## 六、长文本生成的落点（Stage 4）

**长文本生成不在 s5**——s5 是 12+ 岁抽象推理级（概念/数学）。长文本在 **Stage 4 文章级**（6-12 岁，句接句转移 + 文章骨架 + 句间关系标记，数据 = Wiki 百科 2-5 万句对）。

**结构性优势**：定式网络生成成本随长度**线性**（每步 O(d)）vs LLM 自回归 O(L²)——长文本生成无计算障碍，但 Stage 4 前需先做 §五 的向量化优化（否则长文本 = 每词 13-132ms 的线性积累）。

## 七、结论

1. **速度由 E 决定**：E 增长 → d 增长 → 传播变慢（越喂越慢的超线性来源）；n 影响次级
2. **k 固定 = 性能预算**：K=4 词模式 + wta_k=16 上限，实际发放数动态（min(候选,16)），并发不足由多步传播补偿
3. **实测 75 词/秒（状态机）/ 7.6 词/秒（纯读边）**——纯 Python 已超本地 CPU LLM，瓶颈在 direct_next_multi 的 Python 逐边
4. **向量化是明确的下一步**（10-100 倍 + 对拍等价），是 Stage 4 长文本生成的前置
5. **长文本落点 = Stage 4**（文章级），不是 s5 推理级
