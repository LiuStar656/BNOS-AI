# [REPORT] 定式网络速度优化第七波实验报告（v17 推理榨干：edge_min 扫描 + drive 缓冲复用）

> 日期：2026-08-10 | 状态：[OK] | 版本：接第六波（v13 四步实现优化）之后；按用户要求"用最新快照模型（测试时关闭学习门）榨干推理极限"——v17.0 冻结态全链实测：39.9 → 20.9ms/次（-48%）

## 一、背景与目标

用户："未来会继续喂的，但在现阶段榨干推理的极限，用最新的快照模型（测试的时候要关闭学习门）"。执行：v17.0（4960 万边，v13 的 3.6 倍）冻结态（learn_gate=False）全链实测；配置层（edge_min 扫描）+ 实现层（drive 缓冲复用）双管齐下。

## 二、v17 基线

| 项 | v13.0 | v17.0 |
|---|---|---|
| 边数 | 1392 万 | **4960 万** |
| 唤起（edge_min=0.5 冻结态） | 25.6ms/次 | **39.9ms/次** |

v17 传播边 29.8 万/步（v13 的 ~3 倍）——**传播宽度随知识量增长**，正是"未来继续喂"要面对的核心。

## 三、v17 推理步构成（预热后实测，edge_min=2.0）

| 段 | ms/步 | 占比 |
|---|---|---|
| fire+collect（分桶+行收集+concat） | 2.12 | 46% |
| rng+update_v | 1.23 | 27% |
| wta+topk（候选 8266） | 0.84 | 18% |
| prop（29.8 万边） | 0.43 | 9% |

计时段 4.62ms/步。**fire+collect 是大头**（v17 边多后 concat+收集帧放大）——与 v13 的构成不同（v13 时 collect 仅 0.04ms）。

## 四、edge_min 参数扫描（`runs/_edge_min_scan_v17.json`，934 条强边评估）

| edge_min | 唤起 ms/次 | 强边命中率 |
|---|---|---|
| 0.5（原配置） | 34.9 | 0.072 |
| 1.0 | 27.4 | 0.071 |
| **2.0** | **26.9** | **0.076（最高）** |
| 4.0 | 24.1（最快） | 0.069 |

**v17 结论：edge_min=2.0 是平衡点（-23%，命中率最高）；4.0 最快但命中略降**。新配置推荐 2.0（`_grow_v16.py` 配置块已更新，注明第七波数据）。

## 五、实现优化：drive 缓冲复用（位级一致 ✓）

传播段每槽 `np.zeros(n)` 分配 → 预分配 `self._drive[slots, n]` 缓冲（reset/expand 对齐），每槽清零→累加→`v[:,k]+=`→下槽清零。语义与 np.zeros 完全一致（清零后累加）。

对拍：主对拍 0 差异 + 唤起 44=44（3.4×）；分支对拍 4 组合全 0 差异。

## 七、CPU 极限评估（v17 视角，实测口径）

- **已拿**：edge_min 2.0（-23%）+ drive 复用（-26%）+ 第六波实现优化
- **剩余构成**：fire+collect ~2ms（concat+收集帧——阶段 B：CSR/全融合内核可消 ~1ms）；rng+update_v 1.2ms（rng 流物理必需）；wta+topk 0.8ms（候选治理需机制实验）
- **下一层**：请求级并行（吞吐 ×核数）——"未来继续喂"的高频推理场景建议优先做这个；GPU 属放大路线
