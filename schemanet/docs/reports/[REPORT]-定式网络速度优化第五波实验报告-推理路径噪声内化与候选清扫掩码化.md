# [REPORT] 定式网络速度优化第五波实验报告（推理路径噪声内化与候选清扫掩码化）

> 日期：2026-08-10 | 状态：[OK] | 版本：接第四波（edge_min + 增量快照）之后；推理路径纯实现优化：`_update_v` 噪声内化 + `setdiff1d` 掩码化，全部位级一致

## 一、背景与需求

用户问"推理速度现在有优化空间吗"——对唤起路径（冻结态，edge_min=0.5）逐段计时定位，实施两项零语义风险的实现优化。

## 二、诊断：推理步真实构成（~8.5ms/步，修正后）

| 部件 | ms/步 | 占比 | 备注 |
|---|---|---|---|
| setdiff（侧抑制清扫） | 2.9 | 34% | 候选 16716 放大（默认 inh_loose=1.0 不执行） |
| prop（传播） | 2.0 | 24% | edge_min 已压，剩余宽度 |
| noise 生成 | 1.2 | 14% | numpy 比较+乘两 pass（训练路径已内化，推理路径漏了） |
| wta + topk | 2.0 | 24% | 候选 16716 放大 |
| where/collect | 0.8 | 9% | — |

踩坑记录：初测 update_v 显示 7.2ms/步（占 45%）——**numba 缓存首载混入计时的伪影**（复测 0.08ms，与数据无关）。与第一波 §4.3 同源教训：计时须先预热。

### 2.1 inh_loose 启用验证（候选数治理）——实测否决

候选 16716 的根因是静息过阈累积，假设"启用 inh_loose 清扫"可压候选提速。实测（edge_min=0.5，v13.0 上直接开）：

| inh_loose | 唤起 ms/次 | 强边命中率 |
|---|---|---|
| 1.0（现状，关闭） | **33.2** | 0.107 |
| 0.5 | 45.2 | 0.109 |
| 0.3 | 41.6 | 0.101 |
| 0.1 | 42.2 | 0.107 |

**启用清扫反而慢 10–35%**：候选多时清扫本身（setdiff+乘法）就是成本，且现状直接跳过该段；命中率全程持平（检索不受影响，但提速目标不成立）。**inh_loose 不是推理杠杆**，否决。

## 三、改造清单（sparse_net.py，2026-08-10）

| # | 位置 | 改造 | 语义 |
|---|---|---|---|
| 1 | `_update_v` | 签名 `noise` 数组 → `raw + noise_p + noise_amp`（噪声内化，与 `_train_core` 同款） | `(raw<p)*amp` IEEE 位级一致 |
| 2 | step 推理路径 | 删除 numpy 噪声两 pass，raw 直传内核 | 同上 |
| 3 | step 侧抑制段 | `setdiff1d`（unique+isin）→ 布尔掩码（`mark[top]=True; candidates[~mark[candidates]]`） | 结果集合一致；losers 用于逐元素乘法，顺序无关 → 位级一致 |

分支专项（`_tmp_verify_branches.py`）4 组合全 0 差异——组合 1/3（inh_loose=0.3/0.5 + 唤起传播路径）正好覆盖 setdiff 掩码段与新 `_update_v` 签名。

### 4.2 速度

| 场景 | 优化前 | 优化后 |
|---|---|---|
| 唤起（edge_min=0.5，冻结态） | 33.2ms/次 | **31.0ms/次（-6.6%）** |

收益全部来自 ① 噪声内化（-2.2ms/次）；③ 掩码化默认配置（inh_loose=1.0）不触发——为 v13.2 机制启用时备好（届时候选清扫段从 ~2.9ms → ~0.2ms）。

## 五、推理速度空间结论（实测口径）

| 手段 | 状态 | 收益 |
|---|---|---|
| edge_min（第四波） | ✅ 已启用 | ~2.5× |
| 噪声内化 + setdiff 掩码 | ✅ 本轮 | ~7% |
| inh_loose 清扫 | ❌ 实测否决 | 负收益 |
| 传播全 numba（CSR 索引） | ⏳ 工作量大 | ~15% |
| GPU/批处理 | ⏳ 放大路线 | 数量级（规模放大时） |

**结论：推理的 CPU 空间已接近收完（edge_min 2.5× + 实现优化 ~7%）；下一个数量级在结构/规模侧**（候选数治理需机制实验、传播 CSR 重构、或 GPU/批处理——均属放大路线）。
