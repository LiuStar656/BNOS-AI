## 一、背景与问题

上轮实验验证"表示并发成立"（双槽隔离、零串扰）。本实验追问：**并发量 G 增大到多少会导致崩溃**？

**并发量定义**：同一学习期交替学习的独立词对组数（每组 `_learn_sentence([X,Y])` 10 轮）。
**设计**：G ∈ {1,2,4,8,16,32,64}，每组在干净快照 v13.0 重载（隔离并发量效应）；主实验所有组同槽 slot=0（剥离槽位隔离，测纯并发拥挤）；副实验组 mod 4 轮转 4 槽（模拟多任务）。
**崩溃判据**：唤起成功率 < 50%（定式保真度断崖）或激活规模爆炸（超临界迹象）。
**词对筛选**：随机采样 + 基线唤起 < 0.3（初始不相关，fan-out 小）。

## 三、为什么找不到崩溃（机制分析）

1. **教学式学习 = 干净注入**：`_learn_sentence` 每句前清 v/spikes/pre_trace → 词对间无残留污染 → STDP 只学相邻转移 → **每组边独立建立，互不关联**。并发量只决定"边总数"，不决定"组间耦合"。
2. **选词"初始不相关" = fan-out 小**：唤起阶段 WTA 竞争环境小 → 目标轻松进 top-k。这再次印证注意力理论：**竞争由 fan-out 决定，不由边数决定**。
3. **激活规模恒定 84**：注入普通词后多步传播发放 84 神经元，与 G 无关 → 无超临界迹象（σ 未变化）。

## 四、真正的崩溃维度（本次未触发的变量）

实验表明**"并发量"不是崩溃的主维度**。崩溃边界应在三个其他维度：

| 维度 | 机制 | 预期 |
|---|---|---|
| **A. hub 竞争环境** | 并发组含 fan-out 巨大的词（"我"1.7 万出边）→ 唤起竞争拥挤（上轮已证"我→吃"边存在但被挤出） | G 增大 + hub → 早崩 |
| **B. 传播式学习** | 真实经历（run 模式不清理）→ 共同发放对爆炸 → 超临界雪崩（σ≫1） | 无教学隔离时崩 |
| **C. 长期边密度** | 学习→sleep→学习循环，边密度累积 → σ 上升 | 长期崩，非一次并发崩 |

**推论**：定式网络的并发学习容量极大（≥64 组），"崩溃"不是并发的后果，而是**结构本身（hub 扇出 / 学习模式 / 边密度）**的后果——这与"内存边界 = hub 扇出边界"的结论同构：**瓶颈在结构，不在并发**。

## 五、诚实边界

1. 词对为初始不相关（基线 < 0.3），未含 hub 词——若含 hub 词结果可能不同（维度 A）；
2. 每组 10 轮教学，边增长有限——长期累积效应（维度 C）未测；
3. 轮转 G≥32 出现 0.25 串扰（跨槽传播混合），提示槽位轮转非完全隔离——需溯源（v 跨槽传播）；
4. 实验在内存中修改网络，未覆盖快照。

## 六、结论与后续

1. **教学式并发训练容量 ≥ 64 组，无崩溃**——定式网络并发学习能力远超"4 槽位"直觉（槽位不是并发上限，教学隔离才是隔离机制）；
2. **崩溃边界不在并发量维度**，在 hub 竞争环境 / 传播式学习 / 长期边密度三个维度；
3. 后续：测维度 A（hub 词并发组）、维度 B（传播式经历并发）、维度 C（累积学习曲线）；轮转串扰 0.25 溯源。

## 附：回答"Python 会不会限制度式网络并发"

- **结构性并发**（槽位隔离、边分桶、增量成长）：不受 Python 限制——本实验 64 组并发即实证；
- **执行并行**（多核吞吐）：受 GIL/单核限制——是工程问题，可用多进程（G 点独立并行）、numba/OpenMP（内核分块）解决，与机制无关。
