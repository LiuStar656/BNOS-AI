# 定式网络 Stage 3 v15 实验报告（对话/回答读取机制：direct_next 直接边接话 + 域内过滤 + 训练平衡）

> 日期：2026-08-10 | 状态：[OK] | 版本：成长路线 §2.6 复杂句单元落地"对话即学习"（铁律 6）的读取侧实现（快照 v14.0 → **v15.0**，全量验收 384s 通过）

## 一、背景与需求

前置探测（`20260810_115157_probe_s3`，v14.0 上实测）暴露核心矛盾：

- **续推侧读取失败**：走全局回响/涟漪/WTA 续推时，虚词枢纽（的/了/是/你 等）连接数量爆炸，**前缀续推 0%**——因为/虽然/先 的定式词读不出来；
- **方案 A 已验证**：直接传出突触读取（`next_words_direct`：读词直接传出突触、不走全局回响）**9/10** 命中——"答案"本来就存在网络边里，只是续推读取机制读不出来。

v15 = 把方案 A 固化落地为**对话/回答读取机制**，并通过训练平衡解决真实语料边强度碾压专门定式边的问题。这是"对话即学习"（铁律 6）落地段的关键一步：网络终于**"会说话"**（读得传出突触、接得上话）。

验收链：直接传出突触问答 ≥0.9、前缀接话 ≥0.7、对话轮次一致率 ≥0.8、链式接话每步 ∈ 合法后继集、继承 v14 全量验收零遗忘。

## 二、方案设计

### 2.1 直接传出突触读取 `direct_next`（方案 A 固化）

读词直接传出突触：`ng.W_out[i][0]` 稀疏边汇聚到目标词取 top-k。**不走全局回响/涟漪/WTA**——把"答案"当网络里的边直接读：

```python
def direct_next(ng, pats, n2w, src, k=6, domain=None):
    scores = Counter()
    for i in pats.get(src, []):
        row = ng.W_out[i][0]
        if row:
            for j, wt in row.items():
                w = n2w.get(j)
                if not w or w == src: continue
                if domain and w not in domain: continue
                scores[w] += wt
    return scores.most_common(k)
```

### 2.2 域内过滤（domain）

只保留**对话域词表**（S/V/O + 关系词 + 关系句内容词，61 词），排除虚词枢纽（的/了/是/你 等）与域外词——虚词枢纽连接数量爆炸是续推 0% 的根因，域内过滤直接消除。

### 2.3 前缀接话 `prefix_next`（多词前缀 → 会话感知）

真实对话 = 词级输入。两条读取路径：

1. **配对直读**：关系词位于**倒数第二位**且配对边存在 → 直读配对词（因为→所以 / 虽然→但是 / 先→然后）。解决"对称竞争"（下雨→所以 40 vs 下雨→但是 24，训练平衡后压倒）：关系词在上文出现时，配对词是**唯一合法后续**，不走内容词竞争。
2. **最后词传出突触**：否则取前缀最后词直接传出突触（域内过滤）。

```python
def prefix_next(ng, pats, n2w, prefix, k=6, domain=None):
    if len(prefix) >= 2 and prefix[-2] in REL_NEXT:
        rel = prefix[-2]; nxt = REL_NEXT[rel]
        w = edge_between(ng, pats, rel, nxt)
        if w > 0.1: return [(nxt, w)]
    return direct_next(ng, pats, n2w, prefix[-1], k=k, domain=domain)
```

### 2.4 训练平衡（方案 D：真实语料边 vs 专门定式边）

实测暴露：真实语料边强度碾压专门固化边——

| 边 | 来源 | 强度 |
|---|---|---|
| 想要→你 / 想要→的 | 真实语料 | 19.2 / 38.4 |
| 想要→苹果 | v13 固化 | ≤2.5 |
| 在→你 | 真实语料 | 206.0 |
| 在→看 | v13 固化 | 8.0 |

专门定式边被真实语料边淹没 → 直接传出突触读不出。落地 **R_BIAS=2 加权跟读 + B 型自适应加权**：

```python
balance_seqs = [["我", "想要", "苹果"], ["我", "在", "吃"], ["下雨", "所以"]]
for seq in balance_seqs + [["想要", "苹果"]]:
    for _ in range(R_BIAS): _learn_sentence(ng, seq, pats, slot=0)
n_b = 0
while edge_between(ng, pats, "在", "看") < edge_between(ng, pats, "在", "你"):
    _learn_sentence(ng, ["他", "在", "看"], pats, slot=0); n_b += 1
    if n_b > 80: break
```

实测：在→看 8.0 → **208.0**（26 轮），在→你 206.4——专门定式边反超真实语料边。

### 2.5 对话练习（教师说 → 网络接 → 判定 → 修正）

对话轮次机制（铁律 6 落地）：教师说 → 网络 `direct_next` 接话 → 判定（top-1 ∈ 预期候选）→ 修正。13 轮练习脚本，5 话题（因果 3 + 顺序 3 + 转折 3 + 想要 2 + 动宾 2）。

- **开放续推的预期候选 = 全部已学合法传出突触**（避免把合法词误当错词）；
- **修正（保守版，不删边）**：一致不动；读不出或读错 → 固化预期边 ×3（`_learn_sentence(teacher + [expect[0]])`）。不删边避免破坏合法对称边（如下雨→但是，删了会伤"虽然下雨但是跑步"）。

### 2.6 链式接话验收（对话生成）

从起始词逐词生成整句（会话感知 prefix_next），**每步 ∈ 该步合法后继集**（所以→带伞/吃饭 同为合法，不作精确句匹配）。

## 四、关键发现

1. **读取机制与记忆机制是两回事**：网络"记住了"（边都在）但"不会说话"（续推读不出）——v15 证明**读取 = 显式的直接传出突触读取 + 域内过滤**，不走全局回响。方案 A 从探测 9/10 升级到落地 10/10。
2. **训练平衡解决"语料边碾压定式边"**：真实语料是海量共现（在→你 206），专门固化边只有几次教学（在→看 8）——不平衡时直接传出突触被淹没。自适应加权（`while 在→看 < 在→你`）让专门定式边反超（208.0 vs 206.4），**用同一套学习机制、不改权重语义**。
3. **关系词配对直读 = 对话上下文感知**：内容词双传出突触对称竞争（下雨→所以/但是 同量级）无法靠强度裁决 → 关系词位于上文倒数第二位时**配对词是唯一合法后续**（因为…所以、先…然后、虽然…但是），直读配对词规避竞争。这是 v15 对话机制区别于单步问答的关键。
4. **修正保守化（不删边）**：v13/v14 删边惩罚会破坏合法对称边（删 下雨→但是 伤 虽然下雨但是跑步）——v15 修正只**固化预期边 ×3**，语义错位交给验证门/LLM 讲评，网络只管读得出来。
5. **读取验收口径 = 合法后继集而非精确句**：所以→带伞/吃饭/看医生/睡觉/穿衣服 都是合法答案，精确句匹配会把合法接话误判为错——对话是"选合法后续"，不是"背课文"。

## 五、诚实边界

- 域内过滤是**人工划定的对话域词表**（61 词）——域外词仍读不出（域外词由 Stage 4 文章单元承接）；
- 配对直读表 REL_NEXT = {因为→所以, 虽然→但是, 先→然后} 是**人工编码的关系词配对常识**（与 v14 训练数据同源），不是网络学来的；
- 开放续推的"预期候选 = 全部已学合法传出突触"：网络接话只保证"合法"，不保证"最合理"（合理性的语义判断由 LLM 教师兜底）；
- 对话练习全部命中 → 修正路径（固化 ×3）**未在实测中触发**，其收敛性待错例时验证；
- 链式接话的"每步 ∈ 合法后继集"口径宽于精确句匹配——网络能顺出合法句，不能复述特定句。
