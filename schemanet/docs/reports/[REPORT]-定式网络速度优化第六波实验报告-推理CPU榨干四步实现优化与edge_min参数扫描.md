## 四、edge_min 参数扫描（`runs/_edge_min_scan.json`）

| edge_min | 唤起 ms/次 | 强边命中率 |
|---|---|---|
| 0.0（全量） | 34.0 | 0.091 |
| 0.5（当前配置） | 25.7 | 0.109 |
| 1.0 | 26.3 | 0.091 |
| 2.0 | 22.9 | 0.103 |
| **4.0** | **21.8** | **0.117（最高）** |

**结论：edge_min 越高越快且命中率不降反升**（4.0 时速度 -36%、命中 +29% vs 全量）——弱边全剪后强定式检索更纯。建议新版本配置 edge_min=2.0（保守）或 4.0（激进，实测最优）。

## 五、推理 CPU 极限评估（实测口径）

```
基线（第五波后）  35.2ms/次 → 第六波后 25.6ms/次（-27%）
edge_min=4.0 后   21.8ms/次（再 -15%）
```

- **已拿**：edge_min（2.5×）+ 六波实现优化（累计 -27%）+ 参数扫描（4.0 再 -15%）
- **剩余**：未计时 Python 杂项 ~3.3ms/步（阶段 B：CSR 全局索引 + 全融合推理内核，预估 -40%，工作量大）；prop 串行累加（位级一致锁死，~2ms）
- **终极**：请求级并行（吞吐 ×核数）与 GPU（放大路线）
