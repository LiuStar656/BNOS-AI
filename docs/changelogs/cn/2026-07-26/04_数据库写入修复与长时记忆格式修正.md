# 04 — 数据库写入修复与长时记忆格式修正

> 日期：2026-07-26 | 涉及文件：4 | 变更类型：Bug 修复

---

## 一、问题描述

多个数据库表（`feelings`、`self_cognition`、`other_cognition`、`user_facts`）存在写入失败的问题——GUI 数据浏览中某些表格看不到最新数据。同时 TTS 会将情绪标签（如 `<惊讶>`）读出来，长期记忆仅存储用户输入，缺乏 AI 回复上下文。

## 二、根因分析

1. **_dedup_and_merge 列名硬编码**：函数写死 `SELECT content FROM [{table}]`，但 `event_summary` 表用 `summary` 列名，导致 `sqlite3.OperationalError: no such column: content` 被静默捕获
2. **TTS 情绪标签正则不匹配**：LLM 输出使用尖括号（`<惊讶>`），但 TTS 正则匹配方括号（`[惊讶]`）
3. **长期记忆仅存用户输入**：`_write` 方法只写入用户输入的 `content` 到 `long_term_memory`，没有 AI 回复

## 三、修改方案

### 3.1 _dedup_and_merge 列名修复 (db.py)

```python
def _dedup_and_merge(
    table: str,
    conv_id: str,
    new_content: str,
    conn: sqlite3.Connection,
    importance: int = 3,
    column: str = "content",  # 新增参数，默认 content
) -> str | None:
    old = conn.execute(
        f"SELECT [{column}] FROM [{table}] WHERE conversation_id=? ORDER BY id DESC LIMIT 1",
        (conv_id,),
    ).fetchone()
```

调用时传参：
```python
# event_summary 使用 summary 列
_dedup_and_merge("event_summary", conv_id, val, conn, column="summary")
```

### 3.2 TTS 正则修复 (main.py)

```python
# 修复前
m = re.match(r"^\[([\u4e00-\u9fff]{2,4})]", text)
return re.sub(r"^\[[\u4e00-\u9fff]{2,4}]", "", text).strip()

# 修复后
m = re.match(r"^<([\u4e00-\u9fff]{2,4})>", text)
return re.sub(r"^<[\u4e00-\u9fff]{2,4}>", "", text).strip()
```

### 3.3 长期记忆格式修正 (db.py)

# 合并用户输入 + AI 回复写入 long_term_memory（供 MemOS 语义检索）
