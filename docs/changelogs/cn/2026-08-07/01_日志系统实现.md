# 01 — 日志系统实现

> 日期：2026-08-07 | 涉及文件：7 | 变更类型：基础设施新增

---

## 一、问题描述

BNOS AI 项目缺少统一的日志系统，存在以下痛点：

1. **GUI 日志无持久化**：仅有 `print()` 输出到控制台，关闭窗口后日志丢失，无法回溯问题
2. **引擎日志无法排查**：`engine.py` 的 `_p()` 方法仅 `print()`，引擎崩溃或启动失败后无历史记录
3. **节点日志完全丢弃**：`standalone_runner.py` 中节点子进程的 `stdout` 和 `stderr` 被设为 `DEVNULL`，节点内部报错（如 Python traceback、JS 异常）完全丢失
4. **无批次隔离**：无法区分不同启动会话的日志，多次启动后日志混在一起难以排查

## 二、根因分析

1. **GUI 层**：没有配置 Python `logging` 模块的文件 handler，所有日志只走 stdout
2. **引擎层**：`_p()` 方法仅封装 `print()`，没有写入文件的通道
3. **节点层**：`standalone_runner.py` 的 `start()` 方法使用 `stdout=DEVNULL, stderr=DEVNULL` 丢弃节点输出。当初为了避免节点日志刷屏控制台而牺牲了可观测性
4. **架构缺失**：没有"启动批次"概念——每次 GUI 启动应该创建独立的日志目录，与生命周期绑定

## 三、修改方案

### 3.1 整体架构

```
┌──────────────────────────────────────────────┐
│  GUI 进程                                    │
│  ┌────────────────────────────────────────┐  │
│  │ gui/core/logger.py (新建)              │  │
│  │  ├─ 启动时创建批次目录                 │  │
│  │  ├─ app.log (INFO+)                    │  │
│  │  ├─ error.log (ERROR+)                │  │
│  │  └─ sys.excepthook → error.log        │  │
│  └────────────────────────────────────────┘  │
│         │                                    │
│         │ subprocess.Popen + --log-dir      │
│         ▼                                    │
│  ┌────────────────────────────────────────┐  │
│  │ bnos_runtime (修改)                     │  │
│  │  ├─ engine.log  ← _p() 写入            │  │
│  │  ├─ nodes/{node_id}.log ← 节点子进程   │  │
│  │  └─ engine_pipe.log ← 管道输出         │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

### 3.2 目录结构

```
logs/
  └── 20250807_143052/              ← 启动批次
      ├── app.log                   ← GUI 运行日志
      ├── error.log                 ← GUI 错误日志
      └── engine/
          ├── engine.log            ← 引擎日志 (_p 写入)
          ├── engine_pipe.log       ← 引擎 stdout 管道

              ├── node_chat.log     ← 节点子进程日志
              └── ...
```

### 3.3 GUI 日志系统 (gui/core/logger.py)

新建 `gui/core/logger.py`，职责：
- `setup_gui_logger()`：创建批次目录，配置双文件 handler（app.log + error.log）+ 控制台 handler
- `get_logger(name)`：获取模块级 logger
- `get_batch_dir()`：获取当前批次目录
- `sys.excepthook`：未捕获异常写入 error.log

```python
# 使用示例
from gui.core.logger import get_logger
_log = get_logger("knowledge_graph")
_log.info("图谱加载完成，共 %d 个节点", n)
_log.error("节点绘制失败: %s", e)
```

### 3.4 引擎日志 (bnos_runtime/engine.py)

`PipelineRunner` 增加可选 `log_dir` 参数：

```python
# 修改前
def __init__(self, pipeline_path: Path):
    ...
def _p(self, *args, **kwargs):
    print(*args, **kwargs, flush=True)

# 修改后
def __init__(self, pipeline_path: Path, log_dir: Path | None = None):
    ...
    self._log_fh = open(log_dir / "engine.log", "a") if log_dir else None
def _p(self, *args, **kwargs):
    print(*args, **kwargs, flush=True)
    if self._log_fh:
        print(*args, **kwargs, flush=True, file=self._log_fh)
```

同时支持 CLI 参数 `--log-dir`：
```bash
python -m bnos_runtime.engine pipeline.json --serve --log-dir ./logs/20250807/engine
```

### 3.5 节点日志 (bnos_runtime/standalone_runner.py)

`start()` 方法增加可选 `log_dir` 参数，节点子进程的 `stdout`/`stderr` 从 `DEVNULL` 改为写入日志文件：

```python
# 修改前
def start(self) -> tuple[str, subprocess.Popen]:
    proc = subprocess.Popen(
        [str(python_exe), entry],
        stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL,
        ...
    )

# 修改后
def start(self, log_dir: Path | None = None) -> tuple[str, subprocess.Popen]:
    log_fh = None
    if log_dir:
        node_log = Path(log_dir) / "nodes" / f"{self.node_id}.log"
        log_fh = open(node_log, "a", encoding="utf-8")
    proc = subprocess.Popen(
        [str(python_exe), entry],
        stdout=log_fh if log_fh else subprocess.DEVNULL,
        stderr=log_fh if log_fh else subprocess.DEVNULL,
        ...
    )
```

**向后兼容**：`log_dir=None` 时行为不变（DEVNULL 或继承父进程）

### 3.6 接入点 (gui/main.py)

```python
def main():
    # 初始化日志系统
    from gui.core.logger import setup_gui_logger, get_logger
    _batch_dir = setup_gui_logger()
    _log = get_logger("main")
    _log.info("BNOS AI 启动 — 批次目录: %s", _batch_dir)

    # 启动引擎时传递批次日志目录
    _engine_log_dir = _batch_dir / "engine"
    _start_engine(log_dir=_engine_log_dir)
```

## 五、风险评估

| 风险 | 概率 | 影响 | 缓解措施 |
|------|------|------|----------|
| 日志文件磁盘占用 | 低 | 中 | 可定期清理旧批次 |
| 节点日志文件句柄泄漏 | 低 | 中 | log_fh 随子进程关闭自动释放（子进程退出时 OS 关闭文件描述符） |
| 引擎日志文件写入阻塞 | 极低 | 低 | 使用 `flush=True` + Python 文件缓冲，不会阻塞 |
| BNOS 编辑器同步问题 | 低 | 低 | `log_dir` 为可选参数，不传时行为完全不变 |

## 六、影响范围

| 模块 | 影响 |
|------|------|
| gui/core/logger.py | 新建，不影响现有代码 |
| gui/main.py | 启动流程增加日志初始化 |
| gui/pages/node_page.py | 引擎输出管道增加文件写入 |
| bnos_runtime/standalone_runner.py | `start()` 方法签名变化（增加可选参数，向后兼容） |
| bnos_runtime/engine.py | `PipelineRunner` 构造函数变化（增加可选参数，向后兼容）；新增 `--log-dir` CLI 参数 |
| BNOS 编辑器 | 同步时传 `log_dir=None`，行为完全不变 |

## 七、验证方法

1. 启动 GUI → 检查 `logs/` 目录下是否创建了批次目录
2. 检查 `app.log` 是否包含启动日志
3. 检查 `error.log` 是否为空（正常情况）
4. 检查 `engine/engine.log` 是否包含引擎启动信息
5. 检查 `engine/nodes/` 下是否创建了各节点的日志文件
6. 触发异常 → 检查 `error.log` 是否捕获到异常堆栈
7. 重启 GUI → 检查是否创建了新的批次目录，旧目录内容保留
