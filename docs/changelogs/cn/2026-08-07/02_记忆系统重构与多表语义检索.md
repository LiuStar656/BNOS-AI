# 02 — 记忆系统重构：新增日记表与多表语义检索

> 日期：2026-08-07 | 涉及文件：10 | 变更类型：架构重构
>
> 提交：`f116292` refactor: 重构记忆系统，新增日记表与多表语义检索

---

## 一、问题描述

AAA 认知节点的记忆系统存在以下问题：

1. **日记数据混存**：日记被写入 `event_summary` 表，靠 `[diary 日期]` 前缀标记区分，导致事件摘要与日记数据混杂，无法独立查询、统计和检索
2. **检索覆盖单一**：MemOS 语义检索只索引 `long_term_memory` 一张表，对话原文（`user_messages`）和日记（`diaries`）无法参与回忆，记忆召回不完整
3. **确认次数噪音**：prompt 中展示「自我/他人认知」的确认次数（`certainty_*`），对 LLM 决策无实际帮助且引入冗余字段
4. **图谱索引无法增量更新**：知识图谱每次全量重建，数据量大时耗时；节点坐标缺失，GUI 只能自行布局，且连边数量不可配置

## 二、根因分析

1. 日记功能最初以「带标记的事件摘要」形式实现，属于临时方案，没有为日记建立独立的数据模型
2. MemOS 索引仅维护 `(entry_ids, identity_keys)` 两个数组，缺乏「来源表」维度，无法区分条目属于哪张表
3. `certainty` 字段是早期为评估认知可信度而设计，但实际未参与任何决策逻辑
4. 图谱导出只输出 `entries + edges`，未保留向量降维坐标与全部相似度对，GUI 侧无法复现布局

## 三、修改方案

### 3.1 新增 diaries 表（db.py）

`ensure()` 建表逻辑新增 `diaries` 表，与 `event_summary` 彻底分离：

```sql
CREATE TABLE IF NOT EXISTS diaries(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    conversation_id TEXT NOT NULL DEFAULT 'default',
    date TEXT NOT NULL,
    content TEXT NOT NULL,
    mood TEXT,
    created_at TEXT NOT NULL DEFAULT(datetime('now','localtime')),
    identity_key TEXT NOT NULL DEFAULT 'gui:default');
```

### 3.2 日记检测与写入重构（diary.py / main.py）

- `diary._diary_exists`：从「在 `event_summary` 中 LIKE `%[diary date]%`」改为直接查 `diaries WHERE date=?`
- `main._on_diary_response`：从「写 `event_summary`（带标记、截断 500 字）」改为「INSERT `diaries`（content 上限提升到 2000，含 mood）」

### 3.3 移除确认次数逻辑（db.py / main.py / prompt.py）

- `self_cognition`、`other_cognition` 写入不再做去重合并，改为直接 INSERT（与 adaptive-agent-architecture 策略一致），保留 `_increment_certainty`
- `_gather_context` 移除 `self_certainty` / `other_certainty` 查询
- `prompt.py` 移除 `[确认次数: {self_certainty}]` / `[确认次数: {other_certainty}]` 占位符

### 3.4 MemOS 多表语义检索（memos.py）

索引增加「来源表」维度：

```python
_entry_tables = []   # list[str]: 条目来源表名
```

- `rebuild_index` 从 **long_term_memory / user_messages / diaries** 三张表收集条目（去重 `(table, id)`）
  - `user_messages` 以 `[role] content` 形式入索引
  - `diaries` 以 `[diary] content (心情: mood)` 形式入索引
- `retrieve` / `retrieve_raw` 返回条目所属 `table`，按表回查原文：
  - `user_messages` → 附带 `_fetch_feeling` 查询到的「当时心情」
  - `diaries` → 附带日期与心情
  - `long_term_memory` → 附带创建日期
- 结果统一格式 `[日期 | 相似度] 内容`，便于 prompt 注入
- `main.py`、`listener.py` 中按 `r.get("table")` 动态拼接表名回查（`SELECT content FROM [{tbl}] WHERE id=?`）

### 3.5 MemOS 索引系统健壮性（memos.py）

- `_get_model(timeout)` 支持超时控制：`timeout=0` 非阻塞快查（模型未就绪返回 None），避免阻塞推理链路
- 索引文件新增 `entry_tables` 字段；加载时兼容旧索引（无该字段则默认全部为 `long_term_memory`）
- `_encode` / `retrieve` 在模型未就绪时返回 None / 空结果，不再抛异常

### 3.6 记忆图谱 PCA 可视化与可配置边规则（memos.py）

- 图谱索引格式版本化（`GRAPH_INDEX_VERSION = 2`），版本不匹配触发全量重建
- `rebuild_knowledge_index` 支持**增量更新**：先 `_load_knowledge_index` 缓存，仅编码新条目；新增 `force_full` 强制全量参数
- 新增 `_compute_2d_coordinates`：SVD/PCA 将高维向量降维到 2D，归一化到 1500×1200 画布坐标，随 `entries` 导出 `x/y`
- 边生成规则可配置：`max_edges_per_node`（1–20，默认 5）、`threshold`（默认 0.6）
- 导出内容扩展：`all_pairs`（全部相似度对，供 GUI 力引擎）、`sim_matrix`、`meta`（节点/边统计、布局、时间戳）
- 新增 `recompute_graph_edges`：仅按新 `max_edges` 重算边与坐标，**不重新编码向量**，供 GUI 调整参数时快速刷新

### 3.7 其他优化

- `history_summary` 事件摘要增加创建日期前缀 `[YYYY-MM-DD]`（main.py）
- `db_command clear` 排除 `sqlite_%` 系统表，只清用户表（main.py）
- 更新 4 个示例输出文件：`output_default.json` / `output_logseq.json` / `output_prompt.json` / `output_reply.json`

## 五、验证方法

1. 首次对话触发日记写入，确认 `diaries` 表出现记录且 `event_summary` 不再混入日记
2. 次日首条对话触发 `_diary_exists` 查询，确认不会重复写同一天日记
3. 对话中包含历史关键词，确认 `retrieve` 能从 `user_messages` / `diaries` 召回并附「当时心情」
4. 运行 `rebuild_knowledge_index`，确认 `knowledge_graph.json` 含 `x/y` 坐标、`all_pairs`、`meta`；再次运行命中缓存（无新条目时跳过）
5. 调用 `recompute_graph_edges` 调整 `max_edges_per_node`，确认不重新编码即可更新图谱
6. 检查 prompt 输出，确认无「确认次数」字样；`db_command clear` 后系统表（sqlite_sequence 等）仍存在
