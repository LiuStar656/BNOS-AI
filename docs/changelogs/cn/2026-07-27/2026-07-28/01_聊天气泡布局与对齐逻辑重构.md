# 01 — 聊天气泡布局与对齐逻辑重构

> 日期：2026-07-28 | 涉及文件：5 | 变更类型：UI 重构

---

## 一、问题描述

聊天气泡界面存在多个视觉和功能问题：

1. **气泡尾部留白**：使用 `doc.size().width()` 计算气泡宽度时，返回的是文档布局宽度而非实际内容宽度，导致气泡右侧出现多余空白区域
2. **对齐混乱**：ChatBubble 内部使用 `QSpacerItem` 控制左右对齐，与外层 `msg_layout` 的布局管理冲突，导致部分场景下用户/AI 气泡对齐方向不正确
3. **流式追加宽度异常**：旧逻辑采用"只增不减"的宽度策略，流式输出时当较长文本被更短文本替换后，气泡宽度不会收缩
4. **Live2D JS 控制台乱码**：JS `console.log` 输出包含不可编码字符时，`print()` 直接抛出 UnicodeEncodeError，导致控制台输出丢失
5. **知识库面板分类不完整**：数据库表标签缺少"日记"分类，且 `self_cognition` / `other_cognition` 表返回全部 200 条记录，信息过载

## 二、根因分析

1. **QTextDocument 宽度测量缺陷**：`doc.size().width()` 返回的是 QTextDocument 的 layout width（即 `textWidth`），而非实际文本内容的像素宽度。该值默认为 `QTextBrowser` 控件宽度，导致气泡宽度总是等于控件宽度，而非文本内容宽度。

2. **Spacer 与外层 Layout 冲突**：ChatBubble 内部用 `QSpacerItem` + `QHBoxLayout` 推挤气泡实现左/右对齐，但外层 `chat_page.py` 的 `_msg_layout` 同样设置了 `setAlignment`。两层对齐逻辑叠加，导致某些嵌套布局中对齐失效。

3. **宽度只增不减导致过度占用**：`_calc_content_width()` 使用类属性 `_current_width` 缓存最大值，流式追加时即使新内容更短也不会收缩，长期运行后所有气泡均膨胀到最大宽度。

4. **JS 输出编码未处理**：Live2D 页面的 `_on_js_console` 直接 `print(msg)`，当 `msg` 包含当前控制台编码无法表示的字符时（如某些 CJK 扩展区字符），Python 默认编码器抛出异常。

## 三、修改方案

### 3.1 聊天气泡尺寸计算（chat_bubble.py）

将宽度测量方式从 `doc.size().width()` 改为 `QFontMetrics` 逐行测量，气泡紧贴文本内容并限制最大宽度：

```python
# 修复前：使用 doc.size().width() 测量宽度
def _adjust_size(self, update_width: bool = True):
    doc = self._browser.document()
    height = int(doc.size().height()) + 28
    self._browser.setFixedHeight(max(height, 10))
    if update_width:
        self._current_width = self._calc_content_width()
        self._browser.setFixedWidth(self._current_width)

def _calc_content_width(self) -> int:
    font = QFont("Segoe UI", 14)
    fm = QFontMetrics(font)
    padding_h = 36
    max_line_w = 0
    for line in self._text.split("\n"):
        if line:
            w = fm.horizontalAdvance(line)
            if w > max_line_w:
                max_line_w = w
    pw = max_line_w + padding_h
    min_w = int(fm.averageCharWidth()) + padding_h
    w = max(pw, min_w)
    if w > self._current_width:
        self._current_width = w
    return min(self._current_width, self._max_width)

# 修复后：使用 self._browser.fontMetrics() 逐行测量
def _adjust_size(self, update_width: bool = True):
    doc = self._browser.document()
    height = int(doc.size().height()) + 28
    self._browser.setFixedHeight(max(height, 10))
    if update_width:
        fm = self._browser.fontMetrics()
        padding_h = 36
        max_line_w = 0
        for line in self._text.split("\n"):
            w = fm.horizontalAdvance(line)
            if w > max_line_w:
                max_line_w = w
        width = max_line_w + padding_h
        min_width = fm.averageCharWidth() * 3 + padding_h
        width = max(width, min_width)
        width = min(width, self._max_width)
        self._browser.setFixedWidth(width)
```

关键差异：
- `doc.size().width()` → `fm.horizontalAdvance()` 逐行测量真实文本像素宽度
- 移除 `_current_width` 类变量和"只增不减"逻辑，流式追加时宽度随内容自动重算
- `QSizePolicy.Expanding` → `QSizePolicy.Maximum`，避免气泡抢占多余空间
- `_on_doc_resized` 不再只更新高度，改为调用 `_adjust_size(update_width=True)` 同时更新宽高
- 设置 `doc.setTextWidth(self._max_width)` 确保文本达到最大宽度时自动换行

### 3.2 对齐逻辑外移（chat_bubble.py + chat_page.py）

移除 ChatBubble 内部的 QSpacerItem 对齐控制，改为由外层的 `_msg_layout.setAlignment()` 统一处理：

```python
# chat_bubble.py — 修复前：内部用 spacer 控制对齐
if role == "user":
    layout.addItem(QSpacerItem(0, 0, QSizePolicy.Expanding, QSizePolicy.Minimum))
    layout.addWidget(self._browser)
else:
    layout.addWidget(self._browser)
    layout.addItem(QSpacerItem(0, 0, QSizePolicy.Expanding, QSizePolicy.Minimum))

# chat_bubble.py — 修复后：移除 spacer，对齐全由外层控制
layout.addWidget(self._browser)
```

```python
# chat_page.py — 新增：气泡添加到布局时设置对齐
count = self._msg_layout.count()
self._msg_layout.insertWidget(count - 1, bubble)
# 设置对齐：用户右对齐，AI左对齐
alignment = Qt.AlignmentFlag.AlignRight if role == "user" else Qt.AlignmentFlag.AlignLeft
self._msg_layout.setAlignment(bubble, alignment)
```

### 3.3 Live2D JS 控制台编码修复（live2d_page.py）

```python
# 修复前
print(f"[JS-{levels.get(level, str(level))}] {msg} ({src}:{line})")

# 修复后
import sys
line_content = f"[JS-{levels.get(level, str(level))}] {msg} ({src}:{line})"
print(line_content.encode(sys.stdout.encoding, errors="replace").decode(sys.stdout.encoding, errors="replace"))
```

使用 `errors="replace"` 将不可编码字符替换为 `?`，避免 UnicodeEncodeError。
