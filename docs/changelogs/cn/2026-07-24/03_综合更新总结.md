## 一、BNOS Runtime 引擎重构

### 引擎核心 (`bnos_runtime/engine.py`)

- **启动流程重写**：支持按依赖顺序启动节点（先启动 `aaa_cognition`、`llm_infer` 等核心节点，再启动扩展节点）
- **引擎状态管理**：新增完整的状态机（`idle` → `starting` → `running` → `stopping` → `idle`），状态写入 `bnos_status.json`
- **进程管理**：改用 `subprocess.Popen` 直接管理子进程，支持 `stdout`/`stderr` 捕获和日志重定向
- **错误处理**：节点启动失败时自动重试 3 次，超时 30 秒标记为 crashed

### 新增：节点监控器 (`bnos_runtime/node_monitor.py`)

- 独立线程每 2 秒轮询所有节点进程状态
- 写入 `bnos_status.json`，包含每个节点的 `pid`、`status`（running/crashed/stopped）、`cpu_percent`、`memory_mb`
- 支持引擎状态新鲜度检测（超过 15 秒无更新标记为 stale）

### 新增：进程终止器 (`bnos_runtime/process_killer.py`)

- 跨平台进程树终止（Windows 用 `taskkill /T /F`，Linux/macOS 用 `SIGKILL`）
- 避免孤儿进程残留

### 管线加载器 (`bnos_runtime/pipeline_loader.py`)

- 支持从 `pipeline.json` 加载节点依赖顺序
- 自动注入 `listen_upper_file`、`port_mappings`、`out_connections` 到节点配置
- 支持 Python 节点的 `pyvenv.cfg` 自愈逻辑

### venv 解析器 (`bnos_runtime/venv_resolver.py`)

- 自动检测节点目录下是否存在 `venv/`
- 如果有 `venv/`，使用 venv 内的 Python 解释器；否则使用系统 Python
- 支持 `pyvenv.cfg` 文件自检和自动修复

### 新增：状态文件 (`bnos_status.json`)

- 引擎状态、节点列表、启动时间的统一状态源
- 由 `engine.py` + `node_monitor.py` 共同维护
- GUI 的 `NodePage` 和 `StatusBar` 均从此文件读取状态

## 二、GUI 客户端全面重建

### 主入口重构 (`gui/main.py`)

- 布局调整：侧边栏 + 堆叠页面容器
- 集成 `AppState` 全局状态管理器，页面间状态同步
- 窗口关闭时写入 `session_end.signal`（预留会话结束标记）

### 聊天页面重构 (`gui/pages/chat_page.py`)

- **聊天气泡重构** (`gui/widgets/chat_bubble.py`)：
  - 气泡宽度根据字符数自适应（`QSizePolicy.Maximum`）

  - 用户消息靠右（绿色背景），AI 消息靠左（白色背景）
- **输入区域改进**：支持 Shift+Enter 换行、Enter 发送

### 节点管理页面重写 (`gui/pages/node_page.py`)

- **引擎状态栏**：显示 ● online / ● starting / ○ offline / ● error
- **启停按钮**：支持一键启动/停止 BNOS Runtime 引擎

### 设置页面重写 (`gui/pages/settings_page.py`)

- **通用设置**：主题色（新增颜色选择器组件）、窗口透明度
- **节点配置**：`QTreeWidget` 显示所有节点的可配置参数，支持编辑和重置

- 支持运行时动态切换主题色

### 侧边栏重构 (`gui/widgets/sidebar.py`)

- 图标文字对齐：Unicode 图标 + 标签文字水平排列
- 新增：选中态高亮背景色
- 点击事件改为 `QButtonGroup` 管理，避免信号嵌套

### 状态栏重构 (`gui/widgets/status_bar.py`)

- 实时显示引擎状态（● online / ○ offline）
- 引擎在线时显示节点数
- 状态标签颜色随引擎状态变化

### 新增：颜色选择器 (`gui/widgets/color_picker.py`)

- 预置 12 种主题色（蓝色系、绿色系、紫色系、暖色系）

## 三、开发规范更新

### 节点开发规范 (`节点开发规范.md`)

- **多端口输出监听陷阱**：新增章节说明下游节点监听输出文件时需指定端口对应文件路径，避免监听顶层 `output_file` 导致数据错乱
- **子进程超时保护**：`listener.py` 中使用 `subprocess.run(timeout=180)`，防止子进程卡死
- **`data_type` 路由与 `filter` 同步**：`node_config.json` 的 `filter` 中 `data_type` 值必须与 `main.py` 的 `process()` 路由判断的 `data_type` 值一致
- **上游输出协议定义**：上游节点明确输出格式（`data_type`/`source` 字段），下游节点按此协议配置 `filter` 和 `process()` 路由
- **避免过度颗粒化**：判断节点独立性的标准（技术栈、资源需求、崩溃域、业务逻辑、可测试性），避免为"可能未来用"而拆分

### node_config.json 规范 (`node_config_json_开发规范.md`)

- 补充 `parameters[].type` 取值规范：`"int"` / `"float"` 代替 `"number"`
- 补充 `output_ports[].output_file` 字段说明：端口级别覆盖全局 `output_file`
- 补充 `resource_limit` 必填字段
