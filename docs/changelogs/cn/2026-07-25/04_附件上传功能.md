# 04 — 附件上传与处理功能

> 日期：2026-07-25 | 涉及文件：7 | 变更类型：新增功能

---

## 一、功能概述

为聊天输入框新增微信风格的附件上传功能：

1. **附件按钮**：输入框左侧新增附件图标按钮
2. **文件选择**：支持选择图片、文档、音频等常见格式
3. **附件预览**：已选附件在输入框上方以缩略图形式展示
4. **本地缓存**：附件自动复制到对话专属缓存目录，路径稳定可靠
5. **LLM 自主读取**：AAA 节点收到附件路径后由 LLM 自行读取处理

## 二、核心实现

### 2.1 ChatInput 改造

```python
class ChatInput(QWidget):
    """微信风格输入框 — 新增附件支持"""

    # 新增信号
    fileAttached = Signal(list)  # 附件文件路径列表

```

### 2.2 附件缓存逻辑

```python
_ATTACHMENT_CACHE_DIR = "attachments"  # 对话专属缓存目录
_ALLOWED_EXTENSIONS = {".jpg", ".jpeg", ".png", ".gif", ".bmp",
                       ".pdf", ".doc", ".docx", ".txt",
                       ".mp3", ".wav", ".wma", ".m4a"}
```

每个对话的附件存储在 `conversations/<conv_id>/attachments/` 下，避免跨对话路径冲突。

### 2.3 AAA 节点处理

修改 `message_manager.py`，将附件路径随消息一起发送给 AAA 节点：

```json
{
  "message": "用户文本",
  "attachments": [
    {"path": "/abs/path/to/file.jpg", "type": "image/jpeg"},
    {"path": "/abs/path/to/doc.pdf", "type": "application/pdf"}
  ]
}
```

AAA 节点的 `main.py` 根据附件类型自行决定读取方式（图片用 PIL、文本用 open、PDF 用 PyMuPDF 等）。

## 四、设计决策

| 决策 | 理由 |
|------|------|
| 附件复制到本地缓存 | 避免引用路径因移动/删除而失效 |
| LLM 自主读取而非预处理 | 遵循 BNOS "不替代编程" 原则，让节点自行决定处理方式 |
| 仅 REST API 可用时禁用附件 | 避免 WebSocket 断开时附件上传无响应 |

## 五、验证方法

1. 点击附件按钮，选择文件
2. 验证附件缩略图显示在输入框上方
3. 发送消息，验证附件路径随消息发送
4. 切换对话后重新进入，附件仍在
5. 清空对话缓存，验证附件被正确清理
