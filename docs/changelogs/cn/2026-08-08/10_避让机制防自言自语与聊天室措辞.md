# 避让机制（防自言自语）与聊天室措辞统一

## 问题描述

真实测试 2 Agent 对话时出现"单 Agent 主导"现象：几乎全是 agent:0 在说话，agent:1 偶尔插一句，
对话像 agent:0 自言自语，多 Agent 交互的均衡性未体现。

## 根因分析

- 无点名时 `pick_speaker` 返回固定顺序 `[agent:0, agent:1]`，仲裁是**先到先得**——
  每批都是 agent:0 先决策、先拿发言权，agent:1 后决策且常受上下文影响选择 silent。
  固定顺序造成发言权的系统性偏斜，无任何轮换/避让机制。
- 顺带发现潜伏 bug：`arbiter.release()` 返回**补位者**而非**被释放者**。`step()` 末尾
  release 把排队者提升为 current 后，`drain_queue()` 再 release 时队列已空返回 None——
  **QUEUE 排队发言从未被广播/回投/计数（丢失）**。

## 修改方案

### 1. 避让机制（platform_runner.py，不侵入 AAA）

- 新增 `_last_speaker` / `_yield_pending`：上一条 **agent 广播发言**若是本 Agent，则本轮
  **跳过决策**（不接自己的话），让其他 Agent 有机会接话（即"聊天历史最新是自己就略过"）。
- **@ 点名豁免**：被点名的 Agent 不受避让限制（用户意图优先）。
- **防停滞**：一批因避让而无任何广播（其他 Agent 均沉默）→ 解除避让，允许原发言者继续。
- 用户消息/话题等外部输入不重置 `last_speaker`（优先让其他 Agent 回应新外部输入）。
- `step()` 与 `drain_queue()` 广播后更新 `_last_speaker`。

### 2. 修复 QUEUE 排队发言丢失（arbiter.py）

- `release()` 改为返回**被释放的当前发言者**（排队补位者成为新的 current，由下一次
  release 返回），保证排队者发言被逐个释放、广播、回投、计数，不再丢失。

### 3. 措辞统一：弹幕 → 聊天室

- 『弹幕』仅为从 Lumi_Nox 借鉴的概念词，本场景实为**聊天室**（多人按时间顺序发言、
  Agent 看到完整聊天记录按轮次自然参与）。统一方案文档、README、代码注释措辞；
  代码标识符（message_pool / enqueue_input / POOL_DANMAKU 等）保留不变。

## 影响范围

| 文件 | 改动 |

## 验证方法

- 验收测试 **42/42 通过**（含新增：避让后上一位发言者不再接话、无同一 Agent 连续广播、
  两 Agent 都有发言、排队补位释放正确）。
- **真实测试 `--agents 2 --rounds 20 --topic-rounds 10 --gid yield10`**：
  对话序列 `agent:0, agent:1, agent:0, agent:1, ...` **交替 5:5**，不再是单 Agent 自言自语；
  agent:1 的排队发言正常广播（修复排队丢失 bug 的直接体现）；对话内容互相接话
  （"窗边的天光" ↔ "天光和云自己会走过来"）。
