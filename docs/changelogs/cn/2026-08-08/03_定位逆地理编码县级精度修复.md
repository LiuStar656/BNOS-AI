# 定位逆地理编码县级精度修复

## 问题描述

定位历史与运行日志中位置显示为"遵义市, 贵州省"（地级市），而非更精确的县级"习水县"。
`_read_latest_from_db` 在 Qt 定位记录无城市名时触发逆地理编码并写库，日志持续出现
`[Location] Qt 定位逆地理编码: 遵义市, 贵州省`。

## 根因分析

`_reverse_geocode` 仅使用 Photon（OSM）单源：Photon 的 `city` 字段是**地级市**
（如"遵义市"），而 BigDataCloud 免费接口的 `locality` 才是**县级**（如"习水县"）。
旧逻辑在 Photon 成功时直接返回，BigDataCloud 只在 Photon 失败时兜底，
导致"更精确的县级名"从未被采用。实测对比：

- Photon：`street="赤水西路"`、`district="杉王街道"`、`city="遵义市"`（地级市）
- BigDataCloud：`locality="习水县"`（县级，更精确，但无街道信息）

## 修改方案

**双源合并**：city 优先取 BigDataCloud 的 `locality`（县级），street/district 取
Photon 的（街道级），region/country 取任一源。改造 `location.py` `_reverse_geocode`：

```python
# 旧 v1.5：Photon 优先，成功即返回
result = _reverse_geocode_photon(lat, lng)
if result is None:
    result = _reverse_geocode_bigdata(lat, lng)

# 新 v1.5.1：双源合并，各取所长
photon = _reverse_geocode_photon(lat, lng)
bigdata = _reverse_geocode_bigdata(lat, lng)
if not (photon or bigdata):
    return None
p_city, p_region, p_country, p_street, p_district = photon or (None,) * 5
b_city, b_region, b_country, _, _ = bigdata or (None,) * 5
result = (
    b_city or p_city,          # 县级 locality 优先（习水县），回退地级市（遵义市）
    b_region or p_region,      # 贵州省
    b_country or p_country,    # 中国
    p_street,                  # 赤水西路（仅 Photon 提供）
    p_district,                # 杉王街道（仅 Photon 提供）
)
```

## 影响范围

| 文件 | 改动 |
|------|------|
| `nodes/node_python_aaa_cognition/location.py` | `_reverse_geocode` 由单源改为双源合并（v1.5.1） |

存量数据：`location_history` 中 qt_ 记录已写入"遵义市"，修复后执行
`UPDATE ... SET city=NULL, region=NULL, country=NULL, street=NULL, district=NULL
WHERE source LIKE 'qt_%'` 清空，下次 GUI/AAA 读取时自动按新逻辑重新补全。
（`_read_latest_from_db` 仅对 `not city` 的 qt_ 记录触发逆地理编码。）

## 验证方法

- 实测当前坐标：`(28.3304, 106.1866) → ('习水县', '贵州省', '中华人民共和国',
  '赤水西路', '杉王街道')`；`(28.3302, 106.1864)` 同结果。
- 验证后重启 GUI，日志应显示 `Qt 定位逆地理编码: 习水县, 贵州省`；
  数据浏览-定位历史显示"赤水西路，杉王街道，习水县，贵州省"（街道级）。
