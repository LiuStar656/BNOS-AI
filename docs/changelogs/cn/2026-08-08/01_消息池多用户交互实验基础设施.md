# 消息池与弹幕式消息处理基础设施

## 问题描述

按 `[PLAN] 消息池与弹幕式消息处理方案（多用户交互实验）.md` 开发基础设施（先不做实验）：
多 Agent 仿真平台需要消息池订阅、user_id 多用户维度、多用户认知存储与检索、
静默处理通道、批量输入合并上下文、发言仲裁与路由、后台监听认知更新、实验数据采集
共八项能力（F1–F8）。

## 根因分析

- AAA 现有 `_on_text` 仅支持单条文本逐次触发 LLM，100 条弹幕 = 100 次调用（缺 F1/F5）。
- 全部记忆表只有 `identity_key`（AI 自我身份），无"谁在说话"的用户维度（缺 F2/F3）。
- 输出侧有条件发言但平台侧无显式静默信号（缺 F4）。
- 平台无仲裁器，多 Agent 可能同时回复同一消息（缺 F6）。
- 认知更新依赖对话轮计数，静默观察不进入演化管线（缺 F7）。
- 无结构化实验数据输出（缺 F8）。

## 修改方案

### AAA 侧（节点 node_python_aaa_cognition）

1. **F2 `db.py`**：新增 `_TABLES_NEED_USER_ID`（user_messages / event_summary /
   other_cognition / user_facts），`ensure()` 末尾 v6.0 幂等迁移 `user_id TEXT NOT NULL DEFAULT ''`
   （空串 = AI 自己 / 匿名 / 全局认知兜底）。`_dedup_and_merge` / `_write` /
   `write_parsed_async` / `_write_parsed` 全线增加 `user_id` 参数与写入列，
   去重按 user_id 隔离（避免多用户相似消息误合并）。
2. **F3 检索**：新增 `g_where_identity_user(conn, table, column, conv_id, identity_key, user_id)`：
   优先返回指定 user_id 的专属认知，无则回退 `user_id=''` 全局认知。
   `_gather_context` 的 `other_cognition` / `user_facts` 检索按 user_id 过滤。
3. **F5 `prompt.py`**：`_CONTEXT_HEADER` 中「他人认知（对用户）」改为
   `{other_cognition_label}` 占位（按 user_id 渲染「对 用户A」）；「用户文本」改为
   `{user_text_section}` 占位（批量时注入「本轮消息池消息（按时间正序）：[用户A] msg1 ...」）。
4. **F1/F4/F7 `main.py`**：新增 `_on_pool_batch` 批量入口（批量写库归属 user_id →
   F5 合并上下文 → 缓存 pending → `_observe_counter` 静默观察计数，每 5 批触发后台反思）；
   `_on_parsed` 增加 `batch_mode=True`，返回显式 `{action: reply|silent, content, user_id, ...}`；
   修复反思轮 pending 上下文丢失（原实现丢 identity_key/user_id，多 Agent 场景会退回默认身份）。

### 平台侧（新增 tests/message_pool/ 包）

5. **F1 消息池** `message_pool.py`：`enqueue_input`（入队不打断 + 同人同文窗口去重）/
   `pop_all_inputs`（批量取出，优先级降序 → 时间正序 → 单用户配额截断）。
6. **F6 路由与仲裁** `router.py`（@ 点名检测 `pick_speaker`）`arbiter.py`
   （`SpeechOutputArbiter`：QUEUE / DROP / INTERRUPT 三策略，单一发言权，事件发布到 EventBus）。
7. **F8 采集** `collector.py`：events.jsonl / decisions.jsonl / evolution.json，runs/ 目录留档。
8. **桥接与编排** `agent_bridge.py`（调 AAA 批量入口，多轮回执直到拿到显式决策）+
   `platform_runner.py`（step 编排：批量 → 路由 → 各 Agent 决策 → 仲裁广播，步末释放发言权）。

## 影响范围

| 文件 | 改动 |
|------|------|
| `nodes/node_python_aaa_cognition/db.py` | v6.0 user_id 迁移；写入/去重/检索全线 user_id 维度；新增 `g_where_identity_user` |
| `nodes/node_python_aaa_cognition/main.py` | 新增 `_on_pool_batch`；`_on_parsed` batch_mode 显式决策；`_gather_context` user_id/batch_items/pool_batch_section；`_observe_counter` |
| `nodes/node_python_aaa_cognition/prompt.py` | 他人认知标签占位 + 批量输入段占位 |
| `tests/message_pool/`（新增） | event_bus / message_pool / router / arbiter / collector / agent_bridge / platform_runner / infra_acceptance_test / README |

GUI 直连路径（`_on_text`）与现有测试（`self_evolution_test.run_round`）不受影响：
新增参数全部带默认值，空 batch 场景行为不变。

## 验证方法

- 基础设施验收测试 `tests/message_pool/infra_acceptance_test.py`（不跑 LLM 实验）：
  单元 21 项（总线 / 消息池去重配额排序 / 路由点名 / 仲裁三策略 / 采集器）
  + 集成 11 项（Fake LLM 覆盖批量链路：批量写库 user_id 归属、reply/silent 显式决策、
  静默轮事件摘要写入、DROP 策略单一发言权、decisions.jsonl 落盘）。
- AAA 侧冒烟验证（临时脚本，验证后删除）：user_id 迁移、`g_where_identity_user` 兜底、
  `pool_batch_section` 渲染、`_on_pool_batch` 全链路，24 项全通过。
- 实验本体（真实 LLM 多用户认知演化）按方案 §六/§七 另行执行，不属于本次范围。
