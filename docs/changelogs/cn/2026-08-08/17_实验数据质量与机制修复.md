# 17 实验数据质量与机制修复：失败/静默分离、user_id 归因、末位偏置、人格演化断链、引用链注入

## 问题描述

5 Agent 40 轮真实实验（20260808_103432，exp_5a40r_v2）因账户欠费（HTTP 402）中断，运行问题分析报告暴露 6 个问题；结合上一轮（101510）分析报告，确认两类根因性问题：

- **P0 数据污染**：189 条 API 失败记录全部落入 `action="silent"`（静默率 84% 是假指标，真实 17.8%）；静默/回复的 `user_id` 一律等于批次最后一条消息的发送者（3 次实验复现），认知归因错乱；
- **P1 机制断链**：回应对象存在末位偏置（几乎总回应批次最后一条 → agent:0/1 成认知黑洞，永不被认知）；人格演化管线断裂（3 次实验人格向量零漂移，但情绪能动，断裂点定位到 `_adjust_vector`）。
- **引用链缺失（用户新诉求）**：聊天记录标注"回答谁"是事后渲染给人类看的，**LLM 决策时看不到"谁在回应谁"**——批次是扁平列表。

## 根因分析

| 问题 | 根因 |
|---|---|
| P0-1 失败落 silent | `agent_bridge.py` subprocess 失败分支直接构造 `action="silent"`；inline 异常与 `platform_runner` 并行分支 `except` 同样构造 silent |
| P0-2 user_id 归因末位 | `_on_pool_batch` 把 `last_user_id`（批次末位）作为 user_id 一路传递，`_on_parsed` 写库/决策均用它；`setdefault` 不覆盖已存在的空串 |
| P1-3 末位偏置 | 合并上下文按时间正序排列，LLM 倾向回应最后一条；批次前端发言的 agent 永不被选为回应对象 |
| P1-4 人格零漂移 | `_on_parsed` 恒以 `reaction="neutral"` 调 `_process_mood_and_evolution`，而 `_adjust_vector` 只统计 positive/negative → pos/neg 为空 → 每维 continue → `vector_changed` 恒 False → 永不写库（情绪走 `db.save_mood_value` 独立写库所以能动） |
| 引用链缺失 | 发言回投消息不带"回应对象"，批次注入无引用结构 |

## 修改方案

### P0-1：失败记录与静默分离

1. `agent_bridge.py`：subprocess `code != 0` → `action="error"`（原 silent）；inline 分支 `try/except` 捕获 LLM 异常 → error；
2. `platform_runner.py`：单 Agent / 并行分支 `except` → `action="error"`；
3. `collector.py`：新增 `error_count` 独立计数（evolution.json 落盘）；
4. `topic_report.py`：`_speech_stats` 统计 error 并排除出 silent 口径。

### P0-2：user_id 归因 = 回应对象

`main.py` `_on_parsed` batch_mode 下重算 user_id：reply 时取 LLM 显式【回应对象】；静默/群聊/无回应对象 → 不归因（""）。检索注入（`_on_pool_batch` 的 last_user_id）保留——上下文检索仍针对最后发言者，仅**归因**改按回应对象。`aaa_serve.py` / `agent_bridge.py` 兜底不再用批次末尾。

### P1-3：回应对象末位偏置

1. `platform_runner.py` `_batch_for(aid, batch)`：把 @ 该 Agent 的消息移到批次末尾——利用末位偏置反向为"@ 优先"服务（AAA 收到 @ 消息时，最后发言者=@ 者，自然优先回应）；
2. `prompt.py`：回应对象节引导"从整个批次挑选（不一定是最后一条）+ @ 点名优先"。

### P1-4：人格演化断链

`personality.py` `_adjust_vector`：neutral 反馈也参与演化——pos/neg 为空但存在 neutral 观测时，向观测风格收敛（步长仍限幅 ±0.02；自我一致时 delta≈0 不漂移）。

### 引用链注入（v6.4）：LLM 决策可见"谁回应谁"

1. `message_pool.py`：Message 增加 `reply_to` 字段，`enqueue_input` 透传，`to_dict` 输出；
2. `arbiter.py`：`request_speech` / `_grant` / 队列项透传 `reply_to`（排队补位不丢失引用链）；
3. `platform_runner.py`：广播发言回投时 `reply_to=决策的【回应对象】`（step 主路径 + drain_queue 补位）；
4. `agent_bridge.py`：派发 msgs 携带 `reply_to`；
5. `main.py`：`_fmt_pool_msg` 把批次消息格式化为 `[作者] 内容（回应 X）` 注入 pool_batch_section（群聊 → "（回应群聊）"）。

## 影响范围

- AAA 节点：`main.py`（归因 + 批次标注）、`prompt.py`（引导）、`personality.py`（neutral 演化）；
- 实验基础设施：`agent_bridge.py`、`platform_runner.py`、`aaa_serve.py`、`collector.py`、`topic_report.py`、`message_pool.py`、`arbiter.py`；
- GUI 单用户路径不受影响（batch_mode=False 不经过批量归因逻辑；GUI 演化行为不变——neutral 观测也演化同样适用于单用户路径，属通用修复）。

## 验证方法

`infra_acceptance_test.py` 新增 U9（P0/P1，12 项）+ U10（引用链，6 项）→ **96/96** 全过（原 78 + 18 新增）：

- P0-1：inline/subprocess 失败 → `action="error"` 且 user_id 不归因；collector error 独立计数；
- P0-2：reply user_id = LLM 回应对象（非批次末位）；静默 user_id 空；
- P1-3：@ 消息移末位；无 @ 保持原序；prompt 引导含"不一定最后一条 + @ 优先"；
- P1-4：neutral 反馈触发演化（warmth 0.6→0.9 收敛）；自我一致不漂移；
- 引用链：Message/仲裁器/回投/批次标注四层透传与渲染正确。

## 结论

P0 两个数据污染问题修复后，静默率与认知归因恢复真实语义（失败独立标记、归因按回应对象）；P1 打通人格演化管线（neutral 反馈可演化）并缓解末位偏置（@ 优先 + prompt 引导）；引用链注入让 LLM 决策时与人类看到的聊天记录一致（谁在回应谁）。**待充值后重跑 5 Agent 40 轮实验验证**：llm_stats 构成应为「决策 ≈ 40×4（避让跳过一个） + 后台 review + 平台直连」，且 error 记录可单独核算。
