# 14 意识流同步：静默决策也更新想法（回不回复只看【自然回复】有无文本）

## 问题描述

消息池实验（F9 子进程架构）中，Agent 选择不回复（`action=silent`）时，决策记录里**「想法」和「心情」字段为空**。真实 DeepSeek 实验（`runs/20260808_092728_n3_25r`）中大量 silent 记录的 `"想法": ""`、`"心情": ""`。用户要求：

1. **n 个 agent 同时接收、同时决策、同时回复（也可不回复）**——并发能力 F9 已实现；
2. **想法是意识流，无论回不回复都应同步更新**——静默决策也必须带出想法/心情；
3. **回不回复的判断标准 = 【自然回复】字段下有无文本**——没有自然回复 = 不回复。

## 根因分析

- 回复与否的判断逻辑本身正确（`_on_parsed` batch_mode 已按 `reply_text = parsed["自然回复"]` 判空），**问题在想法来源**：真实 LLM 静默时没有输出【想法】节（prompt 未强制），`parse_llm_output` 对空节直接跳过（parser.py `_store_section` 空内容 return），导致 `parsed.get("想法")` 为空串。
- fake LLM 固定输出【想法】段，故冒烟/验收测试未暴露；真实 LLM 格式不稳定才暴露。
- 并行决策（F9）让测试的共享 fake_llm 计数器产生竞态：第一批发言者取决于两个并行线程谁先抢到计数器，@ 点名豁免使决策条数在 3~4 间浮动（偶发 1 项断言失败）。

## 修改方案

### 1. `nodes/node_python_aaa_cognition/prompt.py`（根因修复）

【自然回复】明确静默规则 + 【想法】强制输出：

```
【自然回复】
你给用户看的回复文本（禁止使用emoji和颜文字）。如果你决定不回应这条消息，此节**留空**（不输出任何内容）
【想法】
1-2句话描述你此刻的内心想法（意识流）。**即使【自然回复】留空（选择静默），你也必须输出此节**——这是你不说话时也在进行的内心活动
```

### 2. `nodes/node_python_aaa_cognition/main.py`（数据完整性兜底）

batch_mode 返回时给【想法】/【心情】默认值，保证 LLM 违反格式时静默决策也带状态：

```python
"想法": parsed.get("想法", "").strip() or "收到消息，保持观察，暂不回应",
"心情": parsed.get("心情", "").strip() or "平静",
```

回复与否仍只看【自然回复】有无文本，与想法字段无关（判断逻辑未变）。

### 3. `tests/message_pool/infra_acceptance_test.py`（测试稳定性）

- I1/I2：共享 `fake_llm` 计数器改为**每 Agent 独立确定性 LLM**（alpha 恒 reply、beta 首轮 silent 次轮 reply），消除 F9 并行线程下的计数器竞态，第一批发言者确定为 alpha；
- U7：ping 往返阈值 1s → 2s（预热后首次 ping 仍可能带子进程初始化尾巴，常驻往返本质亚毫秒级）。

## 影响范围

- AAA 节点代码：`prompt.py`（提示词）与 `main.py`（batch_mode 兜底）——仅影响消息池批量决策路径；GUI 单用户对话（`batch_mode=False`）不经过兜底分支，prompt 强化对 GUI 无副作用（GUI 场景无静默）。
- 实验/测试：`infra_acceptance_test.py`（确定性 + 阈值）。
- 平台侧（agent_bridge / platform_runner / aaa_serve）零改动。

## 验证方法

1. 临时验证脚本（验证后已删除）：`_on_parsed(batch_mode=True)` 三场景——
   - 有【自然回复】+【想法】→ `action=reply`，想法保留；
   - 静默但输出【想法】→ `action=silent`，想法保留；
   - 静默且无【想法】→ `action=silent`，想法兜底"收到消息，保持观察，暂不回应"、心情兜底"平静"。
2. `infra_acceptance_test.py` 连续两次 **64/64** 全过（修复竞态与阈值后稳定）。
