# 定位历史同坐标去重

## 问题描述

数据浏览-定位历史标签页中，同一位置出现多条记录：一条显示坐标
（"坐标 106.1866°E, 28.3304°N"），一条显示实际位置
（"赤水西路，杉王街道，习水县，贵州省"），用户困惑"坐标和实际位置为什么分成两条"。

## 根因分析

- 坐标与城市名**本就在同一行**（location_history 表的 latitude/longitude 与
  city/street/district 是不同列），不存在分层存储；看到"两条"是同一次位置的
  **多次快照**。
- Qt 定位每 5 分钟回调一次，GUI `_write_to_db` 每次回调都 INSERT 新记录
  （旧 active 记录标记 `superseded` 保留）；人在原地时坐标基本不变 →
  同坐标记录反复堆积。
- 逆地理编码只在读取**最新 active** 记录时补城市名（`_read_latest_from_db`），
  更早的同坐标 superseded 记录没有城市名 → 界面同时出现"有城市名"和
  "只有坐标"两种形态的同位置记录。

## 修改方案

在 GUI 写入端（`gui/core/location_provider.py` `_write_to_db`，v1.5.3）加去重：
**同坐标（约 330m 容差，覆盖基站抖动）+ 近 30 分钟内有 active 记录 → 只更新
该记录的时间戳/精度/来源，不插入新记录**；位移超过容差才插入新记录，保留移动轨迹。

```python
# 写入前：同坐标 + 近30分钟已有 active 记录 → 去重只更新时间戳
row = conn.execute(
    "SELECT id FROM location_history "
    "WHERE status='active' AND identity_key=? "
    "AND ABS(latitude - ?) < 0.003 AND ABS(longitude - ?) < 0.003 "
    "AND created_at >= datetime('now','localtime','-30 minutes') "
    "ORDER BY id DESC LIMIT 1",
    (self._identity_key, lat, lng),
).fetchone()
if row:
    conn.execute(
        "UPDATE location_history SET created_at=?, accuracy=?, source=? WHERE id=?",
        (now_str, float(location_data.get("accuracy", 5000)),
         location_data.get("source", "qt_cell"), row[0]),
    )
    conn.commit()
    return
# 否则：标记旧 active 为 superseded + 插入新记录（原逻辑不变）
```

## 影响范围

| 文件 | 改动 |
|------|------|
| `gui/core/location_provider.py` | `_write_to_db` 新增同坐标 + 近 30 分钟去重（v1.5.3） |

存量数据：测试期间已清空 location_history（含历史 superseded 记录），
重启 GUI 后按新逻辑重新积累，定位历史只保留"去过的位置"。

## 验证方法

用 `QtLocationProvider.__new__` 绕过定位源初始化，直接调用 `_write_to_db`：

| 场景 | 表内记录数 |
|------|-----------|
| 同坐标连续写 3 次（模拟 Qt 每 5 分钟原地更新） | 1（只更新时间戳） |
| 移动 0.005°（约 500m）后再写 | 2（旧 superseded + 新 active） |

验证后清理测试记录，重启 GUI 观察定位历史不再出现同坐标重复记录。
