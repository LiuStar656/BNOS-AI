# 18 六项数据质量修复：防自认知污染、静默模板分action、幽灵发言口径、截断防御、末位偏置冷板凳轮转、情绪标签引导

## 问题描述

5 Agent 30 轮真实实验（20260808_110344，exp_5a30r）数据核对报告暴露 6 个问题，其中 2 处为上一轮汇报的数字错误（"7 组双向认知"实际 6 组、"决策约 12-15 次"实际 7-11 次），4 处为数据/机制缺陷：

- **A 自认知污染**：`other_cognition` 出现 agent:2→agent:2=1（round_11 话题结束后的残余批次里 agent:2 回应了自己上轮的发言，归因逻辑未排除"回应对象=自己"）；
- **B 静默模板污染 reply**：round_3_agent_0 `action=reply`（内容完整）但"想法"="收到消息，保持观察，暂不回应"——想法 fallback 不分 action，reply 复用了静默文案；
- **C 幽灵发言口径混乱**：话题结束（topic_ended 11:07:29）后 round_11 仍有 4 条 reply 决策（11:07:35-51），平台正确处理"结束"（发言未入池），但 decisions 记 35 条 reply vs events 入池 30 条、evolution rounds=11 vs agent_speech_count=30 vs 配置 60/30，口径三套；
- **D 回复截断**：round_3_agent_0 内容止于"你晾衣服要拨开薄荷"（半句）；round_6_agent_0 想法里混入残缺节标记"【情绪调整"（max_tokens=2048 截断，残缺标记不匹配节正则被吞进上一节）；
- **E 末位偏置第三次复现**：所有 reply 的回应对象几乎全指向批次末位消息作者（round_4/6/8/9/10），agent:0 发言 10 条（全场最多）却无任何 agent 认知它——互认矩阵第 0 列全零，与 5a40r"agent:0 黑洞"一致，跨实验稳定的系统性缺陷；
- **F 情绪标签缺失**：agent:3 短回复无【情绪调整】标签 → mood 恒 0.0（parse 默认 0.0）。

## 根因分析

| 问题 | 根因 |
|---|---|
| A 自认知污染 | `main.py` `_on_parsed` batch_mode 归因 `user_id = _target`，未排除 `_target == identity_key`（自己） |
| B 静默模板污染 reply | `main.py` 想法 fallback `or "收到消息，保持观察，暂不回应"` 不分 action，reply 无想法时也套静默文案 |
| C 幽灵发言口径 | 平台 `_feed_agent_speech` 在 `topic_active=False` 时正确不回投，但 decisions/evolution 不标记"话题已结束"，三个轮数指标口径未区分 |
| D 回复截断 | AAA 子进程 `max_tokens=2048` 在批量场景（批次上下文+想法+情绪+认知节）偶发截断；`parser._SECTION_LINE` 要求完整"【】"独占一行，残缺标记行被并入上一节 |
| E 末位偏置 | P1-3 只处理 @ 场景；无 @ 时批次末位仍是"最后发言者"，LLM 总回应它 → 首位发言者（agent:0）永不被回应 |
| F 情绪标签缺失 | prompt 未强制输出【情绪调整】，LLM 短回复时省略该节 |

## 修改方案

### A 防自认知污染（main.py）
`_on_parsed` batch_mode 归因：`_target == identity_key`（回应自己）→ `user_id = ""`，不写入 other_cognition 自认知。

### B 静默模板分 action（main.py）
想法 fallback 按 `_is_reply = bool(reply_text)` 区分：reply 无想法 → `""`；silent 无想法 → "收到消息，保持观察，暂不回应"。

### C 幽灵发言口径标注（collector.py + platform_runner.py）
1. `collector.py`：新增 `topic_ended` 状态位，`decision()` 在话题结束后附加 `topic_ended=True`；
2. `platform_runner.py` `_end_topic()`：同步置 `collector.topic_ended = True`；
3. `write_evolution()`：extra 落 `agent_speech_count` / `topic_ended` / `rounds_metric="processed_batches"`，明确 rounds 是"处理批次数"口径。

### D 截断防御（aaa_serve.py + run_pool_experiment.py + parser.py）
1. 两处 LLM 调用 `max_tokens` 2048 → 4096；
2. `parser.py`：新增 `_SECTION_FRAGMENT`（`^【[^】]{1,16}$`），残缺节标记行跳过不并入上一节。

### E 末位偏置冷板凳轮转（platform_runner.py）
1. `__init__` 新增 `_responded` 计数（每个 agent 被回应次数）；
2. `_feed_agent_speech`：回投时 `reply_to` 命中 agent → 该 agent 计数 +1；
3. `_batch_for`：无 @ 时，把批次中"被回应次数最少"的 agent 发言移到末位——利用末位偏置反向服务"被忽视者"；@ 场景优先（P1-3 逻辑不变）；platform/用户消息不参与轮转。

### F 情绪标签引导（prompt.py）
【情绪调整】节强化："无论回复还是静默，此节都必须输出一个数字，禁止留空或省略"。

## 影响范围

- AAA 节点：`main.py`（防自认知 + 想法 fallback 分 action）、`parser.py`（残缺节标记剥离）、`prompt.py`（情绪标签强制）；
- 实验基础设施：`platform_runner.py`（冷板凳轮转 + 口径标注）、`collector.py`（topic_ended 标记）、`aaa_serve.py` / `run_pool_experiment.py`（max_tokens）；
- GUI 单用户路径不受影响（batch_mode=False 绕过批量归因与想法 fallback 分 action 逻辑；parser 残缺节防御是通用增强）。
