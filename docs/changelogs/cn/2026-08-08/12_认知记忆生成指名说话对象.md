# 12 认知记忆生成指名说话对象：多用户歧义修复

## 问题描述

用户观察到 `user_facts.json` 中的记忆内容为"用户正在慢慢找回自己的节奏，不着急去远方，享受安静坐着的状态"——LLM 生成的他人认知/用户信息/用户记忆使用笼统的"用户"二字，未点名实际说话对象。在多人（多 Agent / 多用户）场景下，这类无主记忆检索时归属不明，会混入其他对象的认知，产生歧义。

用户要求：**大模型生成记忆时根据实际情况指名说话对象，并生成更详细的内容**。

## 根因分析

1. **Prompt 生成端无指名约束**：`prompt.py` 的 DIRECT_TEMPLATE 中【他人认知】【用户信息】【用户记忆】三段只写"用户"，未提示 LLM 当前对话对象是谁、也未要求点名 → LLM 默认输出泛称"用户"。
2. **Review 后台沉淀端丢失归属**：Background Review（每 5 轮后台反思）的 declarative 用户事实写入 `user_facts` 时 **INSERT 不带 `user_id`**（[review.py](persist_insight) 原实现无该列参数），且 `run_review` / `_trigger_background_review` 调用链均不传递 user_id → 即使对话中有多个说话对象，review 沉淀的用户事实全部归全局，多人场景同样归属不明。
3. **Review prompt 无对象标注**：`build_review_prompt` 只渲染 `[用户]: 内容`，不给 LLM 提供每条消息的说话对象 → LLM 提炼 declarative 时不知道针对谁。

## 修改方案

### 1. `prompt.py` — 生成端指名对象 + 要求详细

- 【他人认知】改为"你对当前对话对象 `{current_user_label}` 的新认识（**必须点名对象、具体描述其言行特点，禁止用笼统的"用户"二字**）"。
- 【用户信息】改为"key=值, key=值（**针对当前对话对象 `{current_user_label}`**）"。
- 【用户记忆】改为"关于当前对话对象 `{current_user_label}` 的信息（喜好、习惯、身份），**具体详细描述**，没有可留空"。
- `_prepare_ctx` 注入 `current_user_label = ctx.get("user_id") or "用户"`（`user_id` 由 `main.py._gather_context` 传入，批量路径取最后发言用户）。

### 2. `review.py` — 沉淀端带 user_id 归属

- `persist_insight(..., user_id="")`：declarative 分支 INSERT `user_facts` 增加 `user_id` 列，去重条件同步加入 `user_id`。
- `run_review(..., user_id="")`：签名透传 user_id。
- `llm_call(..., user_id="")` / `_write_review_prompt_file(..., user_id="")`：节点间通道写的 review prompt 文件带 user_id，LLM 节点回执时归属不丢。
- `build_review_prompt`：user 消息带 user_id 时渲染为 `[用户]（说话对象: agent:X）: 内容`，让 LLM 知道 declarative 针对谁。

### 3. `main.py` — 触发链传递 user_id

- `_get_recent_conversation` SELECT 增加 `user_id` 列。
- `_trigger_background_review` / `_run_background_review` 增加 user_id 参数，透传给 `review.run_review`。
- `_on_pool_batch`（批量路径，取最后发言用户）与 `_on_parsed`（单条路径，取当前 user_id）两处调用点传入。
- `_on_review_response`（节点间通道回执）从 data 取 user_id 透传。

## 影响范围

- `nodes/node_python_aaa_cognition/prompt.py`：DIRECT_TEMPLATE 三段 + `_prepare_ctx`。
- `nodes/node_python_aaa_cognition/review.py`：`build_review_prompt` / `persist_insight` / `run_review`。
- `nodes/node_python_aaa_cognition/main.py`：`_get_recent_conversation` / `_trigger_background_review` / `_run_background_review` / `_on_review_response` / 两处调用点。
- 单用户场景（GUI 直连）行为不变：`current_user_label` 回退"用户"，review 的 user_id 为空归全局。
- 不涉及平台包 `tests/message_pool/`（平台包不含业务逻辑）。

## 验证方法

1. Prompt 构建验证：`user_id=agent:1` 时 DIRECT_TEMPLATE 三段均输出"当前对话对象 agent:1"；无 user_id 回退"用户"。
2. Review 沉淀验证：`persist_insight({'type':'declarative',...}, db, identity, 'agent:1')` → user_facts 落库 `user_id='agent:1'`；`build_review_prompt` 输出含"（说话对象: agent:1）"。
3. 验收回归：`& nodes/node_python_aaa_cognition/venv/Scripts/python.exe tests/message_pool/infra_acceptance_test.py` → 57/57 通过，无回归。
4. 语法检查：main.py / review.py / prompt.py 均无 lint 诊断错误。
