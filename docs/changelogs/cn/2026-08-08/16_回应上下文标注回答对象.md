# 16 回应上下文标注：聊天记录与决策上下文可读"回答谁"

## 问题描述

用户观察多 Agent 聊天记录发现：**很难从聊天记录里看出每个 agent 在回答谁的话**。5 Agent 40 轮对话中大量发言看似接续，但缺少"这条发言回应了谁"的显式信息；同时 `decisions.jsonl` 里决策也缺少回应对象字段，事后分析无法还原对话引用关系。

## 根因分析

消息池为**广播-扁平结构**：平台把一轮批次（多条消息）并发派发到各 AAA 子进程，AAA 合并上下文后 LLM 决策输出回复文本，但：

1. **LLM 决策 prompt 没有"回答谁"的输出要求**——回复文本不声明回应对象；
2. **采集层不记录回应对象**——`decisions.jsonl` 无对应字段，无法事后还原；
3. **渲染层无标注**——`chat_history.md` 只有发言者与文本，看不出对话引用链。

## 修改方案

### 1. `prompt.py`：新增【回应对象】条件输出节

多消息批量场景（消息池）要求 LLM 显式声明回应对象；1 对 1 单条消息不渲染该节（回应对象恒为用户，输出多余且干扰解析）：

```python
# _prepare_ctx 内
if ctx.get("pool_batch_section"):
    ctx["reply_target_section"] = (
        "【回应对象】\n"
        "这条回复主要是回应谁？填写具体对象名（如 agent:3、用户A），"
        "或写\"群聊\"表示回应多条消息；如果你选择静默（自然回复留空），此节留空")
else:
    ctx["reply_target_section"] = ""
```

### 2. `main.py`：batch_mode 返回【回应对象】字段

`_on_parsed` batch_mode 返回值增加 `"回应对象": parsed.get("回应对象", "").strip()`，随决策落盘。

### 3. `agent_bridge.py`：批次上下文记录（batch_context）

决策记录增加 `batch_context`（批次消息作者 + 内容摘录 60 字），供渲染层标注"回应了谁"：

```python
decision["batch_context"] = [
    {"user_id": m.get("user_id", ""),
     "content": (m.get("content", "") or "")[:60]}
    for m in msgs
]
```

### 4. `data_export.py`：渲染层标注 + 旧数据重建回退

- `_reply_context_annotation(decision, batch)`：**标注优先级 LLM 显式【回应对象】 > 批次作者列表**（群聊/多条/所有人 → "（回应群聊）"，单条 → "（回应上下文：X）"，多条 → "（回应上下文：A, B, C（N 条））"）；
- `_reconstruct_round_batches(run_dir, decisions)`：旧数据（无 batch_context）按消息池弹批规则（优先级降序/时间正序、同轮共享 batch_size、弹批边界=最早决策 ts）重建每轮批次；
- 仅当存在无 batch_context 的旧决策时触发重建（新数据直接使用记录值）。

## 影响范围

- AAA 节点：`prompt.py`（条件节）、`main.py`（决策返回字段）；
- 实验基础设施：`agent_bridge.py`（batch_context）、`data_export.py`（标注 + 重建）；
- 1 对 1 GUI 对话不受影响（batch_mode=False 不渲染【回应对象】节）。

## 验证方法

1. `infra_acceptance_test.py`：U8 新增 10 项（prompt 条件节渲染、标注优先级、旧数据重建）+ I1/I2 3 项（batch_context 落盘、作者集合、LLM 回应对象）→ **78/78** 全过。
2. 5 Agent 40 轮真实实验（20260808_101510）：重渲染后 round 1 发言标"（回应上下文：platform）"、round 2 标"（回应上下文：agent:1, agent:2, agent:3, agent:4（4 条））"。
3. 5 Agent 40 轮真实实验（20260808_103432）：LLM 显式【回应对象】落盘（agent:4 / agent:2 / 群聊 等），渲染标注切换为 LLM 显式优先。

## 结论

聊天记录每句发言标注"回应了谁"（LLM 显式优先、批次作者兜底），分析者可一眼还原对话引用关系；prompt 要求 LLM 显式声明回应对象后，回应对象的可观测性大幅提升（也为后续"末位偏置"问题暴露提供了数据基础）。
