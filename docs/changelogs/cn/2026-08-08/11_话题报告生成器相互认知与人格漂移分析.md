# 11 话题报告生成器：相互认知记忆与人格漂移分析

## 问题描述

消息池聊天室实验结束后，只产出 `evolution.json`（他人认知条目数）+ 原始 DB 按表导出，缺少针对两个关键科学问题的直接分析：

1. **相互认知记忆**：多个 Agent 在聊天室中是否形成对彼此（而非仅对模拟用户）的认知记忆？双向认知是否成立？
2. **人格漂移倾向**：每个 Agent 的初始角色种子（性格向量）在话题结束后是否发生漂移？漂移量多大、哪些维度变化？

用户要求按 `[WIP]-实验设计方案.md`（认知演化实验设计方案 v2）的采集方法收集，且**每轮话题结束都要生成报告**。

## 根因分析

- 平台收尾只做 DB 导出与 evolution 汇总，`other_cognition` 表虽然记录了 agent 间认知（user_id=agent:X），但没有按"认知方 × 认知对象"聚合成可读结论。
- `personality_seed` 表只有最终向量（`save_personality` 为 INSERT OR REPLACE 幂等更新），初始种子只在运行脚本内存中，未落盘 → 无法计算漂移基线。
- 缺少统一的报告产物（report.md），与实验设计方案的"每组实验产出 `report.md`"不一致。

## 修改方案

### 1. 新增 `tests/message_pool/topic_report.py`（话题报告生成器）

纯标准库实现（sqlite3/json/glob），不加载 AAA 模型。从留档目录读取数据并生成 `topic_report.md`：

- **相互认知矩阵**：`other_cognition` 表按 `identity_key`（认知方）→ `user_id`（认知对象）分组计数，输出矩阵表（含"其他"对象计数）。
- **双向认知判定**：对每对 Agent (A, B) 判定 A→B 与 B→A 是否均有认知条目 → 相互认知已形成 / 单向认知 / 未形成。
- **认知内容摘录**：Agent 对 Agent 的认知条目全文列出；对其他对象仅计数。
- **人格漂移表**：初始种子（`_run_meta.json` 的 `seeds[identity].vector`，缺失时回退 `decisions.jsonl` 首条 personality 快照）→ 最终向量（`personality_seed` 表）的欧氏距离、各维变化量；漂移 ≥ 0.05 判定"有漂移倾向"。
- **E3 采集指标表**（对齐 [WIP]-实验设计方案.md）：self_cognition / event_summary / self_info / feelings 条数、情绪轨迹（首→末 + 均值）、自我认知关键词 Top3、发言 reply/silent 次数。

### 2. `run_pool_experiment.py`：记录初始种子 + 话题结束自动生成报告

- `_run_meta.json` 增加 `seeds` 字段：每个 Agent 的初始性格向量 + 说话风格（创建 Agent 后统一落盘）。
- 收尾流程新增 `generate_topic_report(run_dir)`，输出 `topic_report.md`（每轮话题结束即生成；当前一轮话题 = 一次运行，收尾时机在 review 线程 join 之后，数据最完整）。

### 3. `__init__.py` / `infra_acceptance_test.py`

- 模块说明补充 topic_report.py。
- 验收新增 **U6**（15 项）：报告文件生成、矩阵、双向判定、漂移表、采集指标表、初始种子读取、personality 表读取、欧氏距离计算、单向认知判定、**n-agent 全覆盖**（3 Agent 矩阵行/列/判定/摘录均验证）。

## n-Agent 支持说明

报告生成器从 `db/agent_*.sqlite` glob 自动发现全部 Agent（`_agent_dbs`），矩阵/判定/摘录/漂移表/采集指标表均遍历所有 identities，不写死 Agent 数量，未来任意 N 个 Agent 的实验均可直接生成报告。验收用 3 个 Agent 的假数据库 + 真实 3-Agent fake 实验双重验证。

## 影响范围

- 新增 `tests/message_pool/topic_report.py`。
- 修改 `tests/message_pool/run_pool_experiment.py`（_run_meta seeds + 收尾生成报告）、`tests/message_pool/__init__.py`（模块说明）、`tests/message_pool/infra_acceptance_test.py`（U6）。
- 不影响 AAA 节点源码；平台包仍不包含业务逻辑（报告生成属实验场景，由实验脚本调用）。

## 验证方法

1. 验收测试：`& nodes/node_python_aaa_cognition/venv/Scripts/python.exe tests/message_pool/infra_acceptance_test.py` → 57/57 通过（含 U6 15 项，3 Agent n-agent 全覆盖）。
2. 真实实验补生成：对 `runs/20260808_090024_yield10` 运行 `topic_report.py` → 报告显示 agent:0→agent:1 四条、agent:1→agent:0 三条 → **相互认知已形成**；两 Agent 漂移 0.0000（短话题未触发演化门槛，需多轮话题累积观察）。
3. 真实 3-Agent fake 实验（`--agents 3 --gid n3_final`）→ 报告矩阵 3×3+其他列、双向判定覆盖 3 对、漂移表 3 行，gid 正确显示。
4. 旧 run 无 `seeds` 字段时自动回退 decisions.jsonl 首条快照，不报错。
5. 修复：`_agent_dbs` 过滤条件改为 basename 判断，避免 run_dir 目录名含 `_final`（如 gid 带 `_final`）时误伤所有 Agent 数据库。
