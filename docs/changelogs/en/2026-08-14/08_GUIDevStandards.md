# 08 GUI Development Standards (Engineering + Styling + Config)

## Background

After letting AI directly control the GUI (22 `ui.*` tools, AI-authored presets/skinning), we lacked a spec file telling AI *how* to change the GUI — the equivalent of DSH's `AGENTS.md + web-styling.md + config-catalog.md` three layers. The GUI previously had no module README, no styling spec, and no config documentation; hard-coded colors were scattered across components.

## Contents

- New `docs/design/[OK]-GUI开发规范.md` (v1.0):
  - **Engineering**: directory layout, core module responsibilities, page registration (ui_registry slots / conflict-is-design), message protocol (messages.py), GUI↔node file-channel protocol (gui_input/gui_reply/mode.json/dsh_task_in.json)
  - **Styling**: theme token system (8 presets + skin packs + fallback table), token-first color rules (no raw hex), component rules (context menus via `QMenu(self)`, `fit_button_width`, no `setFixedWidth`), WeChat-style chat UI spec, skinning closed loop
  - **Config**: gui_config.json structure, node configs owned by nodes, atomic writes to shared files, tool list generated by `to_file`
  - **AI control rules** + **review checklist** (check off before committing GUI changes)
- New `gui/README.md`: module index (points to the spec + core file quick reference + key conventions)

## Verification

- Every item in the spec cross-checked against the live code (theme_engine/config/ui_registry/messages)
- Known existing violations (hard-coded colors in chat_page/settings_panel) registered as "remediation in progress" items
