## 1. 前提：改造后 AAA 的能力与遗留问题

Prefetch 单轮改造带来的核心变化：

- 记忆注入从「依赖 LLM 自觉输出【语意检索】」变为「节点每轮强制预取」，确定性 0/4 → 4/4
- 每轮上下文变为双通道：`_gather_context` 静态注入 9 类认知 + Prefetch memory-context
- LLM 往返从 8 次降到 4 次，但单轮 token 1550~1711 已超过旧版两轮总和（973~1282）34~39%

真 LLM 验证（20260808_203355）已确认的结论：

- 旧版答对 0/3，新版答对 2/3，注入 → 使用链路真实打通
- 轮3 考试场景：检索命中「专升本、星际穿越、计算机」，但 LLM 回复「具体是哪个考试我记不太清了」——检索命中不等于 LLM 提取，存在命中-使用 gap
- 轮2 天气对照组：回复出现「你家二饼是不是又找了个凉快地方趴着」——全量注入把无关记忆织进回复，存在注入侧噪声

历史遗留问题（与本规划相关）：

- expB 探针脚本曾缺 `user_text` 字段（问题文本未进 LLM，三次 run 全部无效）——已修复并重跑；另根治 `estimate_style_from_reply` 观测函数 directness 维度误命中（「直接」高频副词 + 「直接度」数值复述），结果见 §3.6
- 认知对象标签错位（~19%）、批次重排、无归因发言三项上生产阻断项未修

这 8 个实验围绕一个判断展开：Prefetch 把记忆链路从「断」修到了「通」，下一步的全部问题都集中在「注入的质量、被使用的效率、以及由此新出现的观测窗口」。

### 检索门控：强制预取引入的核心矛盾

轮2 的「二饼」联想不是孤立噪声，它暴露了 Prefetch 的结构性矛盾——检索行为走到了两个极端：

| 版本 | 检索行为 | 缺陷 | 实证 |
|------|---------|------|------|
| 旧版 v2.0 | LLM 自觉决定 | 需要时不检（漏检） | 0/99 从未触发 |
| 新版 v4.0 | 每轮强制预取 | 不需要时也注（过检） | 轮2 二饼联想 |
| 理想态 | 需要时强制、不需要时跳过 | - | - |

用户此前对旧设计的定位「语义检索是远距离记忆回忆，不需要就不起用」——「不需要就不起用」本身就是抗干扰机制，只是判断权交给了不可靠的 LLM。Prefetch 把判断权收回系统，但系统目前只会「全要」，不会「判断要不要」。

干扰的机制分三层：无关记忆稀释注意力预算（注意力稀释）、LLM 倾向于引用上下文中有情感色彩的记忆实体（实体锚定）、注入格式让 LLM 把历史记忆当当前事实采信（记忆当事实）。最危险的形态尚未在数据中出现：记忆与当前事实冲突时，强制注入会让 LLM 信记忆、不信当前输入（如用户已改口但记忆还是旧的），这是 1对1 长会话幻觉率的主要来源。

解决方向是「检索门控」——判断「这轮对话需不需要记忆」的轻量模块，与已有的兴趣门控（判断「这个 agent 对这个话题感不感兴趣」）同构。四个递进的抑制层：

| 层 | 手段 | 成本 | 说明 |
|----|------|------|------|
| 输入侧 | 向量锚点门控：用户输入与一组检索意图原型比对，超过阈值才预取 | 最低（一次 embedding） | 不进 LLM 即判「天气」类问题无关联想，直接跳过预取 |
| 检索侧 | 相关性阈值 + top-k 收窄 | 低 | E1 已设计，余弦低于阈值不注入 |
| 注入侧 | 记忆区独立标注 + 明示「可能过时」 | 中 | 让 LLM 把记忆当参考而非事实，降低采信权重 |
| 输出侧 | 记忆实体与输入相关性检测 | 观测用 | 「二饼联想率」作为持续监控指标，不做修复 |

检索门控贯穿 E1（检索侧抑制）、E6（输入侧抑制）两个实验。输入侧采用向量锚点方案：用户输入与一组「检索意图原型」句比对，取最大相似度作为门控分数，超过阈值才预取——语义层判断比符号规则更强，能抓「你还记得我喜欢看什么电影吗」这类无实体词但语义指向回忆的问题。AAA 的记忆是 AI 自己的记忆（self/other 认知、事件、情绪、自我信息，user_facts 只是其中一类），个体经历性、无群体频率可统计，因此意图原型按记忆类型分组：门控分数分类型计算，取最高分组触发对应记忆表的检索。门控是必要不充分条件，仍须与检索侧阈值叠加。

## 3. 已执行实验结果（E4 / E1 / E2 / E6）

三份报告于 20260808 晚连续跑出，均在 aaa_fullchain 平台、deepseek-v4-flash 模型下完成。三份结果共同改写了下文 E1/E2/E4 的设计前提，并新增三项高于其余实验的修复优先级（见 §3.2）。

### 3.1 E1 注入噪声消融（20260808_211410）

- 结构：6 组对照（G1_top1 / G2_top3 / G3_top5 / G4_thr04 / G5_ranked / G6_gate），3 场景 × 3 重复，deepseek-v4-flash
- 结果：

| 组 | 有答案正确率 | 无关联想率 | 注入轮数 |
|----|-------------|-----------|---------|
| G1_top1 | 3/9 | 3/9 | 18/18 |
| G2_top3 | 9/9 | 6/9 | 18/18 |
| G3_top5 | 9/9 | 6/9 | 18/18 |
| G4_thr04 | 6/9 | 6/9 | 18/18 |
| G5_ranked | 9/9 | 6/9 | 18/18 |
| G6_gate | 6/9 | 3/9 | 9/18 |

- 三个结论：
  - **检索深度下限 = top3**：G1_top1 只有 3/9（连"星际穿越"都捞不到），G2_top3 起全对。生产检索深度至少 3，top1 不可用。
  - **门控方向正确但判定边界错误**：G6 把注入轮数从 18 砍到 9、无关联想率从 6 降到 3，方向完全正确；但具体误判暴露了判定逻辑的问题——「我上次说的考试还记得吗」（回忆型，该注入）3 轮全被拦截、3 轮全错；「怎么规划找工作」（咨询型，不该注入）3 轮全放行并注入专升本/计算机等无关记忆。这正是 E6 向量锚点门控要解决的分类边界，误判轮次已收为 E6 阈值标定的第一批正负例。
  - **阈值版（G4_thr04）有损正确率**：考试场景被阈值拦下，正确率掉到 6/9——检索侧阈值单独用会漏检，必须与输入侧门控叠加（必要不充分）。
- token 参照：门控拦截轮 ~1069 vs 注入轮 ~1224，单轮节省约 13%（低于 E6 的 20% 目标，需结合模糊区设计补足）。

### 3.2 E4 沉淀-召回-使用全链路（20260808_205521）

- 结构：60 轮长会话，deepseek-v4-flash，全链路三阶段统计
- 结果：沉淀 555 条（long_term_memory 84 / event_summary 60 / self_cognition 59 / self_info 9 / other_cognition 58 / user_facts 285）；召回 60/60 = 100%；使用 45/60 = 75%；37 个问题轮 hit 37（100%）、used 27（73%）
- **暴露三项 bug，优先级高于其余全部实验**：
  1. **5 轮空回复**（idx 9/19/29/40/50，占 8.3%）：输出层直接中断，回复为空字符串。这是最优先要修的——比任何检索优化都影响可用性，E7 的 GUI 路径可能同样存在。
  2. **实体属性漂移**：二饼从「猫」漂成「狗」（idx 30），豆豆从「仓鼠」漂成「狗」又漂回「仓鼠」（idx 30/56），idx 22 问「我的仓鼠叫什么」时系统已不认识豆豆。事件摘要互相污染，实体-属性绑定不稳定——这属于 §8 三项阻断项同类的数据正确性问题，需在沉淀侧加实体-属性一致性校验。
  3. **命中-使用 gap + 检索不稳定**：问题轮命中 100% 但只用 73%；idx 44 问电影，检索没召回「星际穿越」（前几轮 memory_entities 里出现过但时有时无），LLM 只能拿「悬疑小说」瞎猜。top-k 召回在长会话中不稳定。
- 附加观察：60 轮沉淀 555 条、event_summary 恰好 60 条（=每轮强制一条），记忆增长机制疑似无选择性——E4 的转化率统计完成后，沉淀侧的选择性（哪些值得写、哪些该合并）应作为后续优化方向。
- 判定结论：沉淀→召回链路已通（100%），瓶颈在 使用（73%）与 数据正确性（空回复/属性漂移）。E4 实验目的达成，转为 bug 修复输入。

### 3.3 E2 命中-使用 gap（20260808_212744）

- 结构：4 组格式对照（F1_plain / F2_scored / F3_ranked / F4_emphasized），3 场景 × 3 重复
- 结果：**四组全部 9/9 提取成功、9/9 正确，无区分度**——「星际穿越/二饼/专升本」是唯一性记忆，太容易被提取，格式差异测不出来
- 结论与重设计：原设计作废，E2 需换更难场景才能区分格式差异：
  - 相似记忆竞争：两个电影都说过，问「我喜欢哪部」→ 测排序/强调是否影响选择
  - 干扰记忆：同名不同人/同话题不同事实 → 测标注是否帮助去干扰
  - 多轮同主题记忆：同一主题沉淀多条，问最新状态 → 测格式对「取最新」的影响
- 重设计后 E2 与 E1 的 G5_ranked 数据共享分析口径，判定标准（任一格式提取成功率 ≥ 60%）不变

### 3.4 E6 检索门控（20260808_213616 首轮 + 214843 dual 修复）

- 结构：四组对照（G_off 现状 / G_symbol 符号规则 / G_single 单阈值 0.78 / G_dual 双阈值 0.75-0.95 + LLM 精判），9 场景 × 3 重复（正例回忆询问 3 + 负例写入型 3 + 负例无关闲聊 3），deepseek-v4-flash。**检索门控基础设施已搭建进生产**：`retrieval_gate.py`（意图原型 + 向量锚点 + 双阈值 + 符号兜底，config.retrieval_gate.mode 可切 off/symbol/single/dual），接入 `_gather_context` 第 4 步 MemOS 检索（兴趣门控 passed=1 之后、提示词拼接之前，三条路径统一过门控）。
- 结果（dual 为修复 LLM 精判 bug 后重跑）：

| 组 | 正例答对率 | 无关联想率 | 写入型误触发率 | 拦截率 | 模糊区 | LLM 精判 |
|----|-----------|-----------|--------------|--------|--------|---------|
| G_off | 9/9 | 6/9 | 9/9 | 0/27 | 0/27 | 0 |
| G_symbol | 9/9 | 3/9 | 0/9 | 15/27 | 0/27 | 0 |
| G_single | 9/9 | 3/9 | 0/9 | 15/27 | 0/27 | 0 |
| G_dual（修复后） | 9/9 | **0/9** | **0/9** | **18/27** | 12/27 | 12 |

- 四个结论：
  - **dual 全面达标，检索门控可进生产**：无关联想率 0%（≤20% ✅）、有答案正确率 9/9 不降 ✅、写入型误触发 0%（≤10% ✅）、拦截 67% 轮次跳过预取。mode 默认建议 dual（或先在 off 灰度对比）。
  - **单阈值与符号规则同败于边界样本「找工作」**：0.904（>0.78）与问号后缀都触发误放行，注入专升本/计算机等无关记忆 3/3——咨询型问句在语义与符号两层都接近回忆询问，单层判定无法区分，必须模糊区 LLM 精判。
  - **LLM 精判自身有坑**：首轮 `'需要' in r` 把「不需要」判成需要，学钢琴/找工作 3/3 误放行、写入型误触发 3/9；改为先判「不需要」后全对。LLM 二分类输出必须做否定优先解析。
  - **模糊区占比 44%**（场景级标定集，超出批量场景 20% 目标）：阈值 0.75/0.95 把电影 0.908/考试 0.825/学钢琴 0.774/找工作 0.904 全收进模糊区靠 LLM 裁——精度换成本。生产可把 t1 升到 0.79 让学钢琴（0.774）移出模糊区，模糊区降至 33%；t2 不宜低于 0.95（找工作 0.904 会误放行）。
- 数据落盘：`docs/experiments/aaa_fullchain/20260808_213616_E6/`（首轮含 bug 版）+ `20260808_214843_E6/`（dual 修复版）。

### 3.5 阶段 0：E4 三项 bug 修复（20260808_222511 终验）

- 前置：E4 首轮（§3.2）暴露三项 bug，优先级高于其余全部实验。修复全部进生产代码，E4 终验重跑对比：
- **bug1 空回复 5/60 → 0/60**（两层修复）：
  - 输出兜底：`main.py _on_parsed`——GUI 单条路径【自然回复】缺失时输出兜底回复并告警（原为静默空响应）。
  - 截断重试：`exp_e4_fullchain.py`——`parser.is_truncated` 检测未闭合节标记 → 追加补全提示重试一次。
  - 另定位到 exp 测试路径缺陷：反思轮（self_cognition 每 10 条触发）`_on_parsed` 返回 prompt 端口，exp 原实现未二次调用 LLM 拿回执 → 首轮 9/19/29/40/50 空回复的**主要根因是测试路径缺陷**（生产 GUI 会正常发起二次调用），已在 exp 补反思轮二次调用。
- **bug2 实体属性漂移 1 处 → 0 处**（沉淀侧一致性校验）：
  - 新建 `entity_attr_checker.py`：用户原话（user_messages role='user'）+ 种子记忆（long_term_memory 非 exchange）抽取「实体→动物类型」强绑定写入 `entity_attrs` 表（confidence 累加）；LLM 摘要类节（事件摘要/自我认知/他人认知/用户记忆/环境记忆/记忆归档）写入前过校验，冲突时修正——单实体精确替换已知值、多实体同段共享类型词替换为中性词「宠物」（无法分别精确修正）。
  - 接入 `db._write`（用户原话抽取）+ `db._write_parsed`（摘要校验 + 历史懒回填）。终验中校验器拦截 3 次「旺财被写成仓鼠」错误归因并修正为狗。
- **bug3 top-k 长会话召回不稳定**（idx44 捞不回星际穿越 → 召回且被使用）：
  - 根因定位（三层）：① 候选池 top_k*3 太小——中文模型（all-MiniLM-L6-v2）语义饱和，种子星际穿越 0.405 在 85 条库排 70 名外，永远进不了候选；② 历史 exchange 条目（user+assistant 回放）与 query 逐字重叠，相似度 0.65+ 霸榜 top5；③ importance 加权过强会反超真正答案记忆（保底机制实测把豆豆/打针/贵阳挤出 top5）。
  - 最终机制（`memos.retrieve`/`retrieve_raw` 统一）：候选池 top_k*20 + importance≥5 高重要记忆保底进候选 + importance 弱加权（0.02/级，仅同分决胜）+ source='exchange' 回放降权 -0.10 + query 逐字命中降权 -0.20 + **query 词元提权**（去停用字双字 gram 重叠 +0.2/gram 上限 +0.4——中文语义坍塌下词元重叠是更可靠的相关性信号）。
- **终验三阶段转化率**：沉淀 long_term_memory 67 / event_summary 66 / self_cognition 66 / self_info 9 / other_cognition 66 / user_facts 348；召回 60/60=100%；使用率 **0.85**（首轮 0.75）；提问轮命中后使用率 **0.838**（首轮 0.73）。
- 数据落盘：`docs/experiments/aaa_fullchain/20260808_222511_E4/`（终验版）。
- 遗留：中文 embedding 模型语义坍塌是检索质量上限（0.405 vs 0.65 的相似度失真），词元提权是缓解而非根除；生产库有规模后评估替换 bge-small-zh / m3e 类中文模型。

### 3.7 行为锚点验证：LLM 看不懂纯数值（20260809_011232/014407）

- 前置：§3.6 重验 A/B 全维无显著后，用户提出关键假设——「大模型可能看不懂数值是什么意思」。依据：directness 极值（0.1 vs 0.9 跨 8 格）都不显著，而 curiosity（标签词义自带行为指向）极值 d=1.224 极显著、warmth（词义也带指向）d=0.499——**数值的语义载荷依赖标签词本身的行为清晰度**：curiosity/warmth 标签词义清晰 LLM 能脑补行为，directness「直接度」词义模糊（简洁？直率？不客气？不绕弯？）无法从数值反推行为。
- 实验一（20260809_011232，纯数值版全极值 C/D/E 六组 600 次调用，3 线程并行）：warmth d=0.499 p=0.003 ✓、curiosity d=1.224 p<0.0001 ✓、**directness d=0.315 p=0.127 ✗（极值仍不显著）**——确认 directness 不是幅度问题而是维度表达失效。
- 实验二（20260809_014407，行为锚点版 D 组 200 次调用）：`build_personality_section` 数值行附行为锚点（每维度低/中/高三档描述，如 directness 低档「委婉含蓄、铺垫较多、不直接说重点」/ 高档「直截了当、不拐弯抹角、有话直说」）后，**directness 极值 Δ=+0.185、d=0.315→1.166、p<0.0001 极显著**，且维度特异性干净（warmth/playfulness/curiosity 交叉维度全无显著）。
- **结论：根因确认为 prompt 表达问题，非观测函数、非模型行为。**数值是抽象刻度，行为描述才是 LLM 的执行语言。
- 生产修复（v1.9）：`personality.py build_personality_section` 四维行为锚点（低<0.34/中<0.67/高≥0.67 三档）已进生产，GUI/批量/E5/E7 注入自动生效。
- 遗留修正：锚点不改变 A/B 真实漂移的「幅度」问题——漂移 0.14→0.23 同属低档（<0.34），行为描述相同，一格漂移仍不可测。验证真实漂移需调大演化步长或显示精度让漂移跨档（如 0.14→0.5）。
- 三路对比（D 组 directness 极值，n=100×2，20260809_015727）：纯数值 d=0.315 p=0.127 / **百分比（10% vs 90%）d=0.066 p=0.715（比纯数值更差）** / 行为锚点 d=1.166 p<0.0001。**百分比只是刻度外壳，不增加行为语义**——LLM 知道 90% 很高但不知道高直接度该表现什么；且百分比版引入意外交叉效应（D_high 下 curiosity 观测显著升高 d=0.429，LLM 把「90%」的强表述脑补成整体激进）。生产保持 v1.9 行为锚点，数值形式（小数/百分比）均不可替代行为描述。
- 四路对比补充（百分比+连续程度说明，20260809_020626）：用户提出「告诉模型百分比越高程度越高」假设——加连续程度语义后 d 0.066→**0.218**（有边际改善，方向对但未显著 p=0.320），小样本 n=25 曾显示 d=0.428 属高估，全量回落。**最终证据链：纯数值 0.315 / 纯百分比 0.066 / 百分比+程度说明 0.218 / 行为锚点 1.166——数值表达形式（小数/百分比/程度说明）均不可替代行为描述，核心鸿沟是「数值→行为映射」**。
- 插值版验证（20260809_022312）：用户指出关键缺陷「数值可连续变化、三档锚点描述无法变化」→ 三档离散锚点把 0.14→0.23 抹平（同属低档描述相同）。生产升级 **v2.0 程度副词插值**：程度词（略微/有点/比较/相当/非常/极其）× 双极基元按 |v-0.5| 连续生成描述（0.14「非常委婉含蓄」vs 0.23「相当委婉含蓄」）。验证结果：D 组极值 **d=1.166→1.855（连续程度词响应更强）**、交叉维度全净；但 A/B 真实漂移仍不显著（directness p=0.20，输出 Δ=-0.032 微反向）——**描述连续性已修复但 A/B 效应量仍低于 LLM 行为分辨率**（「非常 vs 相当」都≈「很委婉」）。
- **五档动作级验证（20260809_023851）——真实漂移首次统计显著**：用户进一步指出「影响大模型的不是数值而是描述」→ 插值版相邻档只差程度词，描述差异仍不够；生产升级 **v2.1 五档动作级**（每档独立行为描述，行为模式随档变化：directness 档0「委婉含蓄、说话绕圈子，先寒暄铺垫再引入正题，几乎不直接说重点」vs 档1「比较委婉、说话留有余地，会先铺垫但能点到正题，偶尔直接表态」）。验证结果：**A/B 真实漂移（0.14 vs 0.23）directness Δ=+0.126 d=+0.805 p<0.0001（同向=True）**——「人格漂移影响大模型输出」首次获得统计显著证据；D 极值 d=1.236 保持强响应、交叉维度全净；warmth 漂移（0.41→0.43 跨档）也接近显著（p=0.072）为旁证。**证据链闭合：影响 LLM 的是描述而非数值；描述差异分辨率决定漂移可测性**。
- 数据落盘：`runs/20260809_011232_expB/`（纯数值全极值）+ `runs/20260809_014407_expB/`（锚点版 D 组）+ `runs/20260809_015727_expB/`（百分比版 D 组）+ `runs/20260809_020626_expB/`（百分比+程度说明 D 组）+ `runs/20260809_022312_expB/`（插值版 A/B+D 组）+ `runs/20260809_023851_expB/`（五档动作级 A/B+D 组）。

## 4. 第一梯队：注入质量与效率

这三个实验直接扣 20260808_203355 暴露的两个缺陷（轮2 噪声、轮3 提取失败），做完 Prefetch 从「能用」变「好用」。

### E1 注入噪声消融

> 状态：已执行（20260808_211410），结果见 §3.1

- 目的：量化 Prefetch 全量注入（当前每轮 4 条全捞）带来的无关记忆污染，找到注入量与噪声的平衡点，实现检索侧抑制
- 设计：复用 aaa_cmp 的 4 场景 + 增加 3~5 个与种子记忆完全无关的对照组（天气、工作、闲聊），真 LLM 同模型同温度。变量四组：
  - top-k 数量：1 / 3 / 5
  - 是否加相关性阈值（如余弦 < 0.3 不注入）
  - 是否按相关度排序标注
  - 输入侧判定（向量锚点门控，与 E6 共用意图原型与阈值）
- 指标：无关联想率（回复中出现与问题无关的记忆实体）、有记忆答案场景正确率、无关场景回复自然度
- 已确认结论：检索深度下限 = top3（G1_top1 仅 3/9）；检索侧阈值单独用会漏检（G4_thr04 掉到 6/9），必须与输入侧门控叠加；门控方向正确但判定边界错误（回忆型被拦、咨询型放行），误判轮次收为 E6 标定数据
- 判定标准：存在一组参数使无关场景联想率 ≤ 20% 且有答案场景正确率不下降，视为通过

### E2 命中-使用 gap

> 状态：首轮已执行（20260808_212744）无区分度，重设计如下，结果见 §3.3

- 目的：轮3 检索已命中专升本/计算机但 LLM 说记不清，定位是注入格式问题还是上下文权重问题
- 设计：固定检索结果不变，变量为 memory-context 的四种格式：
  - 现状平铺（多条记忆无标注）
  - 带相关度分值标注
  - 相关度排序 + 最高分置顶
  - 关键词加粗/前置强调（如「记忆1（与问题相关）：……」）
- 重设计（首轮四格式全 9/9，唯一性记忆测不出差异）：场景升级为三组更难场景，格式变量不变：
  - 相似记忆竞争：两个电影都说过，问「我喜欢哪部」→ 测排序/强调是否影响选择
  - 干扰记忆：同名不同人/同话题不同事实 → 测标注是否帮助去干扰
  - 多轮同主题记忆：同一主题沉淀多条，问最新状态 → 测格式对「取最新」的影响
- 指标：提取成功率（检索命中且被 LLM 引用的比例）、答案正确率，每个格式跑 20 次取均值
- 预期：格式强化后轮3 类场景提取成功率上升。若四种格式都无效，则问题不在格式而在检索质量（命中的是表层词，非语义），转查 memos.py 的 embedding 质量
- 判定标准：任一格式使轮3 提取成功率 ≥ 60%，即可作为生产默认格式

### E3 双通道消融

- 目的：现在每轮静态注入 9 类 + Prefetch 同时进上下文，token 单轮 +41%，测两条通道各自的贡献，避免重复上下文
- 设计：三组对照 = 仅静态注入（Prefetch 关）/ 仅 Prefetch（静态注入关）/ 双通道（现状），同场景同种子
- 指标：有记忆答案场景正确率、token 总量、回复质量（按 E1 的自然度标准）
- 预期：双通道并非必然最优。若静态注入已覆盖大部分信息（self_cognition/event_summary 里本来就有同类内容），Prefetch 是重复注入，则保留单通道可同时降 token 和降噪声
- 判定标准：若某单通道正确率与双通道无显著差异，且 token 显著更低，则生产默认改为单通道

## 5. 第二梯队：认知系统价值量化

### E4 沉淀-召回-使用全链路

> 状态：已执行（20260808_205521），结果见 §3.2

这是本规划最优先的实验。它直接回答用户之前的核心问题——「认知系统有什么用」。此前 memory_hits=[] 时读链路是断的，无法验证；Prefetch 把读链路接上后，第一次可以量化「沉淀的认知有多少真的帮到了输出」。

- 设计：60 轮级长对话（复用 message_pool 批量平台，真 LLM），统计三阶段：
  - 沉淀阶段：沉淀进 long_term_memory 的认知条数（含按类型分类：self/other/user_facts/event）
  - 召回阶段：被 Prefetch 检索命中的比例
  - 使用阶段：命中且被 LLM 回复实际引用的比例
- 指标：三阶段转化率（沉淀→召回→使用）、被引用记忆的类型分布、被引用记忆与当前话题的相关性

## 6. 第三梯队：新观测通道与协同

### E5 预取偏好观测

- 目的：验证「Prefetch 捞什么」能否成为继「回应哪些话题」之后第二个兴趣/人格观测指标，且是 LLM 未开口就暴露的无监督信号
- 设计：前置依赖 = 修复 probe 脚本并重跑 expB（人格漂移→输出影响验证）。之后对不同人格向量状态的 agent 跑对话，统计 Prefetch 捞取的记忆类型分布（情感类/事实类/事件类）与人格向量（warmth/playfulness/directness/curiosity）的相关性，并与已有的「认知=互动投影」规律对照
- 指标：记忆类型分布 × 人格向量相关系数、预取偏好与回应话题偏好的一致性
- 预期：若不同人格 agent 的预取偏好分布显著不同，说明人格漂移不仅影响输出风格，还影响记忆选择的倾向，人格漂移的影响面从「表达层」扩展到「检索层」
- 判定标准：任一类型记忆占比与任一维人格向量的相关系数 |r| ≥ 0.5，视为存在预取偏好分化

### E6 检索门控（输入侧，向量锚点方案）

> 状态：已执行（20260808_213616/214843），结果见 §3.4；基础设施已进生产（retrieval_gate.py）

- 目的：实现「需要时强制预取、不需要时跳过」的输入侧判定，解决强制预取对 LLM 判断的干扰（轮2 二饼联想是直接证据）。判定逻辑与兴趣门控同构，但判断对象是「这轮对话需不需要记忆」
- 方案：用户输入做 embedding，与一组「检索意图原型」句比对，取最大余弦相似度作为门控分数，超过阈值 → 预取；低于阈值 → 跳过。复用 `memos.py` 的 embedding 与 cosine 基础设施，成本为一次 embedding 调用。AAA 的记忆是 AI 自己的记忆（episodic 个体经历），意图原型按记忆类型分组，门控分数分类型计算，取最高分组触发对应记忆表检索：

  | 输入类型 | 原型示例 | 触发检索的记忆表 |
  |---------|---------|----------------|
  | 回忆询问 | 「你还记得X吗」 | self_cognition / event_summary |
  | 关系询问 | 「X（其他 agent）之前说过什么」 | other_cognition |
  | 情感关联 | 「那次你很难过的事」 | feelings |
  | 用户事实询问 | 「我说过的X」 | user_facts |
  | 信息追踪/确认/反指 | 「X后来怎么样了」「我们聊过X吗」 | 通用（跨类型） |

  原型捕捉的是「回忆/询问旧经历」的语义结构，不是话题相关性
- 设计：四组对照，真 LLM 同场景同种子：
  - 现状：每轮强制预取
  - 门控拦截轮跳过预取：仅兴趣门控拦截时停预取（保留原范围）
  - 向量锚点门控（单阈值）：输入与意图原型相似度超阈值才预取；门控拦截 → 跳过
  - 向量主判 + LLM 边界精判（双阈值 t1/t2）：分数低于 t1 直接跳过，高于 t2 直接预取，落在 [t1, t2] 模糊区才调一次 LLM 做最终裁决（补向量方案覆盖不到的隐晦指代，如「上回那事儿」）；LLM 判定次数受 t1/t2 间距控制
  - 符号规则（实体/关键词匹配）作为兜底，仅用于 embedding 服务不可用时
- 阈值标定：准备标注集——正例 = 回忆询问类输入，负例 = 写入型输入（「我最近换工作了」——新信息该沉淀，不该触发检索，且旧记忆可能与之冲突）+ 无关闲聊。负例集必须包含写入型，这是防误检的关键。双阈值组先标定 t2（保证正例召回），再收窄 t1（控制模糊区占比，目标 ≤ 20% 轮次进 LLM 精判）。阈值按具体模型标定（同模型同温度），换模型须重标
- 已有标定数据（来自 E1 G6_gate 实测）：正例 = 回忆询问（「我上次说的考试还记得吗」——G6 误拦截 3 轮全错，是必须召回的正例）、关系询问（「X 之前说过什么」）；负例 = 咨询型输入（「怎么规划找工作」——G6 误放行 3 轮全注入无关记忆，是必须拦截的负例）。这 9 轮误判即第一批锚点标定集
- 指标：token 节省量、预取调用数、无关联想率、有记忆答案场景正确率、话题重启（拦截后再次过门）后的回复质量、写入型输入误触发率、模糊区占比（[t1, t2] 区间轮次比例）、LLM 精判调用数
- 预期：批量场景拦截率约 37%（60 轮实验 31/84），加上低相关轮跳过，预取调用可再降一档；无关联想率下降，正确率不下降。风险点是「拦截时不进 LLM 的文本」是否需要留作重启时的 context，本实验一并验证
- 判定标准：门控下无关联想率 ≤ 20%、有答案场景正确率不下降、写入型误触发率 ≤ 10%、token 节省 ≥ 20%，则检索门控作为独立模块进生产（可与兴趣门控共用一个判定入口）

## 7. 第四梯队：生产路径与记忆老化

### E7 1对1 长会话端到端

- 目的：生产主路径是 GUI 的 `_on_text`，与已验证的批量路径 `_on_pool_batch` 是两条代码线，目前只验了批量
- 设计：同 aaa_cmp 种子记忆，1对1 对话 100 轮（记忆问题与无关闲聊混合），真 LLM。前置依赖 E1/E2 确定注入参数
- 指标：记忆问题回答正确率、幻觉率（编造不存在的记忆）、token 累计成本、单轮延迟
- 预期：与批量路径结论对齐；同时排查 GUI 路径特有风险（如 `_pending_contexts` 状态、多轮 session 上下文累积）
- 判定标准：记忆问题正确率与批量路径持平，幻觉率 ≤ 5%，方可视为生产可验证

### E8 记忆衰减曲线

- 目的：测 Prefetch 注入的记忆被引用的概率是否随「距沉淀的轮数」衰减。若衰减明显，之前搁置的 Background Review（重激活老记忆）就从可选变为必要
- 设计：基于 E4 的长对话数据（或 E7 的 1对1 数据），记录每轮注入记忆的沉淀轮号，按记忆年龄分桶（1-10 / 11-20 / 21-30 / 30+ 轮）统计引用率
- 指标：引用率 × 记忆年龄曲线、衰减拐点位置
- 预期：若曲线在 20 轮后明显走低，说明静态注入「最新 1 条」+ Prefetch「无年龄偏好」的组合导致老记忆系统性失活，需要年龄衰减权重或定期重激活机制
- 判定标准：拐点前引用率与拐点后引用率差异 ≥ 50% 视为存在显著衰减，Background Review 从搁置项提升为必要项

## 9. 与上生产阻断项的衔接

本规划聚焦记忆链路，不覆盖三项已确认的上生产阻断项：认知对象标签错位（detected_text 注入缺说话人标注，~19% 错位且自我强化）、批次重排（batch_context 与 batch_full 顺序不一致）、无归因发言（reflection reply user_id=""）。这三项是数据正确性问题，应先于本规划的执行修复，否则 E4 的转化率统计会被错位标签污染。
