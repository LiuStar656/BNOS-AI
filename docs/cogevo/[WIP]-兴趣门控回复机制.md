# [PLAN]-兴趣门控回复机制（消息池 v7.0）

> 状态：实施中 | 日期：2026-08-08
> 前置：v6.6（批次顺序事实源统一、空归因过滤、幽灵发言熔断、截断重试、末位偏置量化、演化阈值 30→10）
> 触发：5a30r_v3 重跑确认末位偏置仍高（80.6%），且根因是"回应对象由 LLM 从批次末尾自由推断"

---

## 一、背景与目标

### 1.1 问题根因

五轮实验连续复现的**末位偏置**（LLM 几乎总是回复批次最后一条消息的发送者）根因不在模型，而在**判定权**：

> 谁值得回应，由 LLM 在长上下文中自由推断 → 模型用"最后一条"作为启发式捷径。

冷板凳轮转（v6.5）只是把末位让给被忽视者，属于"利用偏置"而非"消除偏置"。

### 1.2 目标

1. **回应对象显式化**：是否回应、回应哪条，由平台用向量相似度显式判定（兴趣门控），LLM 只负责"说得好不好"，不再负责"回不回"。
2. **节约 LLM 调用**：对不感兴趣的消息，平台直接判静默，不调 LLM。
3. **可量化采集**：每个 agent 的向量判断（检测文本 + 兴趣值）写入各自数据库，兴趣分布本身成为新实验指标。

---

## 二、机制设计

### 2.1 核心概念

| 概念 | 定义 |
|---|---|
| 兴趣锚点（anchor） | 每个 agent **最近一次广播发言**（自我介绍为初始锚点） |
| 兴趣值 | `cos(消息嵌入, 锚点嵌入)` 余弦相似度（向量均已归一化） |
| 门控判定 | 批内消息对锚点的最大相似度 ≥ 阈值 → 过门 |
| 直接过门 | 消息 `reply_to == 本 agent` 或被 `@` 点名 → 不经阈值直接过门 |

### 2.2 判定流程

> ⚠️ v7.2 起批量路径由 2.6（接话切入判定 + 窗口拼接）取代，本节保留供对照。

```
话题开场：每个 agent 自我介绍 → 锚点 = 自我介绍文本
每批消息（step()）：
  1. 平台取批 batch（≤ max_batch）
  2. 编码一次：批内每条消息编码为归一化向量（平台共享模型，只编码一次）
  3. 对每个候选 agent（pick_speaker 结果）：
     a. 直接过门：批内有消息 reply_to==agent 或被 @ → reason=direct，过门
     b. 兴趣门控：max(sim(msg_i, anchor)) ≥ 阈值 → reason=interest，过门
     c. 否则 → 平台判静默（不调 LLM），记录判定落库
  4. 过门 agent → LLM 决策；上下文 = 完整批次（只看不回不裁）
  5. 仲裁排序：@ 点名 > 兴趣值高 > 冷板凳（被回应少者优先）> 原顺序
  6. 广播发言者 → 锚点更新为其最新发言
```

### 2.3 上下文窗口约定

> ⚠️ v7.2 起批量路径由 2.6（接话切入判定 + 窗口拼接）取代，本节保留供对照。

兴趣门控只决定"**谁决策**"，不裁减"**看什么**"——过门 agent 的 LLM 上下文仍是**完整批次**（含 reply_to/seq 标注），保证决策信息完整、末位偏置统计口径不变（与新机制前后可对比）。

> 注：用户初稿提出"只把窗口段输入 LLM"，经讨论收敛为"完整批次"——因为门控已消除"回最后一条"的动机，再裁窗口会丢失跨消息上下文，且使 batch_context 统计口径与 v6.6 不可比。

### 2.4 近期观察记录注入（v7.1：让"看过但没兴趣"想得起）

**动机**（5a20r_v2 验证）：未过门 agent 对消息的持久留存只有 `interest_judgment`（检测文本 + 兴趣值），但该表**不进 LLM 上下文**——`_gather_context` 只注入当前批 + event_summary 最近 3 条摘要 + MemOS top5 + 认知记忆。"记了"但"想不起"，不感兴趣时看到的潜在高价值消息会永久错过。

**决策**（用户确认方案 a）：过门 agent 决策时，把该 agent `interest_judgment` 中**未过门（passed=0）**的最近 N 条 `detected_text` 注入上下文为"近期观察记录"——零额外 LLM 调用（读表 + 文本拼接），把"看过但没回应"的痕迹回流为可引用的上下文。

**注入格式**（`_CONTEXT_HEADER`"你的他人认知"之后、"本轮输入"之前）：

```
你的他人认知（对 agent:4）：...

【近期观察记录】（你最近看过但未回应的消息，可参考）
- [r5] agent:2：冷笑话挺好笑的
- [r6] agent:4：拼盘这比喻贴切
```

**读取规则**：

| 项 | 规则 |
|---|---|
| 表 | `interest_judgment`（platform 判定落库，AAA 子进程只读） |
| 过滤 | `identity_key = 本 agent` 且 `passed = 0`（过门消息已在本批决策上下文，不重复注入） |
| 排序 | `ORDER BY id DESC`（最新在前） |
| 去重 | 同 `detected_text` 只保留最近一条（连续复读话题不刷屏） |
| 上限 | N 默认 5（`cfg.recent_observations_limit` 可配） |
| 容错 | 表不存在 / 无记录 / 查询异常 → 空段（不影响决策） |

**边界**：只注入 passed=0 的观察；interest_floor 兜底（passed 被改写为 1）的消息视同过门，不重复注入。1 对 1 GUI 路径无门控、无该表记录，此段恒为空。

### 2.5 编码一次、比对多次

- 模型：平台主进程加载一个**多语小模型**（`paraphrase-multilingual-MiniLM-L12-v2`，中文语义可用），5 个 agent 共享一个实例。
- 批内每条消息**只编码一次**（5 个 agent 复用同一批向量）；锚点向量缓存，仅在 agent 发言后更新。
- 复杂度：`O(m)` 编码 + `O(n×m)` 点积（n=agent 数，m=批消息数）。
- 实测量级：5 agent × 10 消息 ≈ 10 次编码（批量 ~300-500ms）+ 50 次点积（微秒级）。真实瓶颈是 LLM 调用（秒级），门控反而**减少** LLM 调用。

### 2.6 接话切入判定 + 窗口拼接（v7.2，取代 2.2/2.3 的整批判定语义）

**动机**（5a20r_v2/v3 分析）：整批判定产生两类失真——① 兴趣值取"对整批的最高值"，回答不了"对**谁**的话感兴趣"；② 过门 agent 回放完整批次，回应对象仍由 LLM 自选（末位偏置的残余通道）。用户修正：**按时间从旧到新逐条发言判定，第一个过门的发言 = 接话切入点**（决定"从谁说完话后开始接话"），上下文拼接为"从该 agent 最近一次发言到切入消息"的窗口。

**旁观者视角（用户设计语义）**：判定者（如 3）是旁观者，不参与 1/2 的对话流。判定对象是**对话流中逐条出现的发言**——1 的第一次发言最早、2 过门回答产生的第二条次早、1 回复 2 形成的第三条……3 从旧到新逐个过门：
- 先对最早的发言判定过没过门；
- 其次判定**次早的第二条发言**：过门 → 从第二条发言插入话题（切入点 = 第二条）；没过门 → 因 1/2 已形成对话流，1 会回复次早发言形成第三条，继续判定第三条……直到第一个过门的发言。

**判定流程（替代 2.2）**：

```
每批消息（step()）：
  1. 平台取批 batch（≤ max_batch）
  2. 编码一次：批内每条消息编码为归一化向量（平台共享模型，只编码一次）
  3. 对每个候选 agent：
     a. 直接过门：批内有消息 reply_to==agent 或被 @ → 切入点 = 该消息，reason=direct
     b. 无 direct → 按时间从旧到新逐条发言判定：
        - 候选序列 = 批内全部消息按时间从旧到新（每条发言都是独立判定对象，不去重）
        - 对每个候选：sim(候选消息, agent 锚点) → 判定记录（detected_text=候选文本, interest_value）
        - 第一个 ≥ 阈值 → 切入点 = 该候选消息，reason=interest，判定终止
        - 全部 < 阈值 → 全部判定落库（passed=0），不接话
     c. 无任何 agent 过门 → 兴趣值最高者兜底，reason=interest_floor
  4. 过门 agent → LLM 决策；上下文 = 窗口（见下）
  5. 仲裁排序：@ 点名 > 兴趣值高 > 冷板凳（被回应少者优先）> 原顺序
  6. 广播发言者 → 锚点更新为其最新发言（判定依据 = 各自 agent 最新一次写入消息池的信息）
```

**窗口拼接（替代 2.3 的完整批次）**：

| 项 | 规则 |
|---|---|
| 区间 | 消息池历史中 `(该 agent 最近一次发言, 切入消息]` 的所有消息，按时间正序 |
| 排除 | 不含该 agent 自己的发言；agent 未发言过 → 下界 = 消息池起点 |
| 截断 | 无（用户确认） |
| LLM 输入 | "本轮输入" = 窗口消息（替代原完整批次） |
| 决策留档 | `batch_context` = 窗口（作者+内容，指标统计依据）；`batch_full` = 完整批（作者+内容，口径复核用） |

> **口径变化（用户确认）**：末位偏置等指标基于 `batch_context`（窗口）计算，与 v6.6 完整批口径**不再可比**，需新基线；`batch_full` 保留完整批供复核。

**与 2.4 观察注入共存**：逐条判定产生更多 passed=0 记录（对每条未过门发言各一条），观察注入仍取最近 N 条去重注入，互不冲突。

**协议变更**：平台 → AAA 的批量负载增加 `window_items`（决策上下文）与 `batch_full`（留档）；AAA 的 prompt"本轮输入"渲染窗口段。

**验收**：U13.8（从旧到新逐条判定、direct 优先、窗口区间计算、batch_context/batch_full 双记录）。

## 三、阈值标定

### 3.1 方法

用历史实验（5a30r_v3，31 条真实 reply）标定：

1. 对每条 reply，取**回应对象消息**（batch_context 中 user_id == 回应对象）与**回应者自己的上一条广播**（锚点）；
2. 计算 `sim(回应对象消息, 锚点)` 分布；
3. 另算随机消息对分布作为"非兴趣基线"；
4. 阈值取「真实接话 p25 与基线 p90 之间的平衡点」，预设下限 0.4。

### 3.2 标定输出（20260808 实测，calibrate_interest_threshold.py）

**真实接话分布**（5a30r_v3，31 条 reply 中 25 对可计算）：

| 统计量 | 真实接话 | 随机基线 |
|---|---|---|
| min | 0.194 | 0.066 |
| p25 | 0.499 | 0.288 |
| median | **0.653** | 0.464 |
| p75 | 0.785 | 0.601 |
| p90 | 0.921 | **0.701** |
| max | 0.988 | 0.943 |

**阈值决策**：真实接话 p25=0.499、基线 p90=0.701 的中点 **0.600**。

| 阈值 | 真实接话保留率 | 基线误放率 |
|---|---|---|
| 0.70（用户原稿） | 32% | ~5% |
| **0.60（采用）** | **56%** | 25.8% |
| 0.50 | 73% | 40% |

> 0.7 会丢弃 68% 真实接话（过度过滤，对话会断）；0.60 在保留多数真实接话与压低基线误放之间取平衡点。

### 3.3 兜底

标定结果若真实接话与基线重叠严重（中文短句嵌入区分度不足）→ 阈值取基线 p90，接受门控更保守，并用"兴趣值最高者必答"兜底（每批至少一个 agent 过门，防止对话停滞）。

> 实测兜底：多语模型下中文短句相似度整体偏低（话题内 0.5~0.9，话题外 0.1~0.4），故 0.60 阈值下存在无任何 agent 过门的批次，interest_floor 兜底已实测生效（r1 话题开场 agent:3 兜底过门发言）。

## 四、与现有机制共存

| 机制 | 优先级 | 说明 |
|---|---|---|
| @ 点名 / reply_to 直接回复 | 1（最高） | `reason=direct` 直接过门，回归"被点名必答" |
| 兴趣门控 | 2 | 无 @ 时，判定"谁对当前对话感兴趣" |
| 冷板凳轮转（v6.5） | 3 | 多个 agent 同时过门时，被回应最少者优先发言 |
| 避让（v6.2） | 4 | 上一位广播者仍跳过（防自言自语），@ 豁免 |
| 话题熔断（v6.6） | — | topic 结束后不产生新决策，门控同样不工作 |

## 五、数据库采集（用户明确要求）

### 5.1 interest_judgment 表（每个 agent 自己的 sqlite）

```sql
CREATE TABLE IF NOT EXISTS interest_judgment(
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    identity_key TEXT NOT NULL DEFAULT 'gui:default',
    round_no INTEGER,
    message_seq INTEGER,        -- 命中消息的消息池全局序号（seq）
    detected_text TEXT,         -- 检测文本：被评估消息的内容（兴趣最高/直接命中那条）
    anchor_text TEXT,           -- 兴趣锚点：自己最近的广播发言
    interest_value REAL,        -- 兴趣值：余弦相似度
    passed INTEGER,             -- 是否过门（1/0）
    reason TEXT,                -- 过门原因：direct / interest / none
    created_at TEXT NOT NULL DEFAULT(datetime('now','localtime')));
```

### 5.2 写入方式

- 平台进程直接 `sqlite3` 写各 agent DB（gate 判定发生在 LLM 决策**之前**，与 AAA 子进程写库时序串行，`PRAGMA busy_timeout=3000` 兜底）；
- 每批每候选 agent 恰好 1 条：记录"兴趣最高那条"（未过门则为失败值）或直接命中条；
- `db.ensure()` 同步加表（新实验库自动建）；平台写入前 `CREATE TABLE IF NOT EXISTS` 幂等兜底；
- `data_export` 自动导出（sqlite_master 全表导出，无需改）。

### 5.3 采集指标（topic_report 扩展）

- 兴趣值分布（min/median/p90）、过门率、reason 分布（direct/interest/none）；
- 门控静默数（LLM 调用节约量）；
- 末位回应率（对比 v6.6 基线 80.6%，验证机制是否生效）。

## 六、实施边界（明确不做）

1. **不改 aaa_serve 协议**：兴趣判定全部在平台进程，AAA 子进程无感知（LLM 上下文不变）。
2. **不裁 LLM 上下文**：只裁"谁决策"，不裁"看什么"。
3. **不动人格演化 / 记忆检索 / 情绪链路**：门控是纯决策前置层。
4. **不新增网络依赖**：模型本地缓存（HF hub），失败回退 `all-MiniLM-L6-v2` 并标注中文精度降级。

## 七、验收方法

### U13 单元验收（infra_acceptance_test.py 追加）

| # | 用例 | 断言 |
|---|---|---|
| U13.1 | 编码一次 | 同文本两次编码一致；批内同消息不重复编码（缓存计数） |
| U13.2 | 门控判定 | sim ≥ 阈值 → passed=1；< → 0；@/reply_to → reason=direct 过门 |
| U13.3 | 锚点更新 | 发言后锚点=新发言；初始锚点=自我介绍 |
| U13.4 | DB 写入 | interest_judgment 表有记录：detected_text + interest_value + passed + reason |
| U13.5 | 平台集成 | 未过门 agent 不调 LLM（fake 计数=0）；过门 agent 正常决策 |
| U13.6 | 仲裁 | @ > 兴趣 > 冷板凳：多候选时冷板凳者先发言 |
| U13.7 | 阈值可配 | InterestGate 接受 threshold 参数；标定结果可回填 |

### 5 agent 20 轮实验验证（真实 LLM）

| 指标 | 目标 |
|---|---|
| 末位回应率 | 较 80.6% 显著下降（门控后"回最后一条"动机消除） |
| 门控静默率 | > 0（有 agent 因不感兴趣被过滤），LLM 调用量下降 |
| interest_judgment 落库 | 5 agent × 每批 ≥ 1 条，全量可查 |
| 相互认知网络 | 仍有双向认知形成（话题不碎片化） |

**实测结论（20260808_123326，exp_5a20r_v2，5 agent × 20 轮，真实 LLM）**：

| 指标 | 结果 |
|---|---|
| 末位回应率 | 58.8%（10/17 可定位）vs v3 的 80.6% —— 下降（注：本批次 agent 互引为主、批更小，口径与 v3 略有差异） |
| 门控静默率 | 55 判定中未过门 25 条（45.5%），省 25 次 LLM 调用（总调用 33，其中子进程 28） |
| 判定 reason 分布 | direct×11、interest×19、none×25；兴趣值 min 0.152 / 中位 0.587 / p90 1.000 |
| 兴趣值落库 | 5 agent × 11 条 = 55 条全量可查（detected_text + interest_value + reason） |
| 参与集中化 | agent:1（中位 0.370）与 agent:3（中位 0.310）兴趣低，20 轮各仅发言 1 次——"不感兴趣不说话"按设计生效 |
| 相互认知网络 | 双向认知形成（agent:0/2/4 互引频繁） |

> 观察：0.60 阈值下参与高度集中于冷笑话话题的 agent:2/agent:4（兴趣值 1.000 持续过门），agent:1/agent:3 全程旁观。门控达成"省调用 + 回应显式化"，但兴趣锚点持续随发言更新，存在话题隧道效应（高兴趣 agent 持续复读）——列为后续观察项，非本次验收范围。
