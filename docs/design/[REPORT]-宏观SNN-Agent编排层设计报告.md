# [REPORT] 宏观 SNN Agent 编排层：用脉冲网络架构重构 agent 工作流

> 日期：2026-08-12 | 版本：v1.0 | 状态：当前有效
> 归属：BNOS-AI 项目（文档位置：docs/design/）

---

## 摘要

本报告记录 BNOS-AI 项目的一次**方向修正**：不再追求"微观结构自主涌现功能"（该路径已被 schemanet 全部实验证伪），转而采用**用 SNN 架构重构整个 agent 工作流**的新方向。核心思想是：agent 的工作单元视为神经元、单元间的协作视为突触、任务执行视为脉冲传播；组件选择由 WTA 竞争路由决定，协作关系由 Hebbian 强化 + R-STDP 奖惩 + 用进废退衰减共同演化。SNN 不做语言生成（交给 LLM 组件），只做**编排**——这是 SNN 的事件驱动、动态路由、可解释、稀疏激活优势的主场。

**铁律**：不依赖混沌涌现。结构由人设计（骨架 DAG），学习只调制连接强度。

---

## 一、背景：微观涌现路径的证伪与转向

### 1.1 微观路径的最终结论（schemanet 综合技术报告）

- **机制层可行**：Hebbian / STDP / R-STDP（奖惩门控）/ 睡眠巩固（用进废退）全部实现——权重从交互中产生，定式可沉淀；
- **语言层未涌现**：三机制全部激活下，语言指标仍低于朴素统计基线（示例：wsum test top-1=0.1125、PPL=600.8，而 KN 基线 PPL=77.2）；
- **能力外置**：预测能力来自代码层读出（S 矩阵直读 / 梯度读出层），不来自动力学本身；
- **混沌路径不可行**：随机初始 + 噪声探索 + 自组织涌现的路径，在缺乏生物物理结构支撑时退化为混沌（超临界放电、自振、无静息态）。

### 1.2 认知转变

从"让 SNN 长出语言能力"转向"让 SNN 编排 agent 行为"。前者是让 SNN 做它最不擅长的事（长程语言结构），后者是让 SNN 做它最擅长的事（事件驱动的动态路由与自组织连接）。语言能力由 LLM 组件承担，SNN 承担**架构**。

---

## 二、为什么 SNN 是 agent 编排的合适范式

| SNN 特性 | agent 工作流需求 | 现况痛点 |
|---|---|---|
| 事件驱动、按需发放 | 组件按需唤醒 | 常驻轮询空转 |
| 动态路由（WTA 竞争） | 工具/组件选择自适应 | 工具选择靠 prompt 硬编码 |
| 连接强度可学习 | 协作关系可演化 | 工作流静态、无法自动修正 |
| 发放轨迹可回放 | 一次任务 = 一条路径 = 可审计 | 黑盒编排不可观测 |
| 稀疏激活、低功耗 | 只激活必要组件 | 全链路常驻浪费算力 |
| 奖惩调节（R-STDP） | 失败路径自动压制 | 失败后只能人工改配置 |

SNN 的已知劣势（语言生成、长程结构）由 LLM 作为最强组件补上——**各取所长**。

## 三、理论来源

每个机制都有明确的理论依据（完整文献见 [方案 §3]([PLAN]-宏观SNN-Agent编排层设计方案.md)，共 11 条），核心映射：

| 机制 | 核心理论来源 |
|---|---|

## 四、核心映射：agent 工作流 → 宏观 SNN

| 微观定式网络 | 宏观 agent 工作流 |
|---|---|
| 神经元 | 工作单元：LLM 调用、工具、记忆读写、检索器、决策器 |
| 发放 | 该单元被激活、执行一次、产出结果 |
| 突触权重 W | 组件 A 输出 → 组件 B 的信任度/转移概率（可学习） |
| Hebbian 强化 | A、B 协作成功多次 → A→B 连接增强 |
| 用进废退 / sleep 巩固 | 长期未用的连接渐进衰减（可复活）；≤eps 修剪 |
| R-STDP 奖惩 | 任务成功/用户反馈 → 强化本次路径（资格迹）；失败 → 压制 |
| WTA | 多个候选组件竞争当前任务，最强（最匹配）的被选中 |
| 不应期 / 疲劳 | 组件处理中不重入；高频组件节流 |
| 学习门 | 运行态冻结连接（纯执行），学习态更新连接（训练） |
| 生命周期 / 兴奋-休眠 | 组件进程按需启动/休眠（BNOS 已有） |

**关键设计原则**：宏观节点是几十个而非八千个，动力学可控、混沌风险小一个量级——这是本路径比微观涌现现实的根本原因。

## 五、机制设计

### 5.1 节点突触协议（新增 BNOS 层）

在现有 `output.json` 文件协议之上，每节点增加连接状态表 `node_state.json`：

```jsonc
{
  "node_id": "llm_infer",
  "synapses": [
    { "to": "tts", "w": 0.72, "last_used": 1786484808,
      "uses": 412, "fails": 13 }
  ],
  "refractory_left": 0,
  "learn_gate": true
}
```

- 读写走文件协议（不引入 SDK、不侵入节点逻辑，符合 BNOS 设计哲学）；
- 初始骨架由人设计的 `pipeline.json`（DAG）生成：有边 w=0.5（中性），无边 w=0。

### 5.2 学习信号（R-STDP 宏观化）

奖惩来源（优先级递减，可叠加）：

1. **任务成败**（硬信号）：调用报错/超时/校验失败 → 失败；流程走通 → 成功；
2. **用户反馈**（软信号）：点赞/采纳 → 成功；纠错/撤销 → 失败；
3. **LLM 自评**（弱信号）：结果被下游判定可用 → 成功。

奖惩沿任务路径按资格迹回溯：

```text
W[a→b] += da_gain * da * eligibility(a→b)
da = +1.0（成功） / -0.5（失败）
eligibility = trace_decay ^ (路径步差)
```

初值参数：`da_gain=0.05`、`trace_decay=0.8`、`w_max=1.0`、`w_min=0.05`（防死连接、可复活）。

### 5.3 用进废退（睡眠巩固宏观化）

```text
每 N 次任务后（sleep）：
  所有 synapse: w *= (1 - decay) 若 last_used 距今 > T_idle
  w ≤ eps 的连接：从状态表删除（骨架保留，可复活）
```

初值参数：`decay=0.1`、`T_idle=7 天`、`eps=0.02`。

### 5.4 WTA 路由

```text
对每个候选 b：score = w[a→b] * (1 - fat[b]) * recency_bonus
选 score 最高者；被选者不应期 refractory 步内不再被选中
```

- 多个候选 = 竞争，动态路由；
- 无候选 = 任务终止（可配置回退到 LLM 兜底）。

## 六、实现层次：bnos_runtime 落地依据

四项机制都必须落在 `bnos_runtime/` 层（依据代码现状）：

1. **连接状态**：拓扑属于编排层（`pipeline_loader.py`）；节点内放连接表会两端不一致，违反节点自治 → 编排层持有；
2. **用进废退**：全局周期调度，单节点无法自判；复用 `node_monitor.py` 周期检查先例；
3. **WTA 路由**：运行时决策，节点是被动 listener 无法选择 → 编排层读表路由；
4. **奖惩注入**：复用 `engine.py` 的 `bnos_cmd.json` 文件命令模式 → `bnos_reward.json`。

新增模块：`synapse_store.py`（连接表）、`synapse_engine.py`（动力学）、`wta_router.py`（竞争路由）、`reward_inject.py`（奖惩接口）。详见 [方案 §5]([PLAN]-宏观SNN-Agent编排层设计方案.md)。

## 七、与主流 agent 架构的横向对比（相关工作定位）

### 7.1 层次定位

补全的能力（可学习连接 + 奖惩 + 用进废退）落在**运行时/编排层**，LLM 在 BNOS 里是功能链中的一环（`llm_infer` 节点）——参与 WTA 竞争的候选组件之一，被激活后才做内容生成。它既不是编排的对立面，也不是路由决策者。

```
应用层（bnosai 等上层应用）           ← 业务语义
   ↑ 奖惩信号（任务成败/用户反馈/自评）
Agent 框架层（思考循环、工具选择）     ← 传统上 ReAct/LangGraph 在此做决策
   ↑
运行时/编排层（进程调度、消息路由）    ← BNOS 在此，补全能力落在这里
   ↑
基础设施层（OS、文件、网络）
```

按职责看，补全能力对应主流框架层的"工具选择/路由决策"，但 BNOS 将其**下沉到运行时层**并用标准协议实现——对所有上层应用通用，上层只需按协议注入奖惩信号。

### 7.2 核心分野：路由决策与内容生成的耦合/解耦

两种架构的真正差异不是"用不用 LLM"，而是**路由决策与内容生成是否耦合**：

| | 主流 agent 框架 | BNOS（补全后） |
|---|---|---|
| LLM 的角色 | 双肩挑：既生成内容，又在 prompt 内隐式决定下一步 | **纯粹的内容神经元**：只生成，不做路由决策 |
| 路由决策者 | LLM 推理（prompt 隐式完成，耗 token、不可回放） | WTA 动力学（运行时，零 token、可回放） |
| 内容生成 | LLM | LLM（被 WTA 激活后） |
| 决策可审计性 | 黑盒 | 脉冲轨迹完全可回放 |

LLM 从"决策者 + 执行者"降级为"纯粹的执行组件"——**决策能力从 LLM 的隐式推理中外置为运行时可学习的显式机制**（"能力外置"在 agent 架构层的延续）。

### 7.3 横向对比

| 维度 | LangGraph / CrewAI / AutoGen | Dify / Coze / Langflow | mem0 / Letta（记忆） | Reflexion / Agent-RL（模型层） | **BNOS 补全能力** |
|---|---|---|---|---|---|
| 所属层次 | 框架层 | 低代码应用层 | 框架层（事实记忆） | 模型层 | **运行时/编排层** |
| 编排方式 | 静态图 + LLM prompt 路由 | 可视化静态 workflow | — | — | **连接强度可学习 + WTA 动态路由** |
| 路由决策者 | LLM 推理（耗 token、黑盒） | 人工连线 | — | LLM 微调后更会选 | **运行时动力学（零 token、可回放）** |
| 经验演化 | 无（改图=改代码） | 无 | 事实记忆增删 | 需要训练，非运行时可演化 | **奖惩驱动，运行时可演化** |
| 遗忘机制 | 无 | 无 | 有（针对事实） | 无 | **用进废退（低频连接衰减、可复活）** |
| 可解释性 | 黑盒（prompt 决策） | 可见（静态） | — | 黑盒 | **脉冲轨迹即工作流，完全可回放** |

主流框架分布：静态编排派（图是开发者画的，自适应外包给 LLM prompt）、模型层学习派（改模型权重，非运行时演化）、记忆派（解决事实记忆，不解决协作路径）。**BNOS 补全能力是唯一把"协作路径的可学习性"放在运行时/编排层的实现**，填补主流架构在"编排层自适应"上的空白。

### 7.4 诚实的边界

1. **无语义理解**：WTA 只按连接强度打分，不理解任务语义——因此初始骨架必须由人设计（`pipeline.json` 承载语义），学习只调强度，而非冷启动自组织；
2. **经验积累慢**：单用户任务频率低，宏观连接的学习信号密度远低于模型层训练——适合"慢适应"场景（长期使用的个人 agent），不适合冷启动；
3. **生态成熟度**：LangGraph 已有检查点、流式、human-in-the-loop；本能力尚在 [PLAN]。

## 八、研究问题

1. **学习信号可靠性**：宏观层"组件协作成功"信号如何定义？任务成败为硬信号，用户反馈与 LLM 自评为软信号——如何融合、冲突时如何仲裁？
2. **收敛与稳定性**：奖惩来回翻转导致连接震荡如何抑制（小 da_gain、EMA、初始中性）？
3. **动态路由的确定性边界**：何时允许路径漂移、何时冻结（`learn_gate=false` 退化为骨架 DAG）？
4. **可解释性交付**：脉冲轨迹回放、连接强度热力图、路径熵——如何做成用户可理解、可干预的观测面板？
5. **长程演化**：连接演化熵、路径多样性如何度量？是否会过早收敛到单一路径（过拟合）？
6. **任务路径追踪**：资格迹需要"本次任务经过哪些连接"，现引擎无路径概念——采用消息带 `task_id`（精确）还是编排层观察推断（零侵入但粗糙）？（详见 [方案 §5.3]([PLAN]-宏观SNN-Agent编排层设计方案.md)）

## 九、实施路线

| Phase | 内容 | 产出 |
|---|---|---|
| 0 | 协议 + 仿真骨架（8-12 节点宏观 SNN 纯矩阵仿真） | `node_state.json` 协议、`synapse_engine.py` 仿真库 |
| 1 | 学习信号接入（成败/反馈/自评 + 资格迹奖惩） | 有奖惩 vs 无奖惩的路由命中率对比 |

| 4 | 长程验证（3 组任务流 × 200 轮，固定 DAG vs 宏观 SNN） | 任务成功率、平均路径长度、演化熵、满意度 |

## 十、风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| 学习信号不可靠 | 高 | 硬信号优先，软信号辅助；冲突时硬信号仲裁 |
| 收敛慢/震荡 | 中 | 小 da_gain、初始中性、动量/EMA |
| 路径漂移导致不确定执行 | 中 | 冻结态回退（退化为骨架 DAG） |
| 复用混沌涌现的错误直觉 | 高 | 铁律：结构人设计、强度 AI 学；不随机初始化拓扑 |
| 违反节点不侵入原则 | 中 | 连接状态表由编排层维护，节点零改动（或最小协议扩展） |

---

## 十一、结论

微观涌现路径的失败给出了一个明确信号：**不要用 SNN 学语言，要用 SNN 做架构**。宏观 SNN Agent 编排层将 BNOS 的静态编排升级为可学习、可解释、可演化的脉冲工作流——组件是神经元、协作是突触、任务成败是奖惩、长期不用是遗忘。这一方向延续了"能力外置"的核心发现（能力来自架构层而非动力学层），并把"让 AI 操作可见、可理解、可动态重构"落到实处：**脉冲轨迹即工作流，连接演化即经验**。
