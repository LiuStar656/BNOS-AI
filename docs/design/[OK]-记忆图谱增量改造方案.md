# 记忆图谱增量改造方案

> 日期：2026-08-07 | 版本：v1.1 | 状态：[OK]

## 一、改造目标

1. **增量构建**：图谱只计算新条目，旧向量和旧边直接复用
2. **显示阈值可配置**：滑块值 = 相似度阈值，值越高越严格
3. **缓存检测**：GUI 加载时检测文件 mtime，数据未变时不重建
4. **分级渲染**：按边权重分层显示，高权重实线、低权重虚线

---

## 二、现状分析

### 2.1 当前数据流

```
rebuild_knowledge_index() 每次调用：
  1. 全量读取 event_summary 表
  2. 全量编码所有条目（包括已有向量的旧数据）
  3. 全量计算相似度矩阵 O(N²)
  4. 全量导出 knowledge_index.npz + knowledge_graph.json

问题：
  - 每次调用都重复编码旧数据（浪费 CPU）
  - 每次都重算完整矩阵（O(N²) 增长）
  - 无缓存检测（即使数据没变也重算）
```

### 2.2 性能瓶颈

| 数据量 | 编码耗时 | 矩阵计算 | 总耗时 |
|:------:|:-------:|:-------:|:------:|
| 200 条 | ~2s | ~0.5s | ~2.5s |
| 1000 条 | ~10s | ~12s | ~22s |
| 5000 条 | ~50s | ~300s | ~350s |

## 三、改造方案

### 3.1 增量构建流程

```
                    ┌─────────────────────────────────────┐
                    │  rebuild_knowledge_index(db_path)    │
                    └──────────────┬──────────────────────┘
                                   │
                    ┌──────────────▼──────────────────────┐
                    │  1. 加载已有索引 (knowledge_index.npz)│
                    │     - embeddings: (M, 384)          │
                    │     - entry_ids: (M,)              │
                    │     - entries元数据                │
                    └──────────────┬──────────────────────┘
                                   │
                    ┌──────────────▼──────────────────────┐
                    │  2. 查询数据库获取新条目            │
                    │     - 对比已有 (id, table) 集合     │
                    │     - 筛选出 all_new 列表           │
                    └──────────────┬──────────────────────┘
                                   │
                          ┌────────┴────────┐
                          │                 │
                   无新条目              有新条目
                          │                 │
                          ▼                 ▼
                   返回(跳过)    ┌──────────────────────────┐
                                 │  3. 编码新条目            │
                                 │     new_vecs = encode(...)│
                                 │     new_ids = [...]      │
                                 └──────────────┬───────────┘
                                                │
                                 ┌──────────────▼───────────┐
                                 │  4. 追加向量              │
                                 │     V_all = vstack(V_old, V_new)│
                                 │     ids.extend(new_ids)  │
                                 └──────────────┬───────────┘
                                                │
                                 ┌──────────────▼───────────┐
                                 │  5. 计算新边              │
                                 │     a) 新↔旧: V_new @ V_old.T │
                                 │     b) 新↔新: V_new @ V_new.T │
                                 │     c) 追加到 edges       │
                                 └──────────────┬───────────┘
                                                │
                                 ┌──────────────▼───────────┐
                                 │  6. 保存索引              │
                                 │     - 覆盖 knowledge_index.npz│
                                 │     - 覆盖 knowledge_graph.json│
                                 └──────────────────────────┘
```

### 3.2 缓存检测流程

```
GUI 加载图谱:
  1. 记录 knowledge_graph.json 的 mtime
  2. 加载图谱数据
  3. 定时检查（60秒）:
     - 重新读取 mtime
     - 若 mtime 未变: 跳过重建
     - 若 mtime 变化: 重新加载 + 重建
```

### 3.3 显示阈值可配置

```
数据层 (memos.py):
  - _export_knowledge_graph(entries, embeddings, data_dir, threshold=0.6, max_edges_per_node=20)
  - max_edges_per_node 作为硬上限，保证图谱密度不会爆炸

GUI 层 (knowledge_panel.py):
  - 新增 "显示阈值" 滑块 (0.00-1.00，默认 0.60)
  - 滑块值 = 相似度阈值：
    * 值越高越严格（只显示高相似度的边）
    * 值越低越宽松（显示更多边）
  - 滑块变化时:
    a) 使用 apply_display_threshold() 快速过滤（无需重新编码）
    b) 边数动态增减，图谱实时响应

示例：
  显示阈值 = 0.90: 只显示相似度 >= 0.90 的边（非常严格）
  显示阈值 = 0.60: 显示所有 >= 0.60 的边（默认）
  显示阈值 = 0.30: 显示几乎所有边（非常宽松）
```

### 3.4 分级渲染

```
knowledge_graph.json 中每条边新增 weight 字段（已有），GUI 按权重分级：

  weight ≥ 0.8:
    - 实线
    - 线宽: weight * 4
    - 透明度: 200-255
  
  weight 0.6-0.8:
    - 实线
    - 线宽: weight * 2
    - 透明度: 100-150
  
  weight < 0.6:
    - 不渲染（或虚线+极低透明度，远距离时显示）

注: 实际渲染阈值由 GUI 滑块控制，分级渲染是额外增强
```

### 3.5 数据结构变更


## 七、注意事项

| 风险 | 应对 |
|------|------|
| 数据库清空后索引不一致 | 检测到 entries 为空时自动全量重建 |
| 旧节点的 top-N 被新节点超越 | 增量时对受影响的旧节点重新评估 top-N |
| max_edges_per_node 变更后旧边不匹配 | GUI 侧按新值过滤，不影响数据层 |
| 模型升级导致向量空间不一致 | 索引中保存模型版本号，检测到变化时全量重建 |

---

*本方案采用"增量构建 + 可配置 + 缓存检测"三重优化，将图谱更新耗时从 O(N²) 降至 O(N×M)，支持用户灵活控制图谱密度。*
